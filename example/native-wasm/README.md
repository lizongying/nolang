# Native package calls for the Nolang JS backend (local WASM module)

Demonstrates `bind = wasm` against a **local file**: a `.wasm` module wrapped
in a small ES module, with no npm install and no CDN involved.

- **Node / Bun / Deno** → `import` the wrapper and forward the `#{c}` externs
  to the wasm exports of the same name.
- **Browser** → same bootstrap, but a relative specifier resolves next to the
  HTML document, so `dist/` needs the module copied there (see below).

## Source

`main.no` imports the local wasm module and declares the C functions it calls:

```no
#{bind = wasm, wasm = './math-wasm.mjs'}
# /math

#{c}
square = (x f64) (r f64)

#{c}
answer = () (r i32)
```

Every `#{c}` extern is forwarded to the wasm export whose name is the C symbol
(leading `_` dropped, `-` → `_`), so `square` calls the export `square`.

`math-wasm.mjs` is the ES wrapper around `math.wasm` (62 bytes, generated by
`gen-math-wasm.mjs` with plain node — no wasm toolchain). The generated code
asks it for exactly two things: a **default export** (an init factory, called
once at startup) and one **named export per extern**. On node the bytes are
read synchronously, so the factory returns the exports object directly and the
bootstrap's ready state flips without any `await`. On a browser target the
bytes are fetched in the background and the factory returns a Promise; native
calls then have to wait for it:

```js
await globalThis.__nolang_wasm_ready["math"];
square(6.5);
```

## Run (Node)

```bash
cd example/native-wasm
no run --js main.no      # prints 42.25, then 42
```

`no run --js` executes the bundle from a temp directory, so it links local
module files (here `./math-wasm.mjs`, and through it `math.wasm`) into that
directory automatically — nothing to install, nothing to copy.

`no build --js -o main.mjs main.no` writes the bundle anywhere you like; the
import then resolves next to the emitted file.

## Run (browser)

```bash
no build --js --browser main.no      # dist/native-wasm.{js,html}
```

The HTML loads the bundle as a module script. A **relative** wasm specifier is
left out of the import map (browsers never remap relative specifiers) and
resolves next to the document, so copy the module next to `dist/native-wasm.js`:

```bash
cp math-wasm.mjs math.wasm dist/
```

For a browser target that should keep working without that step, point `wasm=`
at a **bare** specifier instead — an npm package (declared in
`package.jsonc` `dependencies`) that the import map resolves through a CDN:

```no
#{bind = wasm, wasm = '@sqlite.org/sqlite-wasm'}
# /src/sqlite
```

```bash
no build --js --browser main.no      # dist/*.html import map:
                                     # {"@sqlite.org/sqlite-wasm": "https://esm.sh/@sqlite.org/sqlite-wasm"}
```

## Annotation keys

| key     | values                    | meaning                                             |
| ------- | ------------------------- | --------------------------------------------------- |
| `bind`  | `auto` / `ffi` / `wasm`   | binding strategy; only one per JS build             |
| `wasm`  | string                    | WASM module specifier: bare npm package or relative file |
| `lib`   | string                    | override the FFI library (defaults to `link-libs`)  |
| `init`  | ident                     | WASM init export name (default `default`)           |
| `c`     | (existing FFI key)        | marks the declaration as a C extern                 |

The annotation may sit on the `# import` line (own line above, or trailing) or
in the `#{c}` extern's own group — but **not** split across two groups: the
FFI-lang probe runs before annotation groups are merged, so `#{bind = ffi}`
on its own line above a separate `#{c}` group is ignored. Write
`#{bind = wasm, wasm = '…', c}` when putting it on the extern.

## Known limitations (v1)

- WASM forwarding is **same-name only**; there is no API adapter layer. Mapping
  an API onto a different WASM package (e.g. `better-sqlite3` → `sql.js`)
  requires a Nolang wrapper module.
- The strategy is **per-program**: one JS build uses one `bind` strategy for
  all `#{c}` externs; per-module association is future work.
- The WASM ready Promise is not awaited. Modules that initialize
  synchronously (like this one, on node) are ready immediately; async ones
  publish to `globalThis.__nolang_wasm_ready[<short>]`, and calling before
  readiness raises a clear error.
