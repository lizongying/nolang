# 语法


## 注释

Nolang 支援**单行注释**标记与**多行（块）注释**标记：

- `;` —— 单行标记（注释到行尾）
- `;; <内容>` —— 单行标记（`;;` 后**同一行**还有内容时，注释到行尾，语义等同 `;`）
- `;;\n` —— 多行（块）注释：`;;` 后**紧跟换行**（仅允许空白）时触发多行模式，直到遇到同样后跟换行/EOF 的 `;;` 结束

```no
; 这是注释
; 这也是注释，语义相同
;; 这还是单行注释（;; 后没有换行）
x = 1; 行内注释，注释到行尾
x = 2;; 行内单行注释，语义相同

;;
这是多行（块）注释
可以跨多行
直到遇到单独的 ';;'
;;

y = 3
;;
结束 ;; 后必须换行或文件尾
才会被视为结束定界符
;;
```

> **多行触发规则：** `;;` 后**只能有空白**（空格/制表符）直到换行或 EOF，才会进入多行模式。若 `;;` 后在同一行还有任何非空白字符，则视为单行注释（注释到行尾）。
>
> **多行结束规则：** 结束的 `;;` 同样必须后跟换行或 EOF（中间仅允许空白）。未闭合的多行注释会一直注释到文件尾。

> **规则：每行一条语句，禁止单行多条语句写法。**
> 分号 `;` 是**注释标记**，不是语句分隔符；逗号 `,` 也不能连接多条语句。同一个块 `{ ... }` 内的每条语句都必须各自独占一行。
> 这条规则同样适用于注释中的程式码范例：即使在注释里，也不要用 `;` 或 `,` 把多条语句写在同一行，以免误导读者。

```no
#{fmt-skip}
; ❌ 错误：用 `;` 分隔多条语句 —— `;` 之后整行都是注释，
; 连块的 `}` 也被一起注释掉，块无法闭合，后续程式码被静默丢弃
; cond -> { print('X'); return }

; ❌ 错误：用逗号连接多条语句
; h0 = 1732584193, h1 = 4023233417
; out = from-i64(v), out = from-u64(v)
; debug(msg), info(msg), warn(msg)
```

```no
; ✅ 正确：每条语句独占一行
cond -> {
    print('X')
    return
}

; ✅ 正确：每条语句独占一行
; h0 = 1732584193
; h1 = 4023233417
; out = from-i64(v)
; out = from-u64(v)
; debug(msg)
; info(msg)
; warn(msg)
```

> **为什么 `;` 特别危险：** `cond -> { print('X'); return }` 里 `; return }` 全被当成注释，实际程式码只剩 `cond -> { print('X')`。块永远不闭合，`}` 之后的所有语句（往往包含该函数剩余的整个函数体）都会被吞掉，报错位置也可能严重偏移，极难定位。

### char 类型（Unicode 码点）

`char` 代表**单个 Unicode 纯量码点**（scalar value）。它的底层存储类型是 **`i32`**，不是 `i64`：

- **合法范围**：`0 ..= 0x10FFFF`（即 `0 ..= 1114111`）。码点最大值只需 21 bit，`i32` 完全放得下。
- **越界报错**：字面量超出该范围时，编译期（含 `no vet`）**直接报错**。例如 `c char = 0x110000` ✗、`c char = 1114112` ✗；`c char = 1114111` ✓。
- **允许数值运算**：`char` **可以直接参与整数运算**，例如 `z = a + 25`、`u = ch - 32`（`ch` 为 `for ch <- s` 的迭代变数）都是**正常写法**，按码点值加减。运算一律按 **i32 宽度**进行，结果视为普通整数值；正因如此，`char` 的 `+ - * /` **不像整数家族那样预设返回 `option<int>`**，不会触发「未处理整数溢出」的编译错误。要注意的只有范围：码点最大 `0x10FFFF`，超出 `i32`/码点语义的场合（如做偏移量、累加计数）建议先显式转成 `i32`/`i64` 再算，让意图更清楚。
- **与 `str` 的关系**：`s[i]` 回传 `char`；`char` 可隐式转为 `str`（UTF-8 编码），详见 [字串 — 隐式转换](str.md)。

> **「底层类型」与「调用转换」是两回事。** `char` 自身就是 `i32`。内置函数 `str_from_cp(cp char) -> ?str` 的**源码签名**参数是 `char`；只有在**调用外部 runtime** 时，编译器才把该 i32 参数**零扩展**（`zext i32 → i64`）以匹配 `@str_from_cp` 的 IR 入参——这只是参数准备阶段的临时转换，**不改变 `char` 的类型**。类似 C 的 `char c='a'; f((long)c);`：`c` 本身是 1 字节，调用时临时提升。

## 类型别名与联合类型

类型别名为现有类型建立一个新名称。使用等号语法 `name = type`，支援单一类型别名和多类型联合。

### 语法

```no
; 联合类型：多个类型用 | 分隔
int = i8 | i16 | i32 | i64 | i128 | u8 | u16 | u32 | u64 | u128
float = f32 | f64
num = int | float
string = str | txt

; 单一类型别名
bytes = []byte
buf = [16]u8
```

> `int`、`float`、`num` 定义在 `std/number`，`string` 定义在 `std/str`——它们都不是编译器内建关键字，而是标准库用同一套别名语法写的联合类型。

### 联合类型的链式引用

联合类型可以引用其他联合类型，形成层次结构：

```no
int = i8 | i16 | i32 | i64 | i128 | u8 | u16 | u32 | u64 | u128
float = f32 | f64
num = int | float; num 是 int 和 float 的联合
string = str | txt; string 直接联合两个具体字符串类型
```

### 在函数中使用

联合类型可用于函数参数和返回值，编译器会自动进行单态化（monomorphization），为每个成员类型生成独立的函数版本：

```no
; 参数类型为 num 联合
max = (a ..num) (r num) {
    r = a[0]
    n = len(a)
    i <- [1..n): {
        a[i] > r -> r = a[i]
    }
}

; 方法定义在联合类型上
num.sign = () (r num) {
    {
        . > 0 -> r = 1

        . < 0 -> r = -1

        -> r = 0
    }
}
```

`string`（= `str | txt`）同样可用于参数与返回值：

```no
; str 与 txt 实参都能传入，各自单态化一份具体函数
take = (s string) (n i64) {
    n = len(s)
}

a str = 'hello'
b txt = 'hi'
n1 = take(a); take__str
n2 = take(b); take__txt
```

> 联合类型函数体的既有限制（`num` 与 `string` 相同）：函数体内对 union 参数调用成员方法（如 `s.len()`）尚不支持，需使用全域内建（`len(s)`，字节数）或拆成具体类型的函数；联合类型的变量声明（`s string = 'x'`）也尚不支持。另注意不要定义与成员方法同名的别名方法（如 `string.len`）——它会接管 `s.len()` 调用并在方法体中递回分发回自身。

### 侦测规则

等号语法在以下情况下被识别为类型别名（而非变数赋值）：

- `name = type | type | ...`：联合类型（含 `|`）
- `name = []type`：切片类型
- `name = [N]type`：阵列类型
- `name = ?type`：可选类型
- `name = known-type`：单一类型别名，其中 `known-type` 是内建类型名（如 `i64`、`f64`、`bool`、`str` 等）或先前已定义的类型别名名称

## 原始字符串（Raw String）

使用一对反引号 `` ` `` ` ` `` ` `` 声明原始字符串，类型为 `str`。

### 语法

```
sql = `
SELECT id,name
FROM user
WHERE id > 100
`
```

### 强制格式约束

1. **开头** `` ` `` 后必须**紧跟源码换行**（LF；Windows 档案的 CRLF 同样接受）；
2. **结尾** `` ` `` 必须**单独占一行**，且该行仅允许空白 + 结束反引号；
3. **首尾两行的反引号所在行不计入字符串内容**，只作为分隔标记；
4. **转义规则**：内部所有 `\`、`\n`、`\t`、`\'`、`\"` 全部**原样保留**，不做任何转义解析；
5. **源码内的换行、缩进空格完整保留**到字符串字节里；CR（`\r`）例外——**一律丢弃**，故 CRLF 档案与 LF 档案得到逐位元组相同的值；
6. **无法直接嵌入反引号字符**，如需包含 `` ` `` 只能用普通单引号字符串拼接。

### 示例

```
; 内容为 "SELECT id,name\nFROM user\nWHERE id > 100\n"
; 转义字符 \n \t 原样保留，不解释
raw = `
line1\nline2
\ttabbed
`
```

## 正则字面量（Regex Literal）

Nolang 支援 JavaScript 风格的正则字面量语法 `/pattern/flags`，用于创建已编译的 `regexp` 实例。

### 语法

```no
; 基本正则字面量
re = /\d+/

; 带旗标（flags）
re = /hello/gi

; 字符类、锚点、量词
re = /[a-z]+/
re = /^hello.*world$/

; 转义斜线
re = /a\/b/
```

### 旗标

| 旗标  | 含义        |
| --- | --------- |
| `g` | 全局匹配      |
| `i` | 不区分大小写    |
| `m` | 多行模式      |
| `s` | `.` 匹配换行符 |

旗标是可选的，跟在结束 `/` 之后，由 ASCII 字母组成。

### 上下文敏感的词法分析

`/` 既是除法运算符也是正则字面量的起始符，Nolang 采用与 JavaScript 相同的**上下文敏感**词法分析来区分：

- **表达式起始位置**（语句开头、`=` / `(` / `[` / `{` / `,` / `:` / `;` 等之后）→ `/` 开始正则字面量
- **值产生位置**（标识符、字面量、`)` / `]` / `}` 等之后）→ `/` 是除法运算符
- `//` 永远是行注释（优先级最高）

```no
; 正则字面量（= 后是表达式起始位置）
re = /\d+/
result = match-text(/[a-z]+/, text)

; 除法运算符（标识符后是值产生位置）
ratio = 100 / 4
x = a / b
```

### 脱糖

正则字面量在代码生成阶段脱糖为对标准库 `regexp-compile` 函数的调用：

```no
; 源码
re = /\d+/

; 脱糖后等价于
re = regexp-compile('\\d+')
```

`regexp-compile` 定义在 `std/regexp.no`，创建 `regexp` 结构体并调用 `.compile()` 编译模式。

### 使用示例

```no
; 创建正则并匹配
re = /\d+/
matched = re.matches('hello 123 world')
print(matched); true

; 查找匹配
re = /[a-z]+/g
result = re.find('hello 42 world')
print(result); "hello"

; 作为函数参数
result = match-text(/\d+/, text)
```

> **注意：** 空 pattern `//` 会与行注释冲突（与 JavaScript 行为一致）。如需空匹配，使用 `/(?:)/`。

## 命名规则

变量名、函数名、结构体名等可以以下划线开头，后续可以使用中连接符、字母、数字组成，不能以数字开头，不能以中连接符结尾，不能连续多个中连接符

**大小写规则（必须遵守）：**

- **全局常量、全局变量**：**必须**使用大写字母开头（如 `NOLANG`、`MAX-SIZE`、`HEX-CHARS`）。私有全局变量以下划线开头，其后仍需大写（如 `_NOLANG`、`_PRIVATE-CONST`）。私有全局只在声明它的模块内可见：**同模块**跨函数读写合法，跨模块以 `mod._BUF` 访问是硬错误（去掉 `_` 升级为公开全局）；`_` 表示「模块私有」，不是「不可被函数引用」。
- **局部变量、函数参数**：使用小写字母（如 `hex-chars`、`data-len`）。**不要**使用 `_` 前缀——局部变量本身就在作用域内私有，不需要可见性标记。`_` 前缀仅用于私有全局变量和 FFI 私有宣告。
- **函数名、结构体名**：使用小写字母（如 `sha1-block`、`db-mysql`）

**函数命名惯例（强烈建议）：**

- **不要在函数名前加上模组名前缀**。模组内的函数只需用简短直观的名称，模组前缀由跨模组调用时的 `ShortName.` 自动带出。例如在 `tail.no` 中定义入口函数 `tail` 而非 `tail-run`，定义辅助函数 `atoi` 而非 `tail-atoi`。这样程式码更简洁，跨模组调用时形如 `tail.tail()` 也更直观。
- **入口函数**建议直接使用模组名本身（如 `ping.no` → `ping`、`cat.no` → `cat`）。跨模组导入形如 `# /src/tail.tail`。
- **注意避开关键字**：`awy`（协程组关键字）、`match`（条件匹配关键字）等不能用作函数名。`run` 已移除，可作普通识别符。
- **`main` 是保留名，不可用作函数名**：Nolang 的程式入口由**顶层语句自动合成**（见 `hir2mir.synthesizeMainForTopLevel`），因此无需、也**不允许**显式定义 `main`。一旦出现 `main = (...) { }`——包含方法 `recv.main`、嵌套在其它函数内的 `main`——编译器直接报错（`'main' is a reserved name and cannot be used as a function name`）。要作为入口，把陈述直接写在顶层即可。

> **全局变量必须大写字母开头**，这是强制规则，不是惯例。小写开头的顶层变量会被编译器视为局部变量，可能导致未定义引用等错误。

```no
; ✅ 正确：全局数据使用大写字母
NOLANG = 'nolang'
MAX-SIZE = 1024
HEX-CHARS = '0123456789abcdef'

; ✅ 私有全局变量：下划线开头，其后仍需大写
_NOLANG = 'nolang'
_PRIVATE-CONST = 42
```

```no
#{fmt-skip}
; ❌ 错误：全局变量不能使用小写字母开头
; x1 = 10
; x = 10
; foo-bar = 42
; hello-world = 'Hello World'
```
```

```no
#{fmt-skip}
; ✅ 局部变量（函数内）使用小写字母，不加 _ 前缀
; fn-example = () {
;     x1 = 10
;     x = 10
;     foo-bar = 42
;     hello-world = 'Hello World'
;     ; ❌ 错误：局部变量不需要 _ 前缀
;     ; _x = 10
; }
```
```

### 模组中避免使用全局变量

**强烈建议：如非必要，不要在模组（`.no` 档案）中使用全局变量。** 全局变量会带来以下问题：

- **编译器 bug 风险**：Nolang 编译器对全局结构体变量的跨函式记忆体位址处理存在已知限制，不同函式可能看到不同的位址，导致状态不一致。
- **并发安全**：全局可变状态在 fork 或异步场景下难以追踪，容易引发竞态条件。
- **可测试性**：全局状态使函式产生隐式依赖，难以隔离测试。
- **程式码可读性**：全局变量使资料流隐晦，读者需追踪整个模组才能理解函式行为。

**推荐做法：**

1. **优先使用局部变量**：将状态保留在函式内的局部变量中，透过参数和返回值传递。
2. **使用结构体封装状态**：将相关状态组织到结构体中，透过方法操作（方法接收者为局部变量，位址一致）。
3. **仅在必要时使用全局变量**：如模组级常量（不可变）、单例资源（如全域日志缓冲区）等场景。
4. **全局变量必须大写**：这是强制规则（见上文），小写开头的顶层变量会被编译器视为局部变量。

```no
#{fmt-skip}
; ❌ 避免：在模组中使用全局可变变量
; g-conn = tls.conn {}
; g-buf = ' '
;
; fn-a = () {
;     g-conn.send(g-buf)   ; 全局变量跨函式可能位址不一致
; }
```
```

```no
; ✅ 推荐：使用局部变量，状态透过参数/返回值传递
fn-a = () {
    conn = tls.conn {}; 局部变量，位址一致
    buf = ' '
    conn.send(buf)
}

; ✅ 推荐：将完整流程封装在单一函式中，避免状态跨函式传递
serve-once = (listen-fd fd, body str) (ok bool) {
    ok = false
    client-fd = net.net-accept(listen-fd)
    conn = tls.server-init(client-fd); 局部变量
    conn: {
        ok -> {
            c = it
            c.handshake()
            c.send(body)
            c.close()
            ok = true
        }

        -> fs.close(client-fd)
    }
}
```

> **实践案例**：`std/net/tls.no` 的 `https-serve-once` 函式将完整的 HTTPS 请求-回应周期（accept + handshake + recv + send + close）封装在单一函式中，所有 TLS 状态保留在局部变量中，成功避开了全局变量跨函式位址不一致的编译器 bug。

### 可翻译的文档注解（Markdown 连结）

文档注解可以用一条**独立的 Markdown 连结**收尾，把整段注解指向翻译目录中的一个条目：

```no
; get: 获取第 i 个参数
; 委派至 os.arg(i) builtin（读取 main 的 argv[i]）；越界回传 nil
; [get](#args.get)
get = (i i64) (val ?str) {
    val = os.arg(i)
}
```

**规则：**

- 连结必须是注解群组的**最后一行**，且独占一行；它上方的所有行构成一个整体，作为一条讯息整段翻译
- 目标必须是 `#` 开头的锚点（同一份目录内的条目）。`[说明](https://example.com)` 这类外链是写给人看的普通连结，**不会**被当成翻译标记
- 锚点即键（`args.get`）。它由作者指定、译者在目录里看到，不从文字派生——所以改写措辞不会让既有译文失效。锚点允许字母、数字、`.`、`_`、`-`，并且是全域的，建议加上模组前缀
- 前缀用**打平后的模组名**，不是目录名。编译器把 std 档案打平成它的档名：`std/collection/linked-hash-map.no` 的模组就是 `linked-hash-map`，`use std/collection` 也不会给符号加 `collection.` 前缀。所以 `linked-hash-map.clear` 的锚点是 `linked-hash-map.linked-hash-map.clear`（模组名 + 原样的名字），**不是** `collection.linked-hash-map.linked-hash-map.clear`。`collection`／`net`／`crypto`／`archive`／`encoding`／`database` 这些目录段不属于任何符号，不该出现在锚点里
- 方括号里的字（`[get]`）只是给读原始码的人看的提示，显示时整行都会被剥掉；`[](#args.get)` 也合法
- 只有 `;` 单行注解可以带连结（`;;` 与 `;;block` 不算）

译文放在 `locales/<语言>-doc.noml`，以锚点为键。缺少译文时回退到注解原文，不会变成空白。档名遵循 `.no` 的命名规则（小写字母、数字、单一中划线），标签本身就是这个形式：`--lang=zh-tw` 读的是 `zh-tw-doc.noml`。

标准库里每个有注解的函数与方法都已带上锚点（约 2000 条），所以任何一条译文一落地，LSP 立刻就能用。`make i18n` 只把**已翻译**的条目写进目录，不会把原文当成译文塞进去——否则英文目录里又会出现中文。`go run ./i18n/cmd/genen -doc-missing` 会列出还没翻译的锚点。

**LSP 提示：** 滑鼠悬停在函数名上会显示翻译后的整段说明；悬停在连结那一行上，则显示锚点本身指向的内容（同样是当前语言），方便就地核对译文。

### TOML 设定档（`toml`）

标准库 `toml` 提供 TOML 1.0 设定档的解析与序列化。解析器支援注解、bare/quoted/dotted keys、`[table]`、`[[array-of-tables]]`、basic/literal/multiline strings、整数（十进位/十六进位/八进位/二进位）、浮点数、布林值、日期时间、阵列与 inline table。值以 TOML 原始字面值保存，因此不会遗失阵列、日期时间等资讯。

```no
cfg = toml.parse('title = "Nolang"\n[server]\nport = 8080\n[[server.backends]]\nname = "local"')

doc = toml.new()
doc.put('name', '"nolang"')
doc.put('server.port', '8080')
doc.put('enabled', 'true')
text = toml.stringify(doc)
```

常用 API：

- `toml.new()` — 建立空的 `toml`
- `toml.parse(text)` — 解析 TOML，回传 `?toml`
- `doc.put(key, raw-value)` — 新增或更新原始 TOML 值；会拒绝非法值、重复键由解析器报错
- `toml.get(doc, key)` — 取得原始值（`?str`）
- `toml.get-str(doc, key)`、`toml.get-i64(doc, key)`、`toml.get-f64(doc, key)`、`toml.get-bool(doc, key)` — 取得已转换的 scalar
- `toml.stringify(doc)` — 输出 TOML；array-of-tables 会输出 `[[...]]` 标头

目前文件模型限制单一文件最多 4 个 key、2 个普通表格与 2 个 array-of-tables；单一 key 最长 32 bytes、单一 value 最长 128 bytes，超出时应分割设定档或由呼叫方处理。

### YAML 文件（`yaml`）

标准库 `yaml` 解析与产生 YAML 1.2 core schema 文件，支援块映射、块序列、流式集合、三种引号标量、块标量 `|` / `>`、注解、多文档、锚点与别名、合并键 `<<`、显式键，以及型别推断（null / bool / int / float / `.inf` / `.nan`）。

```no
doc ?yaml = yaml.parse('name: Alice\nserver:\n  port: 8080\ntags:\n  - a\n  - b\n')
doc: {
    nil -> print('nil')

    err -> print(it.msg())

    -> {
        doc = it
        name = doc.find-str('name'); ?str
        port = doc.find-i64('server.port'); ?i64
        name: {
            ok -> print(it)

            -> print('')
        }
        print(doc.to-json())
    }
}
```

常用 API：

- `yaml.parse(text)` / `yaml.parse-all(text)` — 解析，回传 `?yaml`
- `yaml.valid-of(text)` / `yaml.error-of(text)` — 只做校验
- `it.find(path)` / `it.get(key)` — 取子节点，回传 `?yaml`
- `it.find-str(path)`、`find-i64`、`find-f64`、`find-bool` — 便捷取值，回传 `?值`
- `it.to-json()` / `it.to-yaml()` — 序列化

> 注意：子节点以 `?yaml`、取值协助函式以 `?值` 回传，用 match 解包（`child = it.find(path)`，其 `ok` 臂以 `it` 绑定子节点、预设臂处理空值，每臂独立一行）。

## 档案命名

`.no` 档名（含文件夹名）一律使用中连字符 `-` 连接单词，**不使用下划线 `_`**。这与变量名、函数名、结构体名等 Nolang 标识符的命名风格保持一致。

编译器在 `run` / `build` / `test` / `vet` / `fmt` / `ast` 命令中**强制检查**此规范，路径中任何一段（资料夹名或档名主体，`.no` 副档名不计入）违规都会**直接报错**：

- 允许的字元：小写字母 `a-z`、数字 `0-9`、中连字符 `-`。
- 禁止的字元：下划线 `_`、大写字母、以及其他特殊符号。
- 中连字符不得以段首／段尾出现，且不得连续（`--`）。

例如 `tmp/zz_stridx/r_index.no` 因 `zz_stridx` 与 `r_index` 含下划线而被拒；改为 `tmp/zz-stridx/r-index.no` 即合规。绝对 OS 路径（如 `/Users/me/proj/a.no`）只验证落在目前工作目录下的部分，宿主目录名（如 `Users`）不会误报。

```shell
✅ 推荐：
utils/
├── string-helper.no
├── hash-table.no
└── http-client.no
```

```shell
❌ 避免：
utils/
├── string_helper.no
├── hash_table.no
└── http_client.no
```

## 函数定义

函数可以透过**具名结果参数（named result parameters）**&#x8F38;出结果，本质是  
**输出参数（out-parameter）的语法糖**；`return`（及其简写 `***`，暂不推荐使用）仅用于提前终止，不能跟结果。

Nolang 的函数定义形式为 `name = (in-params) (out-params) { body }`：第二个  
括号组 `(out-params)` 宣告具名结果参数（语法糖）。函数体内对它们赋值  
（与普通入参一样皆为引用型别）；**真正接收结果的变数必须在调用处定义**——  
定义里的结果参数名只是占位符，调用方的 LHS（或尾随引数）决定结果落在哪个  
变数：

```no
parse-line = (s str, max-fields ?i64) (fields []str) {
    ...; 函数体内对 fields 赋值
}

; 调用处定义接收变数（LHS 绑定，型别由签名推断）
fields = parse-line(line, nil)

; 多结果按顺序绑定
a, b = swap(x, y)

; 或尾随引数形式：res 作为额外的输出引数传入
add1(5, 3, res)
```

Nolang 的函数有以下特点：

- **具名结果参数是语法糖**：底层仍是透过入参（out-parameter）完成，不会产生  
  新的返回值物件，因此内部是安全的。
- **输入参数唯读**：标量传值，复合类型传唯读引用；禁止在函数体内写入输入参数及其子栏位。
- **输出参数可写**：调用方可将已有变数绑定到输出槽，函数直接在该记忆体修改；也可不绑定，由函数生成新值交付。
- 函数内的变量在函数退出时自动销毁。
- 调用处必须提供接收变数（LHS 或尾随引数）；「函数没有返回值」的说法不准确——  
  准确说法是：结果透过具名结果参数（out-parameter 的语法糖）传递，且由调用处绑定。
- **别名规则**：允许输入唯读引用与输出槽指向同一物件。只要写操作仅发生在输出区、输入仅读取，即为合法；编译器不做静态别名检查。

### 输出槽直接绑回既有变数（避免中继变数）

呼叫端的输出槽可以**直接绑到已存在的变数**，函式会就地改写它的记忆体（见上方「输出参数可写」）。
因此当某个输出只是要接续更新既有状态时，不必先接到一次性中继变数、再写回：

```no
; ✅ 推荐：余数直接写回 r（r 同时是方法的接收者）
qsq, r = r.div-mod(modulus)
```

```no
; ❌ 避免：msq 只被用一次，纯粹是转存
qsq, msq = r.div-mod(modulus)
r = msq
```

- **接收者可同时是输出目标**：`r.div-mod(modulus)` 的接收者 `r` 是唯读输入（隐式 `self`），
  `r` 又绑到第二个输出槽 `r bigint`；依〈别名规则〉，输入只读、输出只写即合法。
  实测（`no build` / `no vet` / `no fmt`）`q, a = a.div-mod(bigint.from-i64(7))` 在
  `a = bigint.from-i64(100)` 之后得到 `q = 14`、`a = 2`，与「先接 `msq` 再 `r = msq`」完全一致；
  即便 `r` 是外层函式的结果参数也一样成立（`src/std/bigint.no` 的 `mod-pow` 正是这种形状）。
- **用不到的输出用 `_` 丢弃**：若商根本没用到，`_, r = r.div-mod(modulus)` 连一个新变数都不必引入，
  是最精简的写法（见后面〈多重赋值〉的 `_` 占位）。
- **单一输出同样成立**：`r = r._mul(r)`、`s = s.trim()`、`out = out.replace-str(...)` 都是 stdlib 既有的就地更新。
- **既有合法程式码不必为此改写**：这是新写程式码的推荐写法，不是重构令；遵循〈黄金法则：不要修改合法程式码〉，
  不要为了风格去动已经正确的程式。

### 参数默认值

**不支援**。参数列表中的 `name type = expr`（例如 `foo = (a i64, b ?i64 = 10)`）是**语法错误**（`E_DEFAULT_PARAM`）：编译器不解析默认表达式，也不会在任何调用点填充默认值。这消除了「一个宣告、多种合法 arity」的歧义，也避免了在每个调用点重复降级默认表达式造成的单态膨胀。

需要可选语义时，把参数宣告成 option 型别 `?T`，由呼叫端**显式**传 `nil` / `ok(...)`，函数体用 `match` 处理：

```no
parse-line = (s str, max-fields ?i64) (fields []str) {
    limit = 1024
    max-fields: {
        ok(v) -> limit = v

        nil ->

        err ->
    }
    ...; limit 即上限
}

; 调用端必须显式传参
fields = csv.parse-line(line, nil); 回退 1024
fields = csv.parse-line(line, ok(256)); 上限 256
```

```no
add = (a i64, b i64) (result i64) {
    result = a + b; 通过参数返回结果
    ...; 占位陈述：不做任何事，build 时整条丢弃（见〈占位陈述〉）
}

; 可变参数
add3 = (a ..i64) {
}

; 函数调用
sum = add(1, 2); sum == 3

; 匿名函数 和for？ 有传参？
(a i64) {
    print(a)
}(10)

; 函数调用
add(a, b)

; 也可能有多个返回值
a, b = swap(5, 3)
```

## 流程控制

> **Deprecated 语法（n 版本后移除）**：`for { }` / `for cond { }` / `for init, cond, update { }` / `for i in [..) { }` / `match x { }` / `if/elif/else { }` 仍可解析但会输出 deprecation warning。请改用下方「**新式语法**」。

### 新旧对照

| 旧式 / 后缀式（suffix）           | 前置式（prefix，format 预设）                   |
| -------------------------- | --------------------------------------- |
| `{ } (true)` 无限循环          | `!! { }` 或 `true { }`                   |
| `{ } (cond)` 条件循环          | `(cond) { }`（空 `()` 视为 false，不执行）       |
| `{ } ()` 不执行               | `! { }` 或 `false { }` 或 `() { }`        |
| `{ } * n` 常数计数             | `n * { }`（N ≤ 0 时循环体不执行）                |
| `for i=0, i<n, i++ { }` 计数 | `n * { }`（常数计数）或 `i <- [0..n): { }`（变数） |
| `for i <- [a..b] { }` 范围   | `i <- [a..b]: { }`                      |
| `for i in [a..b) { }` 范围   | `i <- [a..b): { }`                      |
| `match x { ... }` 匹配       | `x: { ... }`                            |
| `if/elif/else { }` 分支      | `{ cond -> body }`（短路，必须用 `{}` 包裹）      |
| `continue`                 | `*`（简写暂不推荐）                        |
| `break`                    | `**`（简写暂不推荐）                       |
| `return`                   | `***`（简写暂不推荐）                      |

### Loop / While / for-in

> **两种等价写法**：同一个循环支援「前置式 `(cond) { }`」与「后缀式 `{ } (cond)`」，  
> 语意完全相同，只是条件与主体的先后顺序不同。`no fmt` 预设输出**前置式**；  
> 可用 `no fmt -loop-style=suffix` 切回后缀式（两种写法都保证格式化幂等）。

```no

; 无限循环（条件恒为 true）—— 以下两种等价

    ...
}
!! {
    ...
}

; 不执行（条件恒为 false）—— 以下三种等价
! {
    ...
}
! {
    ...
}
! {
    ...

    do-something()

    do-something()

    ...

    ...

;   (5..1]  → 4 3 2 1     左开右闭，递减

    ctn

    brk

```

> ⚠️ **`return`（及其简写形式 `***`，简写暂不推荐使用）只能裸用，不能带返回值。**  
> Nolang 函数没有「返回值」机制——结果一律通过**具名结果参数（out-param）**&#x5728;函数体内赋值传出（见「函数定义」）。  
> 因此 `return <值>`、`return(expr)`、`*** <值>` 都**被禁止**，编译器 / formatter / LSP 都会报错：
>
> - 编译器（`no build`）：`Error: compilation error: parser errors: line L, column C: 'return' 后不能跟返回值；… [E_GENERAL]`
> - `no vet`：`<file>:L:C: [ERROR] nolang-compile: 'return' 后不能跟返回值；… [E_GENERAL]`（与其他诊断同一格式，每条一行）
> - `no fmt`：`format error: …` 并以非零状态退出
> - LSP：在对应行显示红色错误诊断
>
> 错误写法：
>
> ```no
> has = (n i64) (r i64) {
>     n == 0 -> return 0        ; ❌ 编译 / formatter / LSP 均报错
>     r = n
> }
> ```
>
> 正确写法（先给结果参数赋值，再裸 `return` 提前终止；臂体里的多条语句只能各占一行）：
>
> ```no
> has = (n i64) (r i64) {
>     n == 0 -> {
>         r = 0
>         return
>     }
>     r = n
> }
> ```
>
> ⚠️ 压成一行写 `n == 0 -> { r = 0; return }` 不是简写：`; return }` 整段是注释，
> 块因此永不闭合，后续所有语句（常是整个函数体的剩余部分）都被静默吞进这个臂里 ——
> 实测 `no vet` 不报错，函数从未被呼叫。

## 通道（`chan[T]`）

通道是**有界、可增长、发送不阻塞、接收等待**的值队列，接收端以三态 `?T` 逐个取用。
它只保留一种语法符号：`<-`（其余用法见「流程控制」的 `i <- range:` 遍历）。

```no
ch chan[i64] = with-cap(8)   ; 显式初始容量
buf chan[i64]                 ; 裸宣告：等价于 with-cap(0)，发送时按需增长

ch <- 1                       ; 发送（左侧型别是 chan[T] 才算发送）
n = ch.len()                  ; 当前积压数
c = ch.cap()                  ; 初始容量
ch.close()                    ; 关闭：不再接受发送，既有值仍可取
```

### 接收：三态循环

`v <- ch: { ... }` 是**循环**，每轮把三态 `?T` 绑给 `v`；`break` 可提前退出。
`ok` 表示取到值、`nil` 表示通道已关闭且已取空、`err` 表示**真错误**（未初始化的
零值句柄——没有东西可等）——**后两者都会结束循环**（同一轮的臂照常执行）。

`ok` 之外最重要的一条：**空读是「等值」而不是「没有值」**。通道打开但空时，读者
挂起，直到有人 `send` 或 `close`：

- 在协程里（`co` 出来的 `-async` 克隆）它真的 park：状态号写进堆上的帧，任务从
  通道的等待链上登记后返回调度器（见「协程」一节）；
- 在普通函数里没法 park，于是**阻塞**：反复驱动就绪队列，直到有值可取。

所以「取空」必须由 `close()` 结束回圈，形状与 Go 的 `range` over channel 一致。

```no
ch chan[i64] = with-cap(2)
ch <- 10
ch.close()

<- ch: {
    ok -> print('got {it}')      ; it 是本轮的元素
    nil -> print('closed')       ; 取空后落到这里
    err -> print('bad channel')  ; 只有零值句柄才会落到这里
}
```

丢弃回圈变数时写 `<- ch: { ... }`；若 body 的第一条陈述不是对 `v` 的 match，
则 `v` 直接绑**元素本身**（`T` 而不是 `?T`），只有 `ok` 那些轮才跑 body：

```no
i <- ch: {
    print(i)                     ; i 是 i64，不是 ?i64
}
```

要自己分辨三态又想留住回圈变数，body 开头 match 它即可；只写臂（省掉 `v:`）
是同义简写——判据落在**臂名**上，`ok` / `nil` / `err` 三个名字出现才算三态：

```no
i <- ch: {
    ok -> print('got {it}')      ; it 是本轮元素，i 是本轮的 ?i64
    nil -> print('closed')
    err -> print('empty')
}
```

判据是语法的、不是型别的（见下方「形态判定」）。`no fmt` 会把上述简写补成
显式主语 `i: { ... }`；两种写法都能再解析，格式化是幂等的。

### 形态判定

| body 开头 | 形态 | `v` 的型别 |
|---|---|---|
| `co bar(i)`、`print(i)` 等普通陈述 | 元素 | `T` |
| `v: { ... }` | 三态 | `?T` |
| `ok -> ...` / `nil -> ...` / `err -> ...` | 三态（简写） | `?T` |
| 其他裸 match（如 `i > 5 -> ...`） | 元素 | `T` |

判定必须在**解析 body 之前**完成：区块开头若是 match，解析器会立刻把它降糖成
`if` 链，事后再也认不出原意。这一格曾经整格失效——`i <- ch:` 一律被当成元素形态，
三态臂退化成互不相干的独立 guard（每轮全跑），`it` 绑到空值。

### 语义

| 面 | 规则 |
|---|---|
| 容量 | `with-cap(n)` 的 `n` 是**初始**容量；满了之后倍增，`send` **永不阻塞、不丢值** |
| 空读 | **等待**：协程 park、普通函数阻塞驱动就绪队列；`err` 只留给零值句柄这种真错误 |
| 关闭 | `close()` 之后 `send` 中止进程；已入队的值仍按顺序可取，取完报 `nil`；关闭同时唤醒全部等待者 |
| 载荷 | 发送时**深拷贝**（`str` / `%vec` 走 clone），接收方拿到的是独立的一份；不必担心来源变数被改写或提前释放 |
| 并发 | 通道本身不加锁（单线程协作式排程）：等待者挂在控制块的 `waiters` 链上，`send` / `close` 摘下整条链逐个重新入队；**被唤醒不等于拿到值**，恢复后必须重跑可读性判断，所以协程的恢复点是 park 块本身 |
| 死锁 | 就绪队列空、目标任务仍未完成 ⇒ 无法再推进：执行期印 `nolang: deadlock: …` 到 stderr 并 abort，而不是回一个没人送过的值或空转 |

> 空读挂起的一个直接后果：**排空循环必须靠 `close()` 结束**。早期版本把「打开但空」
> 报成 `err` 让循环自然退出，于是 `for` 形状不必关闭通道；现在那条路径是等待，
> 忘记 `close()` 的程式会停在最后一轮（协程里挂起、普通函数里被判死锁）。

### 限制

- **只有 LLVM 后端实作。** `no build --js` / `--wasm` 遇到任何通道节点会给出明确错误
  （`[chbkn001]`），而不是静默产出残缺程式码。
- 通道是**值型别**（一个机器字宽的句柄），可以作为参数、结果或元素传递；
  `chan[chan[T]]`、`?chan[T]` 都能宣告（尚未纳入 `tests/chan.no` 的覆盖）。

## 占位陈述（`...`）

`...` 是语言的一条**占位陈述**：语法上合法、语义上**什么都不做**。主要用于文档演示、
代码骨架与 `TODO` 预留位置。编译时整条陈述在 AST→HIR 阶段即被丢弃，产物与「从没写过这行」
完全一致（实测同一份源码加减 `...` 编译出的二进位 `sha256` 相同）。

```no
parse-line = (s str) (fields []str) {

    ; TODO: 这里还要处理跳脱字元
    ...

    fields = csv.parse-line(s)
}

add = (a i64, b i64) (result i64) {
    result = a + b
    ...
}
```

规则：

- **只能独占一行**（行尾可跟 `;` 注释）。`fail -> ...`、`x = ...`、`[0...n)` 这类写法
  一律报语法错误——`...` 没有值，不能出现在表达式位置或陈述的其余部分。
- **不是 `return` 的别名**，也**不是范围运算子**：范围是 `..`（两点），提前返回写 `return`。
- `no fmt` 原样保留，既不删除也不挪位。

以下写法全部不合法：

```no
#{fmt-skip}
add = (a i64, b i64) (result i64) {
    result = a + b
    ...          ; ✅ 唯一合法形式：独占一行
}

ok -> ...        ; ❌ 语法错误：`...` 不能出现在表达式位置
x = ...          ; ❌ 语法错误：同上
i <- [0...n): {  ; ❌ 语法错误：`...` 不是范围运算子，应写 [0..self.n)
}
```

### Match

```no
; 简单写法，it 用于取参数
x: {
    err -> log(it.msg()); it 是结构化错误 err.err

    nil -> log('nil')

    -> do-right-thing(it)
}

; 析构写法
x: {
    err(e) -> log(e.msg())

    nil -> log('nil')

    ok(v) -> do-right-thing(v)
}

; 注：struct 模式匹配（`user: { User{id=1} -> ... }`）与栏位绑定尚未支援，故不示范

score: {
    [0..59] -> print('不及格')

    [60..89] -> print('良好')

    [90..100] -> print('优秀')

    -> print('分数非法')
}

; 区间语法共 16 种组合，规律：'[' 表示包含左端点，'(' 表示不包含；
;                     ']' 表示包含右端点，')' 表示不包含。
;
; 【有界区间】（4 种）— 两端都有具体值
;   [a..b]  → x >= a && x <= b   两端都包含
;   [a..b)  → x >= a && x <  b   左包含右不包含
;   (a..b]  → x >  a && x <= b   左不包含右包含
;   (a..b)  → x >  a && x <  b   两端都不包含
;
; 【无上限区间】（4 种）— 省略右端点（End=nil），仅检查下界
;   [a..)   → x >= a              左包含，无上限
;   [a..]   → x >= a              左包含，无上限
;   (a..)   → x >  a              左不包含，无上限
;   (a..]   → x >  a              左不包含，无上限
;
; 【无下限区间】（4 种）— 省略左端点（Start=nil），仅检查上界
;   [..b]   → x <= b              无下限，右包含
;   [..b)   → x <  b              无下限，右不包含
;   (..b]   → x <= b              无下限，右包含
;   (..b)   → x <  b              无下限，右不包含
;
; 【完全无界区间】（4 种）— 两端都省略，基于类型最小值/最大值
;   [..]    → true                类型最小值 ≤ x ≤ 类型最大值（两端都包含）
;   [..)    → true                类型最小值 ≤ x < 类型最大值
;   (..]    → true                类型最小值 < x ≤ 类型最大值
;   (..)    → true                类型最小值 < x < 类型最大值
;
; 在 match 中，完全无界区间基于被匹配变量的类型值域（必然为真，等同 catch-all）。
; 在 range-for 中，基于迭代变量的类型范围（如 i64 的 [..] 从 i64.MIN 到 i64.MAX）。
;
; 范例：使用无界区间做完整分类
v = 85
result = v: {
    [..0) -> 'negative'

    [0..60) -> 'fail'

    [60..80) -> 'pass'

    [80..90) -> 'good'

    [90..100] -> 'excellent'

    (100..) -> 'extraordinary'
}
print(result)

num: {
    1 || 3 || 5 || 7 -> print('奇数小数')

    2 || 4 || 6 -> print('偶数小数')

    -> print('更大数字')
}

; 有返回值，最后一个语句/值
result = x: {
    1 -> 1

    2 -> 2 + 1

    -> a + b
}

; 多行 arm body 必须使用大括号 -> { ... }
x: {
    nil -> {
        log('nil')
        do-cleanup()
        return
    }

    err -> {
        log(it.msg())
        do-cleanup()
        return
    }

    ok -> print(it)
}
```

> **多行 arm body 规则**：当 arm body 包含多个语句时，必须使用大括号 `-> { ... }` 括起来。单行 body 可直接写在 `->` 之后。这是因为多行 body 若不使用大括号，option match 的 `it` 绑定将无法正确插入，导致编译错误。

> **for-in 体内 match 语义**：`i <- (a..b]: { 1 -> ... 2 -> ... }` 对每个迭代变量 `i` 执行一次 match 体（`1 ->` 等同于 `i == 1 ->`，依此类推）。这是每轮迭代执行一次 match 的语法糖。

#### Match 主语的三种形态

match 主语可以是**值**、**表达式**或**块**：

| 形态 | 写法 | 求值方式 |
| --- | --- | --- |
| 值 | `x: { ... }` | 直接匹配 `x` |
| 表达式 | `x + 1: { ... }` | 先算出表达式的值再匹配 |
| 块 | `{ ... }: { ... }` | 执行一段陈述主体，匹配其间 `?=` 的结果 |

前两种是**表达式**：既可当陈述，也可在值语境取值（`v = x: { ok -> it, -> 0 }`）。
第三种**只是陈述**——不是表达式、不能赋值、没有区块尾值，`-> _` 用来丢弃结果。
`no fmt` 会把 `}: {` 原样往返，臂间空行规则与一般 match 相同。

##### 表达式主语（`expr: { ... }`）

`expr: { ... }` 的 `: {` 优先级**高于** `=`：在赋值右侧它是整段 RHS，而不是
「先完成 `r = <expr>`、后面再跟一条独立的 match」。因此 option 算术可以一段式解包：

```no
#{overflow=wrap}
rem = seconds % 3600: {
    ok -> it

    -> 0
}

#{overflow=wrap}
sec = rem % 60: {
    ok -> it

    -> 0
}
```

这等价于先前必须拆开的三段式 `rem-opt = seconds % 3600` / `rem = 0` /
`rem = rem-opt: { ok -> it  -> 0 }`。首次赋值可以带显式型别
（`rem i64 = seconds % 3600: { ... }`），二次指派则直接写 `rem = ...: { ... }`；
两者都是单一值位 match，结果型别由臂尾表达式决定。

语意与限制：

- 主语是 D6 option 算术（`+ - * / %`）时结果为 `?T`。match 会把它归一化成
  `__match_subj_L_C ?T` 合成暂存：主语**恰好求值一次**、`ok -> it` 绑到 payload、
  条件走 option tag 比较，`-> 0` 兜底 `nil` / `err`。合成名不会出现在诊断或
  `no fmt` 输出里。
- match 的结果是 **plain T**，并会登记进语义副表；因此后续可继续写
  `sec = rem % 60: { ... }`，连续多段值位 match 不会丢失 payload。
- 值位 match 只在**值语境**附加（赋值／`?=`／复合指派的右侧），且 `: { ... }`
  必须真的是 match 区块。`cond: { body }` 这类陈述层级的条件循环与 struct 字面量
  仍走既有解析路径，不受影响。
- **栏位目标的赋值也是值语境**（2026-11-09 起）：`d.month = mp - 9: { ... }`、
  `b.n ?= b.n + 1: { ... }` 的 `: {` 绑在**右值**上，不是整个赋值。此前这两条
  分支在解析右值时漏推 `CTX_EXPR`（识别字目标走 `let` 有推、`obj.f =` / `a[i] =`
  没有），结果 `: {` 被语句层捡走、套在整个赋值外层，解析成
  `match(主语 = (d.month = mp - 9))`：赋值照旧执行并把 `?T` 隐式拆包后写进栏位，
  而 `ok -> it` / `-> 0` 两臂形同死码。现在臂值才真正落回栏位。
- 索引目标（`a[i] = …: { ... }`）形状相同，但 D9 本来就禁止下标直写，这种写法
  仍会被 checker 以 `idxwrite` 拒绝，须改写成 place-match（`a[i]: { ok -> it = v }`）
  或 `?=`。
- `no fmt` 原样往返 `expr: { ... }`，不会拆成赋值＋独立 match 两条陈述。
- **型别可见性边界**：option 算术主语要归一化成 `?T`，两个运算元的宣告型别必须
  能被 parser 静态看见。若运算元来自深层方法链（接收者型别连 AST 回放都推不出），
  就在它的宣告上补一个显式型别，例如 `e i64 = flr.to-i64()`；否则归一化会保守
  跳过，`ok -> it` 没有绑定、MIR 零填，观测值恒为 0。`src/std/number.no` 的
  `f64.to-str-general` 就是这样：少了这个标注，`fmt.fmt-f64(2.5, '')` 会从
  `'2.5'` 退化成 `'3'`。回归钉在
  `src/parser/value_match_expr_subject_test.go::TestValueMatchExprSubjectASTAnnotatedOperand`
  （拿掉标注即红）。

`src/std` 已于 2026-11-09 把 **122 处 / 22 个模组**的 option 解包改成这个一段式写法：
除最初的三段式（`x-opt = expr` / `x = 0` / `x = x-opt: { ... }`）外，也涵盖两段式
（无零值初始化）、显式型别首次赋值（`x i64 = expr: { ... }`）、以及中间变数在同函式
内多次成对宣告的写法。折叠后主语可以是方法呼叫、索引或 option 算术；
`ok -> it`／`ok(v) -> v`／常量臂／`-> _` 皆经实测等价，`no fmt` 对这些站点幂等。
编译器的型别推断同时照顾「语义副表查到 `?T`、但宣告其实是 `i64`」这种全域同名残值，
`ok -> it` 不会因此丢失绑定。

保留（9 处）的情形：① 内层 match 会写回 `-opt` 变数本身（该变数是后续值位 match
的主语）；② 两层链式 option match；③ 按值分派的值位 match（如 errno → 讯息，不是
option 解包）；④ 宣告与 match 之间还有其它陈述、或中间变数是跨分支累积的结果
（折叠会改变求值时机）。

##### 块主语（`}: {`）

块主语把一段陈述包起来，让**没有 `?T` 结果参数的函式**也能就地处理 `?=` 的上抛：

```no
; d i64: 除数，0 时 6/d 得 err
f = (d i64) {
    {
        v ?= 6 / d; 失败不再要求函式有 ?T 结果参数
        print(v.to-str()); 失败时不会执行
    }: {
        err -> print(it.msg())

        nil -> print('nil')

        -> _; 丢弃结果
    }
    print('之后照常执行'); arms 跑完后流程继续
}
```

语意：

- 主体内的 `?=` 由**最近的**块 match 捕捉（巢状时最内层优先；即使所在函式有
  `?T` 结果参数，也是块 match 优先）。捕捉是递回的：裸块、if 主体、回圈主体、
  match 臂里的 `?=` 都算；函式定义是边界，函式字面量不是。
- 被匹配的是三态 `?T`，沿用标准 option match 的**穷尽性检查**：没有兜底臂时，
  即使 `ok ->` 执行期不可达，也必须补齐 `nil` / `err` / `ok` 三臂。
- 主体顺利走完（零个 `?=` 或全部成功）⇒ 匹配到 `nil`；某个 `?=` 失败 ⇒ 匹配到
  该次的 `nil` 或 `err`（`err` 臂的 `it` 是完整的 `err.err`，见〈`it` 的型别〉）。
- **一次失败停住整个主体**：后续陈述、后续回圈 iteration 都不再执行，arms 只跑一次。
  这是「停止区块」，不是函式 `return`，使用者自己的 `return` / `break` / `continue`
  绑定不受影响。
- 展开完全由既有核心 AST 组成（合成 `?T` 区域变数 + `if` 守卫链 + 一般 match），
  没有新的 HIR / MIR 节点。合成变数名不出现在诊断或 `no fmt` 输出里。

> 与 `=` 就地捕获的分工：`=` 把失败**存进目标变数**、流程继续；`}: {` 把失败
> **收敛成一条 match**、并停止主体剩余部分。需要「失败后仍继续」时用 `=` +
> 后续 match；需要「失败就跳到清理臂」时用 `}: {`。

##### 块 match 与值位 match 的取舍

同一件事——把一条 option 算术的结果拉回 plain 变数——有两种写法。**块主体只有这一条陈述
时两者等价；一旦主体里还有别的陈述、或右值能从别处失败，语意就分岔。**

```no
; A：块 match + `?=`（区块级「try」）
{
    #{overflow=wrap}
    np ?= np + 1
}: {
    err -> _

    -> _
}

; B：值位 match 直接绑目标（陈述级）
#{overflow=wrap}
np = np + 1: {
    ok -> it

    -> _
}
```

`#{overflow=wrap}` 下 `np + 1` 的结果**恒为 `ok`（回绕值）**，两者都只生成一条裸
`add i64`、没有溢出检查分支，失败臂对「加法本身」是死码——这是它们在多数站点看起来
「完全等价」的原因。真正的差别在**作用范围**与**失败路径**：

| 维度 | A：块 match + `?=` | B：值位 match |
| --- | --- | --- |
| 语法位置 | **陈述**：无尾值、不能赋值 | **表达式**：可放赋值右侧、栏位目标、`?=` 右侧 |
| 失败时写入目标 | **零值**（`i64` → `0`、`str` → `''`） | 由兜底臂决定：`-> _` **不写**（保留原值）、`-> 0` 写 0、`-> sum` 写回旧值 |
| 主体剩余陈述 | **全部跳过**（含后续回圈迭代） | 照常执行 |
| 一个 `err` 臂涵盖 | 块内**所有** `?=` | 只有这一条陈述 |
| 目标带型别宣告 | ❌ `q i64 ?= …` 是解析错误（`yh8904fm`） | ✅ `q i64 = …: { … }` |
| 右值是常量折叠 | ❌ `s8gh6opt`（`4 / 2` 折成 plain，不再是 option） | ✅ 主语仍归一化成 `?T` |
| 可用前提 | 函式有 `?T` 结果参数，或本身在块 match 内（否则 `l86f91me`） | 无 |
| 成功时臂 | 也会进臂一次（主体走完匹配到 `nil`），臂里只该放丢弃或纯处理 | 只有 `ok` 臂跑 |

选择顺序：

1. **单条陈述、失败就当 0、后面没有要跑的** → 两者等价，优先 B：少一层缩排、少一次零值
   store，`no fmt` 对两种形态都幂等往返。
2. **一串 fallible 陈述要共用一套错误处理**（读档 → 解析 → 写回）→ A：`?=` 一行一条，
   共用同一个 `err ->` 臂，第一个失败就停在清理臂。
3. **失败要保留原值／换成具体兜底值／让后续陈述照常跑** → B（`-> sum`、`-> 0`、`-> it`）。
4. **这个值还要参与运算**（赋值右侧、栏位目标、`?=` 右侧）→ B：A 是陈述，没有值。
5. **逐元素做、单笔失败不该毁掉整批** → B；**整批一起失败就中止** → A（连回圈迭代都停）。

两条容易踩的：

- 🔴 **注解位置**：`#{overflow=wrap}` 必须写在**块内**、紧贴 `?=` 那一行上方。写在块
  match 外侧（`{` 之上）**不会生效**——实测上溢照样回 `err`、`np` 被 `?=` 清零。
- 🔴 **累加器不要照抄 A**：`sum ?= 1 / (i - 1)` 在失败那一轮会把**已累积的 `sum` 一起抹成
  `0`**（`?=` 的零值写入）。要保留累积值就用 B 的 `-> sum`。

; it 隐式绑定

```no
#{fmt-skip}
; it 的作用域：巢状 match 按层还原
; （占位函数名写 keep —— `use` 是导入关键字，不能当函数名；
;   且裸 `->` 臂在 nil/err 未同时认领时读 it 是编译错误，故各层都写 ok ->）
outer: {
    ok -> {
        keep(it)            ; 外层 it
        inner ?T = f(it)
        inner: {
            ok -> keep(it)  ; 内层 it = inner 的解包值
        }
        keep(it)            ; ✅ 内层臂结束后 it 已还原成外层值
    }
}
```

> **注意**：还原只发生在**巢状**的 match。最外层 match 结束后 `it` 仍保留最后一个臂的值，  
> 不要在 match 之外使用 `it`。需要跨层使用时请存到具名变数（`doc = it`），或用析构绑定  
> `ok(v) -> ...` 把载荷绑到自己的名字上。

> **最佳实践（option 解包首选 `it`）**：被匹配值是 **option `?t`** 时，优先写 `ok -> ...(it)...`  
> 而非 `ok(v) -> ...(v)...`——不引入额外绑定名，也就自然避开「不同臂同名变量导致 codegen 串型」的坑。  
> 只有两种情形必须保留**具名绑定** `ok(v) ->`：(1) 被匹配值是**用户自定义枚举变体**（如  
> `res { ok(v str) }`、`shape { rect(w, h) }`）——那里的 `it` 是**整个枚举**而非载荷，取载荷只能具名；  
> (2) 需要在**巢状 match 之后**继续使用该值——内层 match 会重绑 `it`，请用具名绑定或先复制到具名局部。

### 下标写入必须显式解包

索引读取传回值是 option（越界为 `err`，`code.index-out`），**直接给下标赋值会把越界变成未检查的越界写**，因此不允许，必须二选一：

```no
#{fmt-skip}
; ❌ 不允许：a[1] = 2
```
```

```no
; ✅ place-match：自行处理越界臂（it = 元素位置，可读可写）
a[1]: {
    ok -> it = 2

    -> _
}

; ✅ 错误上抛：所在函式有 option 结果参数时（越界 → 上抛）
a[1] ?= 2
```

- 编译器能证明下标不越界时（定长阵列 + 常量下标、回圈变数可证明界内等）**内部消除检查、直接赋值，没有运行开销**；但语法上仍必须写解包形式——用户侧没有任何豁免。
- map（`[str]i64` 等）**完全不受此规则约束**：`m['b'] = c` 直接写即可，不需要 place-match、也不需要 `?=`——map 的下标是**键**而非位置，写入是 put/insert（缺键插入、有键覆盖），恒有定义、不存在「越界写」；结构体栏位基底（`self.keys[i] = v`）暂不受此规则约束。
- map 的**读**侧仍走 option 口径（与阵列/vec/slice 的 `a[i]` 完全同一条规则）：函式内的 `x = m[k]` 得到 `?V`，键不存在时为 `nil`。`m[k]` 与 `m.get(k)` 同义，`m[k] = v` 与 `m.put(k, v)` 同义，两种写法可自由混用。
- `m[k] ?= v` 是**编译错误**（不只是多余）：`?=` 的 ok 臂是「读出元素再写回**位置**」，map 读出的 `?V` 只是 `get` 的副本，写回它不会回到 map。请直接写 `m[k] = v`。`m[k]: { ok -> it = v }` 这种 place-match 写法仍然可用（等价于 put）。

### 迭代变数也是元素「位置」

`x <- a`（`a` 为 `arr` / `vec` / `slice` / 定长阵列）绑定的 `x` 就是**元素本身的位置**，不是每轮载入的副本：

- **读** `x` 会重新读 `a[__i]` —— 同一轮内先写后读能看到新值，`x = x + 1` 就是读-改-写；
- **写** `x = v` 落回 `a[__i]`；
- match 臂里的 `it` 是同一位置的**别名**（仅在该臂内有效），所以 `x: { ok -> it = v }` 与 `a[i]: { ok -> it = v }` 完全等价。

```no
; 以下两段结果相同：a 的每个元素都变成 5
a []i64 = [0, 0, 0]
i <- [0..3): {
    a[i]: {
        ok -> it = 5

        -> _
    }
}

b []i64 = [0, 0, 0]
x <- b: {
    x: {
        ok -> it = 5

        -> _
    }
}
```

- 元素本身是 option（`[]?T`）时，`it` 是**载荷**，写回时自动包回 `ok`。
- 臂结束后别名失效：match 之后再写 `it = v` 不会回到容器。

**不是位置的情况**（写入只留在局部）：

- `c <- s`（`str`）：元素是解码出的**码点**，字串里没有对应的存储格。
- `k <- m`（map）：下标是**键**而非位置，写入不落回表。

### `it` 只能在「可证明是单一情况」的臂里使用

catch-all `->` 臂承接的是前面没有被显式臂认领的所有情况。只有当剩下的情况**恰好一种**  
时 `it` 才有单一明确的意义：

```no
; ✅ -> 就是 ok（nil / err 都已被认领）
v: {
    nil -> log('empty')

    err -> log(it.msg())

    -> process(it)
}

; ✅ -> 就是 err（ok / nil 都已被认领）
v: {
    ok -> process(it)

    nil -> log('empty')

    -> log(it.msg())
}
```

```no
#{fmt-skip}
; ❌ -> 可能是 nil 也可能是 err —— 编译错误
v: {
    ok -> process(it)

    -> log(it)
}
```
```

补上 `nil ->` / `err ->`，或改用 `ok ->`，即可通过。enum 与裸 match（`{ cond -> ... }`）  
不在此限：`it` 指的是被匹配的值本身，没有 nil / err 的可能。

> `err ->` 臂的 `it` **永远是错误值（`err.err`）**，与 option 的元素型别无关——  
> `option { ok(v t), nil, err(e err.err) }`。所以就算匹配的是 `?i64` / `?bool` 这类  
> 纯量 option，`err ->` 臂里的 `it` 也是结构化错误：读讯息用 `msg = it.msg()`，  
> 比对错误码用 `it.is(code.io)`，发生位置在 `it.file` / `it.line` / `it.col`  
> （由编译器在 `err(...)` 的构造点自动注入）。

```no
; ✅ 组合 option 模式：nil || err -> body
; 当 option 为 nil 或 err 时共用同一个分支

    nil || err -> {
        cleanup()
        return
    }

    ok -> process(it)
}

; ✅ 也可与 -> catch-all 混用
val: {
    nil || err -> log('failed')

    ok -> process(it)
}

### 短路管道（`->`）

`->` 是**左结合的短路管道运算符**，语义固定，**不受外层是否赋值、是否在 match 臂内影响**。裸语句、match 臂的单行 body、赋值右侧三处共用同一套 lowering。

管道内的节点分三类：

| 节点                                | 对管道 state 的影响                             |
| --------------------------------- | ----------------------------------------- |
| 副作用呼叫（无回传，如 `print('A')`）         | 执行，**不改变 state**；只要先前是 Ok 就继续下一个节点        |
| 回传 `?T` 的呼叫（可失败，如 `might-fail()`） | 执行，**覆盖 state**；一旦变成 nil/err，**后续节点全部跳过** |
| 末尾普通值表达式                          | 仅在 state 仍为 Ok 时求值                        |

**只有回传 `?T` 的节点有能力把管道切到失败**；`print` 这类副作用永远不会。所以「整条链都是 `print`」看起来像没有短路，其实只是没有节点能产生失败。

```no
; 没有可失败节点 → 全部执行
ok -> print('A') -> print('B')

; might-fail() 回传 ?T → 失败时 print('B') 不执行
ok -> print('A') -> might-fail(x) -> print('B')

; 赋值右侧：同一套语义
r = print('E') -> might-fail(x) -> 42
```

**边界澄清：**

1. `->` 语义唯一，裸语句与赋值表达式共用同一套管道 lowering，不会因为外层有没有赋值而切换模式。
2. match 臂**单行 body 里的 `->` 是管道延续，不是新臂**；臂与臂之间由**换行**分隔：

```no
; ✅ 一个臂，body 是管道 → 两行都印
ok -> print('A') -> print('B')

; ✅ 两个臂（换行分隔）→ 命中 ok 就不会印 'miss'
v: {
    ok -> print('hit')

    -> print('miss')
}
```

> ⚠️ 臂是以换行分隔的，所以写在同一行的 `pat -> A -> B` 是**一个臂的管道**，不是「if A else B」。需要 if/else 时请把臂分行写，或用 `{}` 包裹的短路组。

1. **管道可以产值**：写在赋值右侧时，管道的结果就是**末尾的值节点**（仅在 state 仍为 Ok 时求值）。

```no
n = 7
x = 1 > 2 -> 42; 条件不成立 → x 保持原值 7
y = 2 > 1 -> 42; y == 42
s str = 'old'
s = 1 > 2 -> 'new'; 短路 → s 仍是 'old'
r = print('E') -> might-fail(bad) -> 99; 中段失败 → r 保持原值
```

失败（条件不成立或被 `?T` 节点短路）时**赋值不生效**：变数保留它原本的值；若是首次宣告则为该型别的零值。这一点和叙述形式一致 —— `{ 1 > 2 -> x = 42 }` 同样不会改动 `x`。

值的型别由臂的末尾表达式推断（`str` / `i64` / `?T` 皆可），与 `x = subject: { arms }` 这既有的 match 取值形式共用同一套推断。

### If / Else

if-else 组（短路）**必须**用 `{}` 包裹。第一个匹配的条件胜出，后续条件不再检查。

```no
; 多分支（推荐新式）— 短路 if-else 链
{
    a == 1 -> {
        a = 1
        b = 2
    }

    a == 2 || a == 3 -> do-something()

    -> {
        c = 0
    }
}

; 单 if（保留）— 独立 if，不短路
x == 1 -> do-something()

; 三元表达式 condition ? true-value : false-value
c = flag ? 1 : 2
max = sum > 10 ? sum : 10
```

**重要规则：**

1. **短路组** — 多个 `cond -> body` 用 `{}` 包裹时，形成 if-elif-else 链，只有第一个匹配的分支执行。
2. **独立 if** — 在函数体/循环体中直接写 `cond -> body`（不包裹 `{}`）是独立 if，不会与相邻的 if-then 短路。
   **一旦出现 else 就必须成组** — 换行的 `->` 兜底臂写在 `{}` 外面是**编译错误**：孤立 `cond ->` 配 `->` 报 `k3r7mbqd`，它上面还有兄弟 `cond ->` 臂时报 `m7vq3xrt`（讯息会点明被丢掉的臂数）。解析器只把换行的 `->` 折叠到**最近的一条**裸 if，其余臂静默失效——字面读起来的意思与实际编译出的结果完全不同，所以定为规则而非警告。请把所有臂包进 `{ ... }`；**不带 else 的孤立 `cond -> body` 仍允许裸写**。
3. **禁止混杂** — `{}` 短路组内的直接子节点必须全部是 `cond -> body` 分支，不能混入普通语句。

```no
#{fmt-skip}
; ❌ 不会短路 — 这些是独立 if，所有条件都会被检查
git-dispatch = (cmd str) {
    cmd == 'a' -> {
        fa()
    }
    cmd == 'b' -> {
        fb()
    }
}
```
```

```no
; ✅ 短路 — 用 {} 包裹，第一个匹配胜出
git-dispatch = (cmd str) {
    {
        cmd == 'a' -> {
            fa()
        }

        cmd == 'b' -> {
            fb()
        }

        true -> {
        }
    }
}
```

```no
#{fmt-skip}
; ❌ if/else 写在短路组外面 — 编译错误
; 换行的 `-> break` 只挂在 `c == 43` 上，命中 `c == 45` 之后仍会被 break 掐断
;   c == 45 -> {
;       exp-sign = -1
;       i = i + 1
;   }
;   c == 43 -> i = i + 1
;   -> break
```
```

```no
; ✅ 同一份代码写成 if 组 — 臂间互斥，`->` 才是真正的兜底臂

        exp-sign = -1
        i = i + 1
    }

    c == 43 -> i = i + 1

    -> break
}
```

```no
#{fmt-skip}

### 异步编程：`awy { ... }` 协程组 + `co`

Nolang 只有一种表面并发语法：`awy { ... }` 协程组，组内用 `co` 衍生任务。
`run` 关键字已移除（`run` 现在是普通识别符）；`awy <handle>` 等待前缀与语句位置裸块
协程组都已废除。**组外写 `co` 是编译错误**（`E_CO_OUTSIDE_GROUP`）。

`co` 有两种形态，两者都只启动**过程**，都不产生值：

```no
; 过程：只写通道，没有宣告回传值
produce = (ch chan[i64], v i64) {
    ch <- v
    ch.close()
}

ch chan[i64] = with-cap(2)
awy {
    co produce(ch, 1)          ; ① 过程 spawn：co f(args)
    co {                       ; ② 闭包 spawn：co { ... }
        ch <- 2
        ch.close()
    }
}
sum = 0
i <- ch: {
    sum = sum + i
}
print(sum.to-str())            ; => 3
```

#### ① 过程 spawn：`co f(args)`

`f` **不得宣告回传值**。spawn 的结果没有去处（`co` 不是值），所以带回传值的函式
被 `co` 呼叫时报 `c0retval`：

```no
worker = (n i64) (r i64) { r = n }   ; 有宣告回传值
awy { co worker(1) }                  ; ✗ c0retval
```

方法隐式返回的 `self` **不算**回传值——它是每个方法都带的接收者出参，存在的目的是
让呼叫能串起来，所以 `co obj.flush()` 这种写法完全正常：

```no
queue {
    n i64
}
queue.flush = () {          ; 隐式 (self queue)，没有其它回传值
    self.n = 0
}
awy { co q.flush() }        ; ✓
```

需要结果就写通道：过程把值发进通道再 `close()`，呼叫方在组外排空。这不是风格建议
而是一条规则——被 spawn 的呼叫，其结果只有在组被 join 之后才可读，而读的地方不在
join 点上；这正是 `chan` 存在的场景。

#### ② 闭包 spawn：`co { ... }`

`co { ... }` 把一段过程就地交给协程执行。区块里的**自由变数按值捕获**
（spawn 当刻的快照，与普通 spawn 的实参深拷贝同一个语义）：

```no
seed = 33
ch chan[i64] = with-cap(1)
awy {
    co {
        ch <- seed
        ch.close()
    }
}
r = 0
<- ch: { ok -> r = it }
print(r.to-str())          ; => 33
```

#### `co` 不是值：只能独立成句

`co` 产生 void，所以它必须占满一个语句。赋值右侧、实参位置、返回值位置一律
`E_CO_NOT_STATEMENT`（`c0nostmt`）：

```no
r = co produce(ch, 1)      ; ✗ c0nostmt
print(co produce(ch, 1))   ; ✗ c0nostmt
```

此外 `co` 后面只能是「呼叫」或「区块」，其它形态报 `E_CO_NOT_CALL`（`c0notcal`）。

#### 无色 async：自动单态化

`co` 是无色（colorless）语法：你写未染色的函式名 `produce`，编译器自动单态化出
`produce-async` 变体并在底层以染色无栈协程执行。不要在应用码手写 `-async` 后缀。

规则：

- **单态化**：`co produce(ch, 1)` 会自动生成 `produce-async`（复制 `produce` 的本体、改名）。若 `produce` 同时也被同步呼叫，两者共存。
- **传递性**：若某过程内部也有 `awy { co child(n) }`，该过程本身也会被单态为 `-async`，异步染色沿呼叫链向上传递。
- **屏障**：组内不是 `co` 的语句（普通赋值、`print`、回圈、`if`、**读通道**…）会先等待所有在飞行的任务。组内的资料依赖因此写成「先读通道、再拿读到的值去 spawn」——读通道本身就是屏障，比隐式的变数依赖更好读。
- **函数体不是协程组**：只有 `awy { ... }` 引入组。函数体、`if` 分支、回圈体内的 `co` 一律拒绝。
- **丢弃结果也要等待**：`awy { co side(5) }` 仍会 spawn + await，不留下未等待的任务。

#### 调度模型：真挂起

`-async` 克隆不是「一口气跑完再回报」，而是一台**可恢复的状态机**：局部变数搬进
挂在 `%task.frame` 上的堆帧，每个挂起点变成本块的终结符（把状态号写进帧就返回），
函式入口改成一条状态比较链（`__state == k` ⇒ 直接跳到第 k 个恢复点）。

因此三个地方会**挂起**而不是阻塞：

| 挂起点 | 恢复条件 |
|---|---|
| `async-yield()` | 把自己重新入队到队尾，等排到队头 |
| `awy` 一个尚未完成的子任务 | 子任务完成时唤醒（登记在 `%task.waiters` 链上，一次唤醒全链） |
| 空的通道接收（`v <- ch:` / `<- ch:`） | `send` / `close` 摘下整条等待链并逐个重新入队 |

调度是单线程协作式、就绪队列 FIFO，所以**顺序完全可断言**，不需要 sleep：
两个任务各让出一次必得 `a1 b1 a2 b2`（`tests/coro-yield.no` 把事件码钉住）。
被唤醒的等待者**不等于拿到值**——一次 `send` 只加一个元素，却可能唤醒多个等待者，
所以通道的恢复点是 park 块本身，它会重跑可读性判断再决定取还是继续等。

> 死锁是可侦测的：就绪队列空而目标任务仍未完成 ⇒ 执行期印
> `nolang: deadlock: …` 到 stderr 并 abort。这比「回一个没人送过的零值」诚实得多。

> **底层 lowering**（不是使用者语法）：每条 `co` 变成 `OpRun`，组尾为各任务插入 `OpAwait`；
> `KRun` / `KAwait` / `OpRun` / `OpAwait` 只存在于 HIR/MIR。协程变换由 MIR 的
> `PlanCoroutines` 在 `Analyze` 之后完成（`src/mir/coro.go`）。

取消：`cancelled()` 可在协程函式内作协作式自我检查；`cancel(h)` 是底层句柄操作，
新语法不暴露 task 句柄，应用码不使用。

## 运算符重载

当左操作数的静态型别定义了特定的 `_op` 方法时，编译器会在 lowering 阶段把中缀运算 `a op b` 自动改写为方法呼叫 `a._op(b)`。重载集合是封闭的 5 个对称二元算术运算符：

| 运算符 | 重载方法 |
|--------|----------|
| `+` | `_add` |
| `-` | `_sub` |
| `*` | `_mul` |
| `/` | `_div` |
| `%` | `_mod` |

```no
big {
    v i64
}

; 回传型别书写 ?big，编译器视作纯 payload big
big._add = (b big) (c ?big) {
    c = big {
        v: .v + b.v
    }
}

f = (a big, b big) (out big) {
    r big = a + b; 编译器改写为 a._add(b)
    out = r
}
```

**型别约定**：运算符重载方法的结果参数**书写为 `?T`，生效型别是纯 payload `T`** —— 编译器不做 option 包装／拆包，方法体内直接对 `c` 赋 `T` 值，呼叫端拿到的也是 `T`。除零等错误与内建数值类型一样在运行期直接 trap，不产生 option。

**语义要点**：

- 仅当左操作数的静态型别定义了对应 `_op` 方法时才改写；内建数值类型（i64、f64 等）仍走内建算术。
- 显式方法呼叫 `a._add(b)` 与 `a + b` 完全等价。
- 左嵌套链式运算逐层改写：`a + b + c` → `(a._add(b))._add(c)`；中间结果型别仍是 `T`，可继续参与运算或方法呼叫。
- 标准库 `bigint` 即以此机制支持 `+ - * / %`（见「标准库 > 其他模组」的 bigint 小节）。

## 数组与切片

容器存储数据副本，原变量与容器独立，杜绝悬垂引用。

**定长数组arr：**

```no
; 使用定长数组
a [3] = [1, 2, 3]; 长度为 3 的定长数组 i64
a [3]u16 = [1, 2, 3]; 指定类型的定长数组

a[nil]
u16 = [1, 2, 3]; 自动推断长度（指定类型）
a[nil] = [1, 2, 3]; 自动推断长度（i64）
```

**变长数组vec：**

```no
v = [1, 2, 3]; 变长数组 i64
bs = [0x11, 0x22, 0x33]
v []u8 = [1, 2, 3]; 指定类型的变长数组

; 预分配（避免反复扩容）
v = with-cap(100); len=0, cap=100（需 push 后索引）
v = with-len(100); len=100, cap=100（可直接索引）
v = with-cap-len(200, 100); len=100, cap=200（预留扩容空间）
```

**切片slice（视图，非独立类型）：**

切片是对原始资料的**视图（view）**，不会复制资料，也不会产生新的独立类型。  
切片内部只记录一个指向原始缓冲区的指标、长度和容量，因此：

- 通过切片修改元素会影响原始资料，反之亦然
- 切片不拥有资料，原始变数释放后切片即失效
- 切片的类型由原始类型决定，方法自然适用，无需「继承」机制

```no
; 支持arr/vec/str
; 支持范围 和for <- 的表示一致
nums [5]u8 = [0, 1, 2, 3, 4]

nums[..]; [0 1 2 3 4]   完全无界，等同整个切片
nums[1..]; [1 2 3 4]     无上限，从索引 1 到末尾
nums[..4]; [0 1 2 3 4]   无下限，从开头到索引 4
nums[2..3]; [2 3]        有界，两端都包含
nums[1..3]; [1 2 3]      有界，两端都包含
nums[1..3); [1 2]        左闭右开
nums(1..3); [2]          两端开区间

; 字符串（切片结果型别为 str 视图，共享底层记忆体；下标为码点位置，与 s[i] 一致）
s = 'abc'
s[1..]; 'bc'
s[1..s.len()); 'bc'
b str = s[0..1]; 切片结果已是 str，可直接赋值给 str 变数
```

> 切片语法支援与 match/range-for 相同的 16 种区间组合。在切片上下文中，无界区间基于切片的长度：`[..]` 表示整个切片，`[a..]` 表示从索引 a 到末尾，`[..b]` 表示从开头到索引 b。

**切片的类型与方法：**

切片不生成新的独立类型，只是原始类型的一个视图（调整了起始指标和长度）。  
因此原始类型的方法直接可用：

| 原始类型           | 切片视图类型       | 可用方法                                                                             |
| -------------- | ------------ | -------------------------------------------------------------------------------- |
| `arr` (`[n]t`) | `[]t<range>` | `[]t` 的所有方法（如 `len`、`push`、`pop`、`contains`、`reverse`、`clone`、`fill`、`to-arr` 等） |
| `vec` (`[]t`)  | `[]<range>`  | 同上                                                                               |
| `str`          | `str<range>` | `str` 的所有方法（如 `to-upper`、`to-lower`、`index`、`contains`、`slice`、`copy`、`fill` 等）  |

```no
; arr 切片 → vec 视图，共享 arr 的底层记忆体
a [5]u8 = [0, 1, 2, 3, 4]
s = a[1..4]; s 是 []u8 视图，指向 a 的记忆体
n = s.len(); slice.len()

; vec 切片 → vec 视图，共享 vec 的底层记忆体
v = [10, 20, 30, 40, 50]
s = v[2..]; s 是 []i64 视图
s.reverse(s.len()); slice.reverse

; str 切片 → str 视图，共享 str 的底层记忆体
s = 'Hello World'
sub = s[6..]; sub 是 'World' 视图
upper = sub.to-upper(); str.to-upper

; 通过切片修改元素会影响原始资料
data = [10, 20, 30, 40, 50]
view = data[1..4]; view = [20, 30, 40]
view[0] = 99; 修改 view 的元素
; data[1] 现在也是 99，因为 view 共享 data 的记忆体
```

### 索引

```no
; 字符串索引 → 回传 ?char（Unicode 码点，不是字节）
c char = s[i]; 显式 plain 型别把结果拉回 char（见〈安全索引〉）

; arr、vec获取元素
arr[i]; → ?elem
vec[i]; → ?elem

; map 获取 value
map[str]
```

> **索引读取的结果恒为 `?T`**：`arr[i]` / `vec[i]` / 定长阵列 / `slice` → `?elem`，  
> `str` / `txt` 索引 `s[i]` → `?char`（D6，与整数算术同一套统一规则）。  
> 因此 `str[i]` 的**推断型别是 `?char`**；要拿回 plain `char` 有两条路：  
> 在绑定上写显式 plain 型别（`c char = s[i]`，lower 期即短路合成，读回 plain 值），  
> 或用 match / `?=` 解包。  
> `str[a..b]` 切片仍回传 `str`（码点语义视图，共享底层记忆体）。  
> `char` 可**隐式转换为 `str`**（编码为单字元字串），因此下列写法皆合法，无需手动呼叫 `char.to-str()`：

```no
s = 'héllo'
c char = s[1]; 'é'（char，其码点为 233）
a str = s[1]; 'é'（char → str 隐式转换）
b str = s[0..1]; 'hé'（切片结果本身已是 str）
msg = 'first: ' - s[0]; char 参与拼接（-）时隐式转为 str
ok = s[0] == 'h'; char 与 str 比较时隐式转为 str
```

### 安全索引（Safe Indexing）

对 `arr` / `vec` / `slice`（`[]T`）/ 定长阵列 / `str` / `txt` 的索引 `v[i]`，**结果一律是 `?T`**：越界时回传 `err`（`err('index out of range', code.index-out)`，附下标所在的源码位置），在界内回传 `ok(值)`，绝不会 abort（runtime error: index out of bounds）。这与整数 `+ - * / %` 的未标注溢出行为是同一条规则（见〈整数运算溢出〉）。

要把 `?T` 用掉，只有三条路（**`#{index-out=DEF}` 注解已于 D11 废弃并移除**，残留注解是编译错误；
也没有「显式 plain 型别拉回 plain」这条捷径，`v i64 = a[i]` 同样必须显式消费）：

**1. 读取 —— match 解包**

值 match 直接取值，或陈述 match 在 `ok` 臂内指派。`-> _` 是「丢弃」臂，
在值语境下产出**元素型别的零值**（i64→0、str→''、byte→0、容器→空容器）。

```no
; 值 match
x = state[5]: {
    ok -> it

    -> _
}

; 陈述 match
state[5]: {
    ok -> x = it

    -> _
}
```

**2. 写入 —— place-match**

`it` 在 `ok` 臂里是**元素位置**（可读可写），不是值副本。

```no
state[5]: {
    ok -> it = x

    -> _
}
```

> **map 例外：** 写入 `m['k'] = 1` **不需要解包**——map 的下标是键、写入是 put/insert，
> 缺键插入、有键覆盖，恒有定义，没有「越界写」可守卫。但 **map 读取 `m['k']` 仍回传 `?V`，必须解包**。
> `m[k] ?= v` 是**编译错误**（`get` 读出的 `?V` 只是副本，写回它不会回到 map），请直接写 `m[k] = v`。

**3. 简写 `?=` —— 上抛错误**

`x ?= state[5]`（读）、`state[5] ?= x`（写）是上面两种 match 的简写：失败时把整个 option
向上抛。它在**两种情形之一**下合法：

- 所在函式有 `?T` 结果参数 —— 失败时写入结果参数并提前 `return`；
- 陈述位于**陈述层级块 match** `{ ... }: { ... }` 的主体内 —— 由最近的块 match 捕捉，
  主体停止、arms 只跑一次，函式**不需要** `?T` 结果参数。

两者皆非是编译错误。因此「回传值不是 option 也想用简写」的标准兜底就是把函式体包进块 match：

```no
handle = (x i64) {
    {
        y ?= x + 1
        print(1)
    }: {
        err -> _

        -> _
    }
}
```

**巢状读取**：内层 match 会重新绑定 `it`，故内层用具名绑定 `ok(it1) -> it1`。使用者给的精确形状
（值 match 直接写在 place-match 的 `it = ...` 右侧）自 2026-11-06 起**会正确写回容器**：编译器在
lowering 时把该值 match 提升为合成暂存再重绑 `it`，回归见 `tests/match.no` 的
`place-write-value-match` 段。**首选直接写法**：值 match 的结果直接绑到最终要用的那个名字，
不要先塞进一次性暂存再拷一次。

```no
#{fmt-skip}
; ✅ 直接绑定目标变数
at = argt[i]: {
    ok -> it

    -> _
}
s.farg.push(at)

; ❌ 不要为单次使用引入一次性暂存
ixout1 = argt[i]: { ok -> it  -> _ }
at = ixout1
s.farg.push(at)
```

「把值 match 提到臂外的具名暂存、臂内再 `it = ixout1`」**与直接写法并不等价**，不是可自由
互换的排版选择：求值时机不同（提到臂外后，外层 `nil` / `err` / catch-all 也会先读一次）；
`it` 只在臂内有效且指向元素位置，拷回必须留在臂内；具名暂存是新绑定，有自己的 move／
所有权与作用域退出销毁；且巢状时内层必须用具名绑定 `ok(it1) -> it1`，不能照抄臂外的
`ok -> it`。只有确实要在多处复用同一个值时才提升，并用有意义的变数名，不要留 `ixout…`
这类迁移工具生成的占位名。

#### 用 `?=` 与块 match 收掉剩余的一次性暂存

上面说的是「单次使用就直接绑定」。再往前一步：安全索引回传的是 `?T`，**所以当函式的
结果参数本身就是 `?T` 时，连值 match 都不必写，`?=` 一行直接上抛**：

```no
#{fmt-skip}
; ✅ 函式有 ?T 结果参数：无暂存、无 match
at ?= argt[i]
s.farg.push(at)
```

**函式结果不是 option 时**（最常见：无回传值的辅助函式，或只是往容器里写回），用这种
「类似 try」的写法把该陈述包起来：

```no
#{fmt-skip}
handle = (x i64) {
    {
        y ?= x + 1
        print(y)
    }: {
        err -> _

        -> _
    }
    print('continues afterwards')
}
```

⚠️ **这不是新的 `try` 语法，语言里也没有 `try` 关键字。** 它就是一个**陈述层级的块
match**（`{ ... }: { ... }`），主语是三态 `?T`；`?=` 把失败上抛给**最近的**块 match
（详见〈`?=` 错误上抛〉与〈Match 主语的三种形态〉）。失败时块主体剩下的陈述——包括
后续回圈迭代——全部跳过，臂只执行一次，然后**继续执行块之后的程式码**，不是函式
`return`。`err -> _` 丢弃错误，`-> _` 兜底丢弃成功结果；要处理错误可写
`err -> print(it.msg())`。

⚠️ **语意差异要讲清楚**（实测，别凭直觉）：`?=` 失败时**目标照样被写成零值**——`i64` 得
`0`、`str` 得 `''`、`out[1]` 得 `0`。但值位 match 的兜底臂 `-> _` **不写入目标**：目标是
**新宣告**时它本来就零初始化，看起来一致；目标**已有值**时两者分岔（`?=` 归零、`-> _`
保留原值，要归零得写 `-> 0`）。另一处差异是控制流：`?=` 会**跳过块主体中它之后的陈述**
（在 `?T` 函式里是提前 `return`，在块 match 里是直接转到臂）。

所以：**块主体里只有这一条陈述、且失败前的旧值不带语意时**，把兜底臂写成 `-> 0` 就完全
等价（这也正是本仓库批次改写的形态，`ixout…` 暂存多为新宣告）；而主体里 `?=` 后面还有
别的陈述（回圈计数、后续赋值）、或目标旧值有意义时就会分岔，那些站点不能机械替换。完整
取舍表见〈块 match 与值位 match 的取舍〉。

另一个容易踩的点：**成功时臂也会执行一次**，catch-all 收到成功值（`-> print('x')` 会印）。
所以臂里只该放丢弃或纯处理；`err -> _` / `-> _` 这种形态没有副作用。

由此得到清理 `ixout…` 一次性暂存的顺序：

1. 值只在同一处用一次 → 直接绑到最终目标名（见上文）。
2. 函式有 `?T` 结果参数 → `TARGET ?= EXPR`，无需暂存。
3. 否则 → 把该陈述放进块 match 再写 `TARGET ?= EXPR`；place-match 写回
   （`SUBJ: { ok -> it = temp  -> _ }`）也直接缩成 `SUBJ ?= EXPR`。
4. 只有确实要在多处复用同一个值时才保留具名暂存，且用有意义的变数名。

两个边界：`?=` 在既没有 `?T` 结果参数、也不在块 match 主体内时是编译错误
（`l86f91me`）；**带型别宣告的 LHS 不能配 `?=`**（`ai i64 ?= a[i]` 是解析错误
`yh8904fm`，`expected assignment operator`）。需要 `byte → i64` 这类显式提升时，改成带型别宣告的直接值 match：

```no
#{fmt-skip}
ai i64 = a[i]: {
    ok -> it

    -> _
}
```

> **适用范围：** `arr` / `vec` / `slice` / 定长阵列 / `str` / `txt` 一律有效；只有**直接变数基底**
> 的索引（`v[i]`）会被改写为安全形式，`receiver.field[i]` 走原有 bounds-check 路径。
> 比较运算元里的索引读取比的是 payload（`a[i] == 5`），不是整个 `{tag, payload}`。

> ⛔ **硬错误：** 把 `?T` 当普通值用（如 `crc = crc ^ s[i]`、`f(s[i])`、`v i64 = a[i]`）会阻断
> `no build`，编译器提示改用 match 或 `?=`（无 `?T` 结果参数时用块 match 包住）。
> 既有语料已由 `no fmt --fix=index-out` 一次性迁移完毕，该工具随 D11 退役。

> **核心保证：** 越界永不静默崩溃——不是被 match 处理、就是被 `?=` 上抛。

> **比较运算元里的索引读取**同样套用安全索引：`a[i] == 5` 比的是 payload（与 `?T == 5` 同一条规则），
> 不是拿整个 `{tag, payload}` 去比。越界时读出 `err`（`code.index-out`），与任何值比较皆为**假**
> （`a[i] == 0` 与 `a[i] == 5` 都为假），且**不会**读到越界记忆体。
> `s[0] == 'a'` 同理：码点与单字元字串比较时走 `char → str` 隐式转换。

> **巢状下标** `a[i][j]`：**两层都是安全索引**。外层 `a[i]` 先做界检查并判断是否存在，
> 只有存在时才对它取 `[j]`；任一层越界，整个表达式就是 `err`。
> 因此 `a[oob][0] == 'c'` 为假而不会 abort。

> **容器比较** `[]T == []T`（以及 `[N]T == [N]T`）是**结构比较**：先比长度，再逐元素比。
> 元素本身是容器（`[][]i64`）时逐层递回；元素是 `str` 时比**内容**而不是 data 指标。
> 顺序比较（`<` / `<=` / `>` / `>=`）对容器没有定义，只支援 `==` / `!=`。

> **`nil` 只能与 option 比较**：`?T == nil` / `?T != nil` 合法；非 option 的
> `T == nil`（`str`、`[]i64`、`[N]T`、`txt`、`i64`、结构体…）是**编译错误**（`q4nilcmp`）。
> 原因不是洁癖：`str == nil` 恒为 false（拿 `%str-long` 结构体与 0 比），
> `[]i64 == nil` 会掉进整数比较路径产生非法 LLVM（`icmp eq i64 %vec, i64`），
> 两者都在静默给错答案。要表达「可能没有值」，把型别宣告成 `?T` 再与 `nil` 比。

## 结构体

结构体定义和字面量都必须使用多行形式，每个字段独占一行，字段之间不以逗号分隔，末尾也不跟逗号。

```no
user {
    name str
    age i64

u = user {
    name: 'Alice'

u.age = 25
print(u.name)
```

```

## 方法

方法定义在类型上，使用 `.` 引用接收者（receiver）。

### 语法

```no
#{fmt-skip}
type.method-name = (params) (results) {
    ; . 是接收者
}
```

### 规则

1. 方法名使用 `type.method` 格式，type 必须是已定义的类型
2. 接收者不需要显式声明参数，在方法体内用 `.` 引用
3. 调用时使用 `receiver.method(args)` 语法
4. 返回值放在第二组括号中，与普通函数一致
5. **语法糖脱糖**：`type.method = (inputs) (rest-outputs...) {}` 等价于普通函数  
   `method = (inputs) (self type, rest-outputs...) {}`。调用 `instance.method(args)`  
   时，instance 绑定到输出列表第一个参数 `self`；函数体内 `.` 指代输出区 `self`；  
   函数对 `self` 的写入直接修改原实例。输出列表除 `self` 以外的其余输出，  
   支持可选解构接收或直接丢弃。

### 示例

```no
; str 方法
str.to-upper = () (out str) {
    n = .len-bytes()
    b []byte = with-cap-len(n, n)
    i <- [0..n): {
        c ?byte = .byte(i)
        v = c: {
            ok -> it

            nil -> 0

            err -> 0
        }
        {
            v >= 97 && v <= 122 -> b[i] = v - 32

            -> b[i] = v
        }
    }
    out = b.to-bytes-str()
}

; char 方法
char.is-digit = () (result bool) {
    result = false
    . >= 48 && . <= 57 -> result = true
}

; struct 方法
user {
    name str
    age i64
}

user.greet = () {
    print('Hello, ' - .name)
}

; 调用
s = 'hello'
u = s.to-upper(); receiver.method()
c char = 5
d = c.is-digit(); receiver.method()
u = user {
    name: 'Alice'
    age: 30
}
u.greet()
```

## 接口

```no
; 定义接口
json {
    to-json()
}

; 接口默认实现
json.to-json = () {
}

noml {
    to-noml()
}

serialize {
    json
    noml
}

serialize = json | noml
serialize = json & noml

; 接口实现
user json {
    name str
    age i64
}

; 重写 + 调用父实现
user.to-json = () {

    ; 父实现
    ..to-json()
}

user.other = () {

    ; 当前实现
    .to-json()

    ; 父实现
    ..to-json()
}
```

### 接口合并

接口可以「合并」其他接口的方法：父接口名写在接口体内，**每行一个**（可带模组前缀），不加逗号、不加括号：

```no
json {
    to-json()
}
noml {
    to-noml()
}

serialize {
    json
    noml
}

; 传递合并：roundtrip 同时获得 serialize、json、noml 的全部方法
roundtrip {
    serialize
    roundtrip-json()
}
```

规则：

- **递回合并**：合并是传递的——`roundtrip` 合并 `serialize`，而 `serialize` 又合并 `json` / `noml`，则 `roundtrip` 拥有全部三个接口的方法。
- **每行一个，不能加逗号**：`serialize { json, noml }` 与 C 风格枚举（`color { red, green }`）同形，因此仍按枚举解析，不是接口合并。
- **同名方法**：签名相同（参数与回传型别一致，接收者名可不同）⇒ 去重保留一个；签名不同 ⇒ 诊断报错。
- **实现端**：型别只需写实作声明（前置清单 `user serialize { name str }`），父接口的方法一并算作已实现，签名校验会穿透父接口。
- **`no fmt`**：旧的「前置清单」写法（`serialize json, noml { }`）仍可解析，但 `no fmt` 会改写成体内形式，`no vet` 对此给出 WARNING 提示。

诊断（`no vet` 与编辑器诊断同源，TraceID `ifmrg001`）：

| 情况 | 讯息 |
| --- | --- |
| 父接口未宣告 | `interface 'serialize': unknown parent interface 'noml'` |
| 循环合并 | `interface 'a': merge cycle a -> b -> a` |
| 同名异签名 | `interface 'serialize': merged method 'to-str' has conflicting signatures ('json.to-str', 'noml.to-str')` |

> `serialize = json \| noml` 这类写法是**联合型别**（union type）语法，与接口合并无关；接口合并只影响「型别必须具备哪些方法」。

### 标签列举（带载荷）

变体可携带具名载荷栏位，写成括号形式 `变体(栏位 型别)`；无载荷的变体直接写裸名。  
一个变体可带**多个**栏位（多栏位载荷在堆上以合成 struct 表示）：

```no
#{fmt-skip}
; 标签列举：变体可带载荷，tag 依声明顺序为 0,1,2...
result {
    ok(v t),
    nil,
    err(e str),
}

; 有值：载荷栏位 v，型别 t
; 空值：无载荷
; 错误：载荷栏位 e，型别 str（用户自定义枚举，与内建 option 无关）

shape {
    circle(r f64),
    rect(w f64, h f64),
    dot,
}
; 单栏位
; 多栏位
; 无载荷
```
```

匹配时用变体名作为臂模式；带载荷的变体可析构绑定载荷（多栏位按位置一一绑定）：

```no
r result = ok(42)
r: {
    ok(v) -> print(v); 把 ok 的载荷绑定到 v

    nil -> print('empty')

    err(e) -> print(e)
}

s shape = rect(3.0, 4.0)
s: {
    circle(r) -> print(r); 绑定单栏位

    rect(w, h) -> print(w * h); 按位置绑定多栏位

    dot -> print('dot')
}
```

变体可在**表达式位置**直接建构，作为函数引数或其它变体的载荷：

```no
x f64 = perimeter(rect(3.0, 4.0)); 内联建构并传参
o outer = wrap(a(5)); 枚举载荷本身是另一个枚举
```

> **命名空间与裸名解析**：编译器内部以「完整限定名」登记变体（`模组.枚举.变体`，  
> 如 `option.option.ok`、`some-mod.my-result.ok`），不同枚举的同名变体互不冲突。  
> 使用者只写裸名（`ok`、`rect`），由编译器**依被匹配/被建构变数的静态型别**自动补全  
> 完整命名。因此两个枚举即使都有 `ok` 变体、且 tag 顺序不同，也能正确区分。
>
> 也可写旧式空格分隔型别 `ok t`，等价于 `ok(v t)`（省略栏位名）。  
> 标签列举的变体名称会登记进编译器的列举变体表，供匹配与穷尽性检查使用。

### 内建标签列举（`#{buildin}`）

在标签列举前加 `#{buildin}` 表示这是**内建列举**：变体（名称、顺序、载荷型别）供  
匹配与穷尽性检查使用，但底层表示与构造由 runtime/builtin 提供，**不生成使用者可见的  
struct/union**。`?t` option 即以此方式声明：

```no
; src/std/global.no
#{buildin}
option {
    ok(v t),
    nil,
    err(e err.err),
}
```

`option` 的 tag 依序为 `0=ok`、`1=nil`、`2=err`，与内建 option 表示一致。使用者无需  
自行声明 option；此处的 `#{buildin}` 让内建 option 的变体来源单一化（见「可空类型(option)」）。

### 枚举注解与内存布局

枚举支援 `#{...}` 注解，位置与其他目标相同（见〈注解位置〉）：**上方**（独立成行）或  
**后方**（同一行尾随）；写在目标**前方同一行**是编译错误。

注解可放在**两处**：

1. **整个 enum 的上方** —— 作用于 enum 定义本身（如 `#{buildin}`、`#{inline=true}`）；
2. **单个成员的上方或同行尾随** —— 作用于该成员（C 风格枚举的「值」与标签列举的「变体」皆可）。

```no
; ① 整个 enum：独立成行置于 enum 上方
#{inline=true}
box {
    full(v i64) #{doc='有值'},
    empty #{doc='空值'},
}

; ② 单个变体：独立成行置于变体上方

; ② 单个变体：同一行尾随

; `#{inline=false}`：明确写出「不用 inline 布局」
#{inline=false}
plain {
    a,
    b,
}

color {
    red #{deprecated},
    green #{deprecated},
    blue,
}
; C 风格枚举的单个值同样支援这两种写法
```

**注解不改变 enum 的结构**：变体名称、宣告顺序（tag）、载荷栏位与型别都不受注解影响，  
匹配与穷尽性检查也完全不变。注解只是附加在定义上的**元数据**。

#### 内存布局（栈式）

标签列举在记忆体中采**栈式布局**（inline stack form）——一个按值存放的小物件，载荷不散落在堆上：

```llvm
%tenum_<name> = type { iN tag, [K x i64] payload }   ; 一般情形
%tenum_<name> = type { iN tag }                      ; 所有变体皆无载荷
```

- `tag` 的宽度随**变体个数**变化，且是完整的 `u8/u16/u32/u64`：
  `<= 256` → `i8`、`<= 65536` → `i16`、`< 2^32` → `i32`、否则 `i64`。判别值依宣告顺序取 `0, 1, 2...`。
- `payload` 是**所有变体共用**的 union（每个变体把自己的栏位写进同一块储存）；`K` 是**最宽变体**
  所需的 8 位元组字数，**不是所有变体相加**，最小为 1。
- 变体内部按**自然对齐**摆放栏位，所以栏位偏移不一定是 8 的倍数（`(a char, b char, c char)`
  的偏移是 0 / 4 / 8）。读写一律按**位元组偏移**寻址（`bitcast` 到 `i8*` 再 `getelementptr`），
  因此「写进去的偏移」与「读出来的偏移」由同一份布局表决定。

大小是 `8 + 8K`（`tag` 被阵列的 8 位元组对齐填充到整字），只有无载荷的列举是纯标签大小：

| 情形 | `K` | 大小 |
| ---------------------------------------------- | ----------------- | ---------- |
| 所有变体皆无载荷 | —（无 payload 栏位） | **1 位元组**（`{ i8 }`；变体 > 256 时为 2 / 4 / 8） |
| 最宽变体为 `i64` / `i32` / `f64` / 指标 | 1 | 16 位元组 |
| 最宽变体为 `char`（4 位元组）/ `bool`（1 位元组） | 1 | 16 位元组 |
| 最宽变体为 `(a char, b char, c char)`（12 位元组） | 2 | 24 位元组 |
| 最宽变体为 `str` / `vec` / `[]T`（16 位元组描述符） | 2 | 24 位元组 |
| 最宽变体为结构体 `T` | `ceil(sizeof(T) / 8)` | `8 + 8K` |

也就是说：**默认就是 16 位元组起**，只有当某个变体的载荷确实更宽时才会长大——
「默认固定 16 位元组」与「大小随变体变化」是同一件事的两面。`char` / `bool` 这类小载荷
只决定对齐，不会把 union 撑大：`payload` 的宽度是「最宽的那一个变体」，不是全部相加。

> 布局的唯一来源是 `src/mir/layout.go`：`tagWidth` 决定 `iN`，`enumVariantLayout` 决定每个
> 变体的栏位偏移与自身大小，`enumUnionLayout` 取最大值得到 `K`。`hir2mir.fillEnumLayout`
> 在建表时就把这些数字记进 `TaggedEnumInfo`，emitter 只读不算——两边不可能算出不同答案。

#### `#{inline}` 的三种写法

`inline` 是一个**布尔**注解，有三种写法，且**值会被真正遵循**：

| 写法                | 含义                          |
| ----------------- | --------------------------- |
| `#{inline}`       | 简写，等于 `inline=true`（独立键即为真） |
| `#{inline=true}`  | 明确为真（`#{inline=1}` 亦可）      |
| `#{inline=false}` | 明确为假（`#{inline=0}` 亦可）      |

非布尔值是**编译错误**（`#{inline=foo}`、`#{inline='true'}`），不会被静默当成真：  
`ValidateFieldTags`（TraceID `fieldtag1`）对结构体栏位与 enum 定义都会报。

在整个 enum 上方写 `#{inline=true}` 是栈式布局的**显式标记**，表示「此枚举使用栈式布局」；  
编译器把它记在 `TaggedEnumInfo.Inline` 上。**目前的默认布局本来就是栈式**，所以加不加  
注解、写 `true` 还是 `false`，布局完全相同——标记的作用是让意图明确，并在日后若变更默认  
布局时作为稳定的选择开关。

> `#{inline}` 写在**整个 enum 上方**表示「这个枚举用栈式布局」；写在**单个变体**上目前  
> 不改变布局，仅保留为该变体的元数据（与结构体栏位不同，见下节）。

#### 结构体栏位上的 `#{inline}`

与 enum 不同，**结构体栏位**上的 `#{inline}` 是**有实际效果**的：它直接决定该栏位是  
**按值内联**在宿主结构体内（`%pt`），还是存成**指标**（`ptr`）。

```no
pt {
    x i64
    y i64
}

holder {
    inl pt #{inline=true}; 按值：结构体直接长在 holder 里
    out pt #{inline=false}; 指标：栏位存的是指向 pt 的指标
    bare pt #{inline}; 简写，等于 inline=true
}
```

| 写法                                             | 栏位布局                        |
| ---------------------------------------------- | --------------------------- |
| `#{inline}` / `#{inline=true}` / `#{inline=1}` | **按值**内联在宿主内（`%pt`）         |
| `#{inline=false}` / `#{inline=0}`              | **指标**（`ptr`）               |
| 不写                                             | 取决于 `NOLANG_FIELD_PTR`（见下表） |
| `#{inline=foo}` / `#{inline='true'}`           | **编译错误**——不是布尔              |

**没有注解时的默认布局由 `NOLANG_FIELD_PTR` 决定。** `mir.FieldPtrLayout` 等于  
`os.Getenv("NOLANG_FIELD_PTR") != ""`，**默认为关**；开启它会启动「Phase 1 布局翻转」，  
把结构体栏位的默认由按值改成指标。

| 栏位                             | 旗标关（默认）   | 旗标开（`NOLANG_FIELD_PTR=1`） |
| ------------------------------ | --------- | ------------------------- |
| 无注解                            | `%pt`（按值） | `ptr`（指标）                 |
| `#{inline}` / `#{inline=true}` | `%pt`     | `%pt`                     |
| `#{inline=false}`              | `ptr`     | `ptr`                     |

也就是说：**注解永远生效，不受该环境变数影响**，旗标只改「没写注解时」的默认。因此在  
默认配置下，`#{inline=false}` 是「主动要求指标」，而 `#{inline=true}` 只是把本来就如此  
的布局再写明一次；一旦翻转开启，两者的角色就反过来。

检查器有两条规则（TraceID `fieldtag1`，`ValidateFieldTags`）：

1. **只对结构体型别的栏位有意义。** 标量 / `str` / `vec` / 阵列 / 切片 / map / option /  
   指标栏位本来就一律按值存放，写 `#{inline}` 等于什么都没说，因此报错；写  
   `#{inline=false}` 同样报错，因为那等于宣称了与编译器行为相反的布局。
2. **按值内联不得成环。** 被内联的结构体存放在宿主**内部**，所以  
   `a { #{inline} b b }` 与 `b { #{inline} a a }` 并存时大小无限，必须报错（直接自我  
   引用是退化情形）。只有 `=true` 才会建立按值边，所以互相递回的结构体在**两侧都写  
   `#{inline=false}`** 时合法。
   > ⚠️ **「不写注解」不等于「不用 inline」。** 默认配置下不写注解就是按值内联，因此  
   > `a { x b }` 配 `b { y a }`（都不写注解）在**默认配置下并不合法**，会以  
   > `opt: error: identified structure type 'b' is recursive` 失败——而且这条错误目前  
   > **不会**由检查器报出，要到 LLVM 验证阶段才炸。要在默认配置下写递回型别，**必须**  
   > 显式写 `#{inline=false}`。只有 `NOLANG_FIELD_PTR=1` 时，「不写」才等于指标。

#### 递回型别：为什么需要 `inline=false`

一个按值内联自己的结构体大小无限，所以**自我引用**不能按值存放。在默认配置  
（`NOLANG_FIELD_PTR` 关闭）下，结构体栏位预设就是按值，因此 `node` 要能参考自己，  
唯一的写法就是明确要求指标：

```no
node {
    v i64
    next node #{inline=false}; 指标：这样 node 才有有限大小
}

n node
n.v = 1
n.next.v = 2
print(n.next.v); 2
```

若把上面的 `#{inline=false}` 拿掉（或写成 `#{inline=true}`），LLVM 会直接拒绝这个  
型别：`identified structure type 'node' is recursive`。

指标栏位**拥有**它的 pointee，生命周期由编译器处理：

- pointee 在**首次写入时惰性分配**（`@__nolang_get_<T>`，内含 `malloc` + 清零），  
  不是在建构宿主时一次分配；
- 宿主离开作用域时 `@__nolang_drop_<T>` 会**空指标检查后释放**它；
- 按值拷贝（`b = a`、作为参数传递、写入容器）会**深拷贝** pointee，因此两个宿主  
  不会共用同一块记忆体、也不会被释放两次。

端到端测试见 `tests/field-inline-annotation.no`。

### 枚举值引用

**规则：枚举值必须使用 `枚举类型.值` 的限定方式引用，不能直接使用裸值。**  
这样可以防止命名冲突，也使外部包无法直接使用具体值。

```no
#{fmt-skip}
; ❌ 错误：直接使用裸值
kind = null
yes = e.is(io)
```
```

```no
; ✅ 正确：使用限定方式
kind = json-kind.null
yes = e.is(code.io)
```

> 枚举类型可用于结构体字段类型、函数参数类型和返回值类型。  
> 定义枚举的模组内部和外部都应使用 `枚举类型.值` 的方式引用枚举值。

### 可空类型(option)

在类型前面加 `?` 表示可空类型：

可空类型变量可以合法持有空值/错误值，编译器会进行相应的空值检查。

`?t` 是内建标签列举，其变体定义于 `src/std/global.no`：

```no
#{buildin}
option {
    ok(v t),
    nil,
    err(e err.err),
}
; tag 0：有值
; tag 1：空值
; tag 2：错误（std 结构化错误 err.err）
```

`err` 变体的载荷**不是 `str`**，而是 `std/err` 的 `err` 结构体（`code` / `msg` / `file` / `line` / `col`）。
`err('msg', code)` 是 `err.new('msg', code)` 的别名构造器——错误码 `code` 是**必填**参数
（参数默认值已从语言移除），没有具体错误码时明确传 `code.unknown`；
位置栏位由编译器在构造点自动注入。只写一个参数的 `err('msg')` 不是这个别名，
而是 option 的 `err` 变体构造器（见下）。

`#{buildin}` 表示底层表示与构造由内建 runtime 提供（`%option` 型别、`ok(...)`/`nil`/`err(...)`  
构造器），`option` 的列举声明仅用于匹配与穷尽性检查。详见「标签列举」与「内建标签列举」。

#### 内存布局

`?T` **按载荷定型**：每个载荷型别各有一个 LLVM 型别，名字由载荷型别推导（单射映射），
所以「载荷型别相同 ⇒ 布局相同」，`?i32` / `?i64` / `?bool` 共用同一个型别：

```llvm
%option_<key> = type { i8 tag, [K x i64] payload }   ; 内联
%option_<key> = type { i8 tag, [1 x i64] payload }   ; 装箱（payload 存 i8* 指标）
```

- `tag` 恒为 **1 位元组**：`option` 只有 3 个变体（`0=ok`、`1=nil`、`2=err`），落在
  「`<= 256` 个变体 → `i8`」这一档。列举的 tag 宽度规则见〈内存布局（栈式）〉。
- 标签之后是**对齐填充**（1 位元组标签 → 填充 7 位元组），再往后才是载荷。
- 载荷大小 `K` 由 `T` 的实际大小决定并向上取整到 8 的倍数，**不是固定槽**：
  `?i64` 是 16 位元组（8 + 8），`?str` 是 24 位元组（8 + 16），`?txt` 是 264 位元组（8 + 256）。
- 超过门槛的载荷改为**堆装箱**：`payload` 只存一个 8 位元组指标，整个 option 是 16 位元组。

门槛 `option-payload-inline-threshold` 按**整个 option 结构**的位元组数计（预设 **264** = 1 位元组标签 +
7 位元组填充 + 256 位元组载荷，最小 **16**）：载荷内联的条件是
`8 + roundUp8(sizeof(T)) <= 门槛`。因此默认「载荷不超过 256 位元组就内联」，`?txt`
（256 位元组内联缓冲）正好落在边界内。

| `?T` 的 `T` | 内联？ | `%option_<key>` 大小 |
| --- | --- | --- |
| `i64` / `i32` / `bool` / `char` / `f64` / 指标 | 是 | 16 位元组 |
| `str` / `[]T` / `vec`（16 位元组描述符） | 是 | 24 位元组 |
| `txt`（256 位元组内联缓冲） | 是 | 264 位元组（正好到默认上限） |
| 大小 > 256 位元组的结构体 / 阵列 | 否 | 16 位元组（载荷在堆上） |
| 自引用的载荷（`node { next ?node }`） | 否 | 16 位元组（自引用只能靠指标断开） |

> **`err` 的载荷恒装箱**：`err` 变体存的是 `std/err` 的 `err` 结构体指标，不占用上面的
> 载荷预算。所以 `?str` 在 `ok` 时是 24 位元组的内联字串，在 `err` 时也是同一个 24 位元组
> 结构——只是 `payload` 那个 word 存的是错误物件的指标。这条规则让「同一个 `?T` 型别、
> 两个变体、两种载荷」不需要额外空间。

> **内联与装箱只改变「放在哪里」，不改变所有权**：两条路径都在**拷贝**发生时给结构体载荷的
> 堆部分另起一份（指标栏位递归、内联拥有的 `str` / `[]T` 缓冲克隆），所以 `?T` 的值语义与
> 是否内联无关——同一个程式在任意 `option-payload-inline-threshold` 下输出必须完全一致。
> 差一个门槛就换一种行为，那是编译器缺陷，不是特性。（纯移转的赋值不克隆，由 option 接手
> 来源的堆。）

> 布局的唯一来源是 `src/mir/layout.go`：`optLayoutOfPayload` 决定 `K` 与是否装箱，
> `optionPayloadOffset`（8）是载荷的固定位元组偏移。`hir2mir` 折叠模组级 `?T` 常量、
> codegen 发射读写，都问同一个函式。

#### `?=` 的跨载荷上抛

`?=` 会先把「右值链**根**的 option」复制进 option 结果参数，让 `nil` / `err` 直接上抛，
成功路径再由 `ok` 臂覆盖：

```no
pick = (p pool) (out ?i64) {
    out ?= p.nodes[0].kind; 根是 ?node，结果槽是 ?i64
}
```

两侧的载荷型别因此**可以不同**，而这是真正的 ABI 边界（`?node` 112 位元组、`?i64` 16 位元组），
不是同一份布局的两种拼写。跨型别能带过去的只有两样：

- `tag`——每个 option 的第 0 位元组；
- `err`——`err` 变体是 option 的属性、与载荷无关，而且恒装箱，所以两侧在载荷区第 0 个字
  都是 8 位元组的箱指标（箱体会被**复制**，不共享，因为两侧都会 drop）。

`ok` 载荷**不跨型别搬运**：目标的载荷区先清零，成功值一律由 `ok` 臂重新写入。
实作在 `@__nolang_opt_prop_<dst>__<src>`（`src/mir/codegen.go` 的 `optPropagateState`），
只在 `?=` 这种编译器生成的上抛赋值上出现。

```no
o ?i64
o = nil; 设为空
o = 42; 设为有值
o = err('msg'); 设为错误

nullableValue ?[]str
nullableString ?str

; 修改可空类型
nullableString = 'test'

; 设置错误
nullableString = err('some error')

; 可通过match判断
x: {
    err -> log(it.msg()); it 是 err.err，讯息靠 .msg()

    nil -> log('nil')

    -> do-right-thing(it)
}

; 强制解包
; 取消实现
; !x.say()
```

### 风格指引：使用 ?t option 取代 (val, ok)

当函数可能失败或返回空值时，**应优先使用 `?t` option 类型**，而非 `(val t, ok bool)` 双返回值模式。

`?t` 是标签列举，有三种状态：`ok`（有值）、`nil`（空值）、`err`（错误）。正常值会隐性绑定，当操作只是找不到值时用 `nil`，当操作遇到实际错误时用 `err(...)`。

```no
#{fmt-skip}
; ❌ 不推荐：双返回值模式
stack.pop = () (val i64, ok bool) {
    .n == 0 -> return
    val = .data[.n]
    ok = true
}
```
```

```no
; ✅ 推荐：option 类型（nil 表示空，err 表示错误）
stack.pop = () (val ?i64) {
    .n == 0 -> {
        val = nil
        return
    }
    val = .data[.n]
}

; ✅ 返回错误
file.read = () (data ?str) {
    .fd < 0 -> {
        data = err('file not open')
        return
    }

    ; ... 读取资料
    data = buf
}
```

使用 match 解包 option：

```no
val = s.pop()
val: {
    nil -> print('empty')

    err -> print(it.msg()); it = 结构化错误 err.err

    -> print(it); it = 弹出的值
}
```

## 整数运算溢出（`#{overflow}` 注解）

Nolang 不支援 panic——任何可能溢出的操作都必须以 `option` 或显式注解处理，绝不会在执行期抛出整数溢位异常。下列**整数四则运算**的溢出行为由 `#{overflow = ...}` 注解控制：

- 有号与无号的 **`+` `-` `*`**：左右运算元为整数（含 `int` 字面量）时皆适用；
- 有号 **`/`**：仅 `INT_MIN / -1` 这一种情况会溢出（无号除法 `a/b ≤ a` 永不溢出，不适用）。

> 无号整数（`u8`/`u16`/`u32`/`u64`/`u128`）的 `+ - *` 与有号整数**遵循完全相同的规则**：未标注时同样预设回传 `option<int>`，溢出 → `err`。这是设计上的刻意选择——「只要无法在编译期证明不可能溢出，就按相同规则处理」。

### 特例：`byte` 与 `char` 算术

`byte` 与 `char` 是溢出语义的**特例**：它们的算术**不产生 option**、不受 `#{overflow}` 注解管辖。

- **`byte`（u8）**：`+ - *` 溢出时**静默 2's 补数回绕**（`250 + 10` → `4`、`0 - 1` → `255`）。`byte` 面向字节缓冲、hex 编解码等「天然容许回绕」的场景，与哈希／计数器的 `#{overflow = wrap}` 同一语义，只是内建、无需注解。
- **`char`（Unicode 码点）**：`+ -` 是**码点算术**，结果超出合法码点范围（`< 0` 或 `> 0x10FFFF`）时为 **`-1`**（无效码点哨兵）——不会 `err`、也不回绕。

**设计理由**：`i8`–`i128` / `u8`–`u128` 一般用于**真实业务数值**（金额、计数、容量），静默回绕会隐藏溢出 bug，因此默认 `err`、强制显式选择；而 `byte` / `char` 的典型用途（字节流、码点遍历）语义上天然容许（甚至期望）回绕，走 option 徒增解包噪音。若需要检测 `byte` / `char` 运算的溢出，先转宽型别（如 `b.to-i64()`）再计算。

| 模式          | 注解                       | 溢出时                         | 结果型别   | 适用场景               |
| ----------- | ------------------------ | --------------------------- | ------ | ------------------ |
| **默认（未标注）** | —                        | 溢出 → `err`，正常 → `ok(value)` | `?int` | 需要侦测溢出的运算          |
| **回绕**      | `#{overflow = wrap}`     | 静默 2's 补数回绕                 | `?int` | 哈希、密码学、计数器等语义上容许回绕 |
| **归零**      | `#{overflow = clamp0}`   | 溢出（上溢或下溢）取 `0`              | `?int` | 差值不得为负的语义（如剩余量）    |
| **最小值箝位**   | `#{overflow = min}`      | 溢出箝位到型别最小值                  | `?int` | 计数器下限、索引保护         |
| **最大值箝位**   | `#{overflow = max}`      | 溢出箝位到型别最大值                  | `?int` | 容量上限、饱和累加          |
| **饱和**      | `#{overflow = saturate}` | 上溢→最大值、下溢→最小值               | `?int` | 讯号/颜色饱和等           |

> ⚠️ **注解不解包**（D1）：`#{overflow = …}` **只决定「失败时怎么取值」**，
> 结果型别恒为 `?T`。要把结果拉回 plain，只能用 match 或 `?=` 消费；两种消费形态
> （`?=` + 块 match／值位 match）的差异与选型见〈块 match 与值位 match 的取舍〉。
> 显式标注成 plain 型别（`w i64 = a - b  #{overflow=wrap}`）**不是**逃生口 ——
> 实测仍报 `15w45dqk`（cannot assign `?i8` value to `i8` variable）。

此外，所有模式都支援**型别前缀形式**，精确指定某个窄型别的饱和界限，例如 `#{overflow = u8-max}`、`#{overflow = i8-min}`、`#{overflow = u16-saturate}`。

> **注解粒度**：`#{overflow = ...}` 是**行注解**——只作用于**紧接其后的下一条陈述**。
> 这是**设计上唯一允许**的形式（防止滥用）：执行语意（codegen）与 `ovfhndld` 硬错误都只认它，
> 而且它只改「溢出时的取值」、不改型别，放宽到块级或函式级会让整片运算的语义由一行远处
> 注解决定。理由详见 [〈注解与注释的作用域〉](annotation-scope.md) §4.1。
>
> ⛔ **放在函数定义上方、块头或档案头都不合法**。目前唯一的漏洞是：函式级注解会让
> `ovf-int-default` lint 跳过整个函式（清单看起来「干净」），函式体内的未标注运算照旧
> 触发 `ovfhndld`；块级注解则让 lint 向下继承而闭嘴，codegen 一律不认。请逐陈述标注；
> `no fmt --fix=overflow` 产生的正是这种逐陈述形式。
>
> 完整模型（L0 模组 / L1 宣告 / L2 区块 / L3 单行，以及哪些键支援哪几层）见
> [〈注解与注释的作用域〉](annotation-scope.md)；该页 §7 列存量与漏洞，§8 是收紧顺序。

> **LSP 快速修复**：编辑器（nolang-lsp）会对未标注的整数运算报出**提示**（`nolang-overflow`，trace id `ovfhndld`），并提供五个 quickfix——**Add `#{overflow = wrap}`** / **`clamp0`** / **`min`** / **`max`** / **`saturate`**——自动在该运算所在语句上方、以与该行一致的缩排插入对应注解，指定溢出行为（结果仍是 `?T`，需另用 match / `?=` 消费）。命令列等价物为 `no fmt --fix=overflow`（见下文）。

### 默认：返回 `option<int>`

未标注时，`a - b` 的结果型别是 `option<int>`。接收端必须是 `?T`（可空型别），并用 match 解构 `err` / `nil` / `ok` 三个分支：

```nolang
main = () {
    x i64 = 100
    d ?i64 = x - 1; 默认：返回 option<i64>
    d: {
        err -> print(-1); 溢出（如 x - 2^63 下溢）

        nil -> print(0)

        -> print(1); ok(value)：正常结果
    }
}
main()
```

> `%option` 的 `data` 栏为 `i64`；窄型别（`i8`/`i16`/`i32`）的结果会先符号扩展（sext）再存入，解包时再截断回原宽度。

### wrap：静默回绕

```nolang
#{overflow=wrap}
sub-wrap = (a i64, b i64) (r i64) {
    r = a - b; 溢出时静默 2's 补数回绕；r 是 plain i64（显式型别）
}
```

语句级：

```nolang
x i64 = -9223372036854775807

#{overflow=wrap}
w i64 = x - 2; 下溢回绕 → 9223372036854775807
print(w)
```

### clamp0：溢出归零

```nolang
x i64 = -9223372036854775807

#{overflow=clamp0}
c i64 = x - 2; 下溢 → 0（上溢同样归零）
print(c)
```

### min / max / saturate：饱和箝位

三种模式把溢出结果「夹」在型别可表示区间内，而非回绕或归零：

```nolang
#{overflow=min}
floor = (a i64, b i64) (r i64) {
    r = a - b; 下溢 → i64 最小值；上溢 → i64 最大值
}

#{overflow=max}
cap = (a i64, b i64) (r i64) {
    r = a * b; 上溢 → i64 最大值；下溢 → i64 最小值
}

#{overflow=saturate}
sat = (a i64, b i64) (r i64) {
    r = a + b; 上溢→max、下溢→min
}
```

型别前缀形式可精确控制窄型别的饱和界限（函数级注解会套用到体内所有对应型别运算）：

```nolang
#{overflow=max}
inc = (x u8) (r u8) {
    r = x + 1; x = 255 时上溢 → 255（而非回绕成 0）
}

#{overflow=min}
dec = (x i8) (r i8) {
    r = x - 1; x = -128 时下溢 → -128（而非回绕成 127）
}
```

### 编译器强制

未标注的整数运算预设回传 `option<int>`，因此「未处理」会被强制拦下。**是否算未处理采并行判断**——满足下列任一项即不报错：

- **`?=` 上抛**（要求函式有 option 结果参数）；
- **就地捕获**：用 `=` 绑定到一个**新**变数（变数自动推断为 `?T`），或显式宣告 `?T`（如 `x ?i64 = a + b`）；
- **`_ = expr` 显式丢弃**（求值本身走安全路径，错误一并忽略）；
- **加注解** `#{overflow = wrap}` / `clamp0` / `min` / `max` / `saturate`（或型别前缀形式如 `u8-max`、`i8-min`），声明接受回绕／饱和语义。

四者皆无时才报错（`ovfhndld`）。

> **纯算术不是可错源**：`+ - * <<` 与取负本身不触发捕获（否则所有算术都会变成 option，标准库爆炸）。所以 `d = x - 1`（不含 `/` `%`、不含安全索引、不含 option 运算元）仍然报错——请加注解，或写成 `d ?i64 = x - 1`。
>
> **既有变数不改型别**：捕获只对「本陈述首次宣告」的目标生效。若变数已经存在（例如先有 `d = 0` 再 `d = x - 1`，或先有 `v i64 = 0` 再 `v = arr[i]`），编译器不会把它就地改成 option，而是报错要求你显式选择语义。

另有两条硬性错误不受上述豁免影响：

- 未标注的整数运算若赋值给**显式 plain `int`** 变数，编译器报错（`cannot assign ?i64 value to i64 variable`），强制你加 `#{overflow = wrap}` / `#{overflow = clamp0}` / `#{overflow = min}` / `#{overflow = max}` / `#{overflow = saturate}`（或型别前缀形式）或改用具名 `?T`。
- 未标注的整数运算若赋值给**已存在**、且型别非 option 的变数（`d = 0` 之后的 `d = x - 1`），编译器报错并提示加上注解或宣告 `?i64`，避免产生非法 IR。

其余规则：

- 无号整数运算（`u8`/`u16`/`u32`/`u64`/`u128`）**同样适用**此机制：未标注时 `+ - *` 预设回传 `option<int>`，溢出 → `err`，与有号整数规则一致。
- `i128` 运算不支援 `option` 路径（data 栏仅 `i64`），统一退化为静默回绕以保留正确性。

> **为什么默认是 option 而非 wrap？** 静默回绕会隐藏溢出 bug；预设回传 `option` 强制呼叫方显式处理溢出（或主动标注 `wrap` 表明「我接受回绕语义」），把「是否容许溢出」变成可见的设计决策。

### 除零（division by zero）

整数 `/` 与 `%` 的除数为 `0` 是**未定义行为（UB）**，与溢出是**两件独立的事**——没有任何注解能豁免它：

- **编译期可判定**：除数是**字面常数 0**（`10 / 0`、`a % 0`、`x / 0`）⇒ **硬错误**（trace id `div-by-zero`）。`#{overflow = wrap}` 不豁免它（该注解管的是溢出，不是除零）。
- **执行期才知道**：除数来自变数／外部输入 ⇒ 编译器在**两条路径上都插入零检查**，差别只在「怎么报告」：

| 结果型别        | 触发条件                    | 除数为 0 时                                                                        |
| ----------- | ----------------------- | ------------------------------------------------------------------------------ |
| `?int`（预设）  | 陈述未标注                   | option tag = `err`，用 `?=` / match 处理                                           |
| plain `int` | 陈述带 `#{overflow = ...}` | 结果强制为 `0`，并在 **stderr** 印出 `nolang: integer division or remainder by zero ...` |

```nolang
safe = (a i64, b i64) (r ?i64) {
    r = a / b; b == 0 → err（呼叫方必须处理）
}

#{overflow=wrap}
fast = (a i64, b i64) (r i64) {
    r = a / b; b == 0 → 0 并印一行 stderr 诊断（不再是裸 sdiv 的 UB）
}
```

> **为什么 `#{overflow = wrap}` 不能豁免零除守卫**：它改变的是**溢出行为**（结果型别仍恒为 `?int`），不是除数的安全性。若让它豁免，编译器就会发出裸 `sdiv`，最佳化器便有权假设除数永远非 0（把 `a / 0` 折成任意值），而 x86-64 的 `idiv` 直接以 #DE 崩溃——既 UB、又没有任何诊断。因此 zero-divisor 守卫**独立于注解**存在；plain 路径之所以多印一行 stderr，正是因为该路径没有 option 可供呼叫方检查。
>
> **同一守卫也覆盖 `sdiv (INT_MIN, -1)`**（结果不可表示，同属 UB；x86-64 上会 SIGFPE）。option 路径把它并入 `err`；plain 路径取 2 补数回绕值（`INT_MIN / -1 → INT_MIN`、`INT_MIN % -1 → 0`）。

浮点除法不受管辖：`1.0 / 0.0` 由 IEEE-754 定义为 `inf` / `nan`，不是 UB。

### 未标注运算列为错误（`ovf-int-default`）

`no vet` 把**未标注**的整数运算回报为**提示**（trace id `ovfhndld`，HINT）。原因：预设的 `?T` 对使用者不可见，必须让他知情——可加 `#{overflow = ...}` 指定溢出行为，或用 `?T` + `?=` / match / 显式 plain 型别消费。真正该阻断建置的是 `optunuse`（option 既没上抛也没解包）。

### 自动修复：`no fmt --fix=overflow`

批量补注解不必手写，用 `no fmt` 的修复类别参数：

```bash
no fmt --fix=overflow -w src/std          # 就地修复整个目录
no fmt --fix=overflow -d src/std/str.no   # 只印 diff，不写档
no fmt --fix=overflow src/std/str.no      # 印出修复后的内容
```

修复是**精准且不污染**的：只在 lint 实际报告的那条运算所在陈述上方插入 `#{overflow=wrap}`，不改动其他陈述、不重排版、不动既有注解，且重跑幂等（已标注者不再变动）。这与直接跑 `no fmt -w` 不同——后者是完整重新格式化。

> 修复后请再跑一次 `no vet` 确认归零。绝大多数情况一次即清空（`src/std` 由 4728 条降为 0）。已知的唯一例外形状：报告落在 match arm 的**条件**上，而该 arm 本体没有任何可标注陈述——行注解只作用于其后的第一条陈述，涵盖不到 arm 自己的条件运算，此时 `no vet` 会再次报出。这种情况请先把该运算抽成独立陈述再标注。

### 自动修复：冗余型别标注

当变量声明的**类型标注与右侧值推断出的类型完全相同**时，该标注是冗余的（`no vet` 会以 hint `tcpoxtfd`、`type annotation '<T>' can be omitted (inferred from value)` 报出）。

- **预设 `no fmt` 就会自动去除**：`no fmt -w` 在格式化时一并移除冗余标注（同时做正常重新格式化），`no fmt -d` 预览含此变更，`-w` 写入。

```bash
no fmt -w main.no          # 格式化并去掉冗余标注
no fmt -d main.no          # 只印 diff（含标注移除）
no fmt -w src/             # 整个目录
```

- **`--fix=redundant`（手术式、只动标注）**：若只想移除冗余标注、不要完整重新格式化（例如对 `src/std`，因 `no fmt` 会丢掉 `#{index-out}`），用此类别——它只删标注、不重排版：

```bash
no fmt --fix=redundant -w src/std          # 就地移除整个目录的冗余标注（不重排版）
no fmt --fix=redundant -d src/std/str.no   # 只印 diff，不写档
no fmt --fix=redundant src/std/str.no      # 印出修复后的内容
```

```nolang
; 修复前
x str = ''
b i64 = 5
m [str]i64 = make-map()

; 修复后（标注 == 推断型别，去掉）
x = ''
b = 5
m = make-map()
```

规则要点：

- **标注型别 == 推断型别**才移除（如 `str`/`i64`/`[str]i64` 与其推断值一致）。
- **可隐式转换但不相等**的情况**不会**移除——保留标注才有转换语意。例如 `c i16 = 5`（`5` 推断为 `i64`，与 `i16` 不等）、`p ?i64 = nil`、`last txt = ''`（`txt` 与 `str` 可隐式互转但型别不同）。
- **无型别标注**的写法（如 `d = 'x'`）本就不会被报，自然也不动。
- **定长阵列标注 `[N]T` / `[?]T` 一律保留**（永不视为冗余）。`[N]` 不是单纯的型别提示，而是决定**表示形式**的开关：写了它，右侧的 `[...]` 字面量才会被解析成固定长度的栈阵列；写了它，推断结果才会「刚好等于」标注——这是标注自己造出来的循环论证。删掉后同一行重解析就变成堆上可增长的切片 `[]T`，语意随之改变：`fixed [3]char = ["x", "y", "z"]` 的 `.push()` 无效（`.len()` 恒为 3），退化成 `fixed = ["x", "y", "z"]` 后 `.push()` 会让 `.len()` 变 4。切片标注 `[]T` 不在其列——它删掉后仍是切片，属真冗余。
- **含十六进位字面量的值一律保留标注**（保守例外）。`no vet` 的型别推断对 `0xNN` 采用「推断为 `byte`」的启发式，与编译器「无标注时整数字面量预设 `i64`」的实际语义不同，因此 `IP-TBL [64]byte = [0x3a, ...]`、`s []byte = [0x50, 0x4b]` 会被误判为冗余；一旦移除，字面量会退化成 `i64` 元素而产生 `expected '[]byte', got '[]i64'` 之类的型别错误。故只要值运算式文本中出现 `0x`/`0X`，hint 与移除都不会发生。
- **右值为栏位读取时一律保留标注**（保守例外）。`i i64 = .pos` 这类写法的标注不是单纯的型别提示，而是下游整数算术是否产生 `?T` 的开关：改由栏位推断型别时，`i + N` 不再是「有号运算」、不回传 `?i64`，两段式解包的 `ok` 臂永不命中、回圈计数器原地不动。实例 `src/std/yaml.no` 的 `parser.looks-like-map-entry`：删掉 `i64` 会让 `yaml.parse('abc')` 陷入死循环。故 `x = .field`、`x = obj.field`（含括号或前缀包裹）上的标注既不报 `tcpoxtfd`，也不会被预设 `no fmt` 或 `--fix=redundant` 删除。

不论走预设 `no fmt` 还是 `--fix=redundant`，移除都只删除被报告的那个型别标注及其前导空白、重跑幂等（已移除者不再变动）。修复后建议再跑一次 `no vet` 确认 `tcpoxtfd` 归零。

### 自动修复：消费 option（`--fix=unwrap`）

统一规则下「产生 option 却从未消费」是唯一该阻断建置的诊断（trace `optunuse`）。批量把它改成显式消费形式，用 `--fix=unwrap`：

```bash
no fmt --fix=unwrap -w src/std            # 就地修复整个目录
no fmt --fix=unwrap -d src/std/str.no     # 只印 diff，不写档
no fmt --fix=unwrap src/std/str.no        # 印出修复后的内容
```

修复形态（见〈安全索引〉）：**所在函式已有 `?T` 结果参数** → 上抛（`x ?= <expr>`）；否则 → 改名 + match 解包：

```nolang
; 修复前
x = a + b

; 修复后（所在函式有 ?T 结果参数）
x ?= a + b

; 修复后（否则，4 行标准形；空兜底臂 = 零值）
x-opt = a + b
x = x-opt: {
    ok -> it

    ->
}
```

与其他 fix 类别一样：手术式文字替换、不改排版、不动陈述上方的 `#{overflow=…}` / `#{index-out=…}` 注解（它们仍负责「失败时怎么取值」），重跑幂等。修复后请再跑一次 `no vet` 确认 `optunuse` 归零。

### 注解绑定与单行合并

`#{...}` 注解**绑定到节点**，因此同一条陈述可同时带多个键；多个注解一律**合并成单行**：

```nolang
#{fmt-skip}
i <- [0..16): {

    #{index-out=0, overflow=wrap}
    buf[base + i] = data[i]
}
```

上面这一条同时需要「越界取默认值」（`index-out`）与「溢出回绕」（`overflow`）两个语意。分成两行写解析结果相同，但 `no fmt --fix=overflow` 产出合并后的单行形式。

> **行注解的作用范围**：`#{overflow = ...}` 只作用于**紧接其后的下一条陈述**。中间若夹著无关的注解仍会正确套用到该陈述。安全索引写入（`arr[base + i] = v`、`.buf[.pos + i] = v`）会被 desugar 成 match 形式，`#{overflow = wrap}` 会一并带到 desugar 之后的节点，故索引算式同样受注解管辖，不会被误报为未标注。

### 错误上抛（`?=` 运算子）

`?=` 是 option 解包 + 向上抛错误的**简便写法**。**函数回传 option 并非必要条件**：下列两种情形居其一即可，
因此回传值不是 option 的函式只要用块 match 包住主体，照样能写 `y ?= x + 1`。

**语法：**

```no
v ?= expr
```

**语义：**

- 如果 `expr` 返回 `ok(value)`，则 `v` 被赋值为解包后的内部值（自动解包）
- 如果 `expr` 返回 `nil` 或 `err`：
  - 函式有 `?T` 结果参数时 → 把该 option 写入结果参数并提前 `return`（自动上抛）；
  - 陈述位于**陈述层级块 match** `{ ... }: { ... }` 主体内时 → 由**最近的**块 match 捕捉，
    **整个主体停止**、arms 只跑一次（**不是** `return`），函式无需 `?T` 结果参数。

**可用条件（二者其一即可）：**

1. 所在函式具有 option 类型结果参数；
2. 陈述位于陈述层级块 match `{ ... }: { ... }` 的主体内（见〈Match 主语的三种形态〉）。

两者皆非时编译器会报错。`err -> _` / `-> _` 两臂可把上抛的错误就地吞掉，是「无 `?T` 结果参数
也想用简写」的标准兜底：

```no
handle = (x i64) {
    {
        y ?= x + 1
        print(1)
    }: {
        err -> _

        -> _
    }
}
```

**结果参数无需预先赋值：** 函式 prologue 不做零初始化，但 return 时未显式赋值的输出参数会被自动零填充（整数 → `0`、`str` / 结构体 → 零值、option → `nil`），因此示例里不写 `result = nil` 样板，只写成功路径的赋值即可。

**示例：**

```no
; 逐行读取档案并处理 — 使用 ?= 简化错误传播
process-file = (path str) (result ?str) {
    f ?= open(path); 失败时自动 result = f; return
    line ?= f.read-line(); EOF 或错误时自动上抛
    result = line
}
```

等价的展开形式（编译器自动生成的 match 链）：

```no
#{fmt-skip}
process-file = (path str) (result ?str) {
    result = nil
    __tmp = open(path)
    __tmp: {
        nil || err -> {
            result = __tmp
            return
        }
        -> f = it
    }
    __tmp2 = f.read-line()
    __tmp2: {
        nil || err -> {
            result = __tmp2
            return
        }
        -> line = it
    }
    result = line
}
```

**链式使用：** 多个 `?=` 可以串联使用，实现管道式错误传播：

```no
pipeline = (input str) (result ?str) {
    a ?= step1(input); 失败则上抛
    b ?= step2(a); 失败则上抛
    result = b
}
```

**裸算术运算：** `?=` 的右侧不限于函数呼叫——任何回传 `option` 的整数运算（如未标注的 `a - b`、`a + b`、`a * b`）都可以直接用 `?=` 上抛溢出错误，无需先绑定到中间变数：

```no
; 溢出时自动 result = err; return，正常时 v 解包为内部值
sub-safe = (a i64, b i64) (result ?i64) {
    v ?= a - b; 下溢/上溢 → err 自动上抛；否则 v = 内部 i64
    result = v
}

add-safe = (a i64, b i64) (result ?i64) {
    v ?= a + b; 同上，适用于 + * 与有号 /
    result = v
}
```

等价展开（编译器自动生成）：

```no
#{fmt-skip}
sub-safe = (a i64, b i64) (result ?i64) {
    result = nil
    __unwrap = a - b            ; option<i64>
    __unwrap: {
        nil -> {
            result = __unwrap
            return
        }
        err -> {
            result = __unwrap
            return
        }
        -> v = it               ; ok(value)：解包内部值
    }
    result = v
}
```

**复合右侧（compound RHS）：** `?=` 的右侧可以是一个含多个 option 运算元的复合运算式。每个 option 运算元会被自动解包，并注入传播守卫——只要任一运算元为 `nil` / `err`，当前函数的 option 结果参数即被设为该值并 `return`（向上抛）；全部成功才把内部值赋给左值：

```no
sum3 = () (result ?i64) {
    a ?i64 = ok(10)
    b ?i64 = ok(20)
    c ?i64 = ok(30)
    total ?= a + b + c; 每个 option 运算元自动解包并传播
    result = total
}

comp = () (result ?i64) {
    a ?i64 = ok(4)
    b ?i64 = ok(6)
    v ?= dbl(a + b); a + b 可能是 option，同样自动解包并传播
    result = v
}
```

> 只有「运算元位置」上的 option 会被自动解包（如 `a + b + c`、`f(b + c)`）；作为函式引数直接传入的 option 变数不在此列——它会走 `?=` 既有的裸 option 引数豁免（`a ?= f(v)`，其中 `v` 为 `?i64`、`f` 接收 plain `i64`）。

**非 option 右侧报错：** 为了避免大范围地把 `=` 误写成 `?=`，当右侧在编译期可被确定为「明确非 option」时，编译器会报错并提示改用 `=`：

- 字面量：`v ?= 42`
- 常数可折叠的整数运算：`v ?= 10 + 20`
- 已知型别且非 option 的区域变数：`v ?= x`（其中 `x i64 = 5`）

报错讯息形如：`` `?=` RHS `42` is not an option — use `=` instead ``。

> 算术运算只要任一运算元是 option（或型别未知 / 为函式呼叫，可能回传 option），即视为「可能 option」而放行，不会误报——例如 `v ?= a + b + c`（a/b/c 为 `?i64`）或 `v ?= b + c`（b/c 未知型别）都可正常编译。

**适用场景：**

- `pop` / `peek` 等可能为空的容器操作 → `?t`（`nil` = 空）
- `read-line` / `read-byte` 等 I/O 操作 → `?str` / `?i64`（`nil` = EOF，`err` = 错误）
- `lookup` / `get` 等查找操作 → `?t`（`nil` = 未找到）
- `parse` / `from-str` 等解析操作 → `?t`（`nil` = 空，`err` = 无效输入）
- `accept` / `dial` 等网路连接 → `?conn`（`nil` = 无连接，`err` = 错误）

**nil vs err：** 当缺失是正常/预期的结果（空堆叠、键不存在、EOF）时用 `nil`；当缺失代表实际的错误状态（I/O 失败、输入无效、连接被拒）时用 `err('msg')`。

**例外：** 当函数需要返回多个独立值（如 `(name str, value str, ok bool)`）时，可保留多返回值模式。

**多返回值最多只能有一个 `?T`（硬错误）：** 函式宣告的返回参数中，`?T` 至多一个。`?T` 是**单一**的错误通道——函式体内的 `?=` 提前返回时，只能把失败放进那个唯一的 option 返回参数；若同时宣告两个 `?T`，编译器只填得上第一个，呼叫方会拿到半填的 tuple（`(err, nil)`），且无从判断哪个值代表失败：

```no
#{fmt-skip}
pair = () (a ?i64, b ?i64) {; 错误：两个 ?T 返回参数
    a = ok(1)
    v ?= boom(); boom() 回 err('boom')
    a = v
    b = ok(2); 永不执行 —— 呼叫方看到 (err, nil)
}
```
```

正确写法是把独立值宣告成 plain 型别，只留一个 `?T` 当错误通道：

```no
lookup = (k str) (value str, found bool, err ?str) {
    value = ''
    found = false
    err = nil
}
```

报错讯息形如：`` function 'pair' declares 2 option (?T) results ('a', 'b'); only one result may be ?T … [moptres1] ``。方法定义的隐式 `self` 接收者是呼叫方别名的出参，不占用这个名额；`#{c}` extern 宣告同样受限。

### 错误捕获赋值（`=` 就地捕获）

`?=` 的语义是「错误向上抛」——它要求所在函式有 option 结果参数，失败时提前 `return`。当你不希望提前返回、而是想在原地处理错误时，用普通 `=`：只要右侧含**可错源**，目标变数就会自动推断为 `?T`，`nil` / `err` **就地存进该变数**，流程继续。

```no
handle = (b i64, c i64, d i64) (r i64) {
    a = b + c / d; a 推断为 ?i64；除零 → a = err
    a: {
        err -> {
            r = -1; 就地处理错误
        }

        nil -> {
            r = -1
        }

        -> {
            r = it; 成功：r = b + c/d
        }
    }
}
```

**可错源（捕获触发源）：**

| 来源                    | 例                                   | 捕获结果                          |
| --------------------- | ----------------------------------- | ----------------------------- |
| 整数除法 / 取模             | `a = b + c / d`、`a = b % c`         | 除零、`MIN / -1` → `err`         |
| 安全索引                  | `a = v[i]`（`arr` / `vec` / `slice`） | 越界 → `err`（`code.index-out`）  |
| option 型运算元           | `a = x + 1`（`x ?i64`）               | `x` 为 `nil` / `err` 时原样存入 `a` |
| 回传 option 的呼叫（作算术运算元） | `a = f(x) + 1`（`f` 回传 `?i64`）       | 同上                            |

> 作为函式引数**直接**传入的 option 不在此列——那交给被呼叫方处理（与 `?=` 的裸 option 引数豁免一致）。

**纯算术不是可错源**：`+ - * <<` 与取负本身不触发捕获（否则所有算术都会变成 option）。但一旦落在 option 路径上（例如右侧另有 `/`，或目标显式宣告 `?T`），这些运算会带**运行期溢出检查**，溢出 → `err`：

```no
ovf = (x i64) (r i64) {
    a ?i64 = x + 1; 显式 ?T → 走 option 包装路径
    a: {
        err -> {
            r = 0; x = i64-max 时溢出 → err
        }

        nil -> {
            r = 0
        }

        -> {
            r = it
        }
    }
}
```

**捕获 vs 上抛：**

| 写法            | 失败时                                 | 需要 option 结果参数 | 之后如何取值             |
| ------------- | ----------------------------------- | -------------- | ------------------ |
| `a ?= expr`   | 设结果参数为 `nil`/`err` 并 `return`（提前返回） | 是              | 不适用（已返回）           |
| `a = expr`    | `a` 就地存 `nil`/`err`，流程继续            | 否              | `a: { ok -> ... }` |
| `a ?T = expr` | 同 `=`（显式标注，含内部可错子表达式）               | 否              | 同上                 |
| `_ = expr`    | 求值但丢弃结果与错误（不报错、不触发 unused lint）     | 否              | 不适用                |

**适用范围：** 安全索引的捕获与 `?=` 一样，**只在回传 `?T` 结果的函式内生效**（见〈安全索引〉第 3 种写法）。`/` `%` 与 option 运算元的捕获则适用于所有函式。

**既有变数不改型别：** 捕获只对「本陈述首次宣告」的目标生效。若目标已经存在（`v i64 = 0` 之后的 `v = arr[i]`、或 `d = 0` 之后的 `d = x - 1`），编译器不会就地改变它的型别，而是报错要求显式选择语义（加 `#{overflow=...}` / `#{index-out=...}` 注解、用 `?=`、或宣告 `?T`）。

### 整数赋值型别检查

编译器会对整数赋值进行型别检查，防止不安全的窄化（narrowing）导致资料遗失。以下是规则：

#### 隐式拓宽（安全，自动允许）

窄整数型别的值可以自动赋值给更宽的型别，因为目标型别的范围完全包含来源型别：

```no
b byte = 200
i i64 = b; ✓ byte 范围 [0,255] ⊆ i64 范围
u u32 = b; ✓ byte 范围 ⊆ u32 范围
```

#### 整数字面量赋值

整数字面量（预设推断为 `i64`）可以赋值给任何范围包含该值的整数型别：

```no
#{fmt-skip}
n u8 = 200; ✓ 200 ∈ [0,255]
m u8 = 300; ✗ 300 > 255，编译错误
big u64 = 18446744073709551615; ✓ 2^64-1，u64 最大值
```
```

#### 不安全的窄化（编译错误）

将宽型别的变数直接赋值给窄型别会导致编译错误，因为可能造成资料遗失。错误讯息会附带**可操作的修复提示**，建议如何用位元运算安全窄化：

```no
#{fmt-skip}
d u64 = 42
h u32 = d; ✗ cannot assign u64 value to u32 variable 'h'; hint: narrow safely with a bitwise mask (e.g. `& 4294967295`) or right shift (e.g. `>> 32`)
h u16 = d; ✗ cannot assign u64 value to u16 variable 'h'; hint: narrow safely with a bitwise mask (e.g. `& 65535`) or right shift (e.g. `>> 48`)
h u8 = d; ✗ cannot assign u64 value to u8 variable 'h'; hint: narrow safely with a bitwise mask (e.g. `& 255`) or right shift (e.g. `>> 56`)
x u32 = d + 1; ✗ 加法结果仍为 u64，不安全
y u32 = foo(); ✗ 函式呼叫结果型别不匹配
```
```

> **修复提示**：编译器会根据目标型别自动计算精确的 mask 值和位移量。按照提示套用 mask 或位移后，即可安全窄化（见下节）。
>
> **有号目标型别**：对 `i8`/`i16`/`i32`/`i64` 等有号整数，提示会说明位元窄化不适用（符号位元截断语义不明确），建议改用显式范围检查。

#### 位元运算安全窄化（自动允许）

当赋值的右侧是**位元运算表达式**（`&`、`|`、`^`、`<<`、`>>`）且目标型别为**无号整数**（`u8`/`u16`/`u32`/`u64`/`byte`）时，编译器允许隐式窄化——因为截断高位是位元操作的标准语义，不会造成非预期的资料遗失：

```no
d u64 = 42

; ✓ mask 运算：结果必 ≤ mask 值，安全落入 u32
h u32 = d & 67108863; mask = 2^26-1 < 2^32
h u32 = d & 4294967295; mask = 2^32-1，正好 u32 范围

; ✓ 位移运算：右移后高位为 0，安全
hi u32 = d >> 32; u64 >> 32 留 32 bits

; ✓ XOR / OR 组合
c u32 = a ^ b; 位元运算结果
b byte = v & 255; mask 到 byte 范围

; ✓ 复合位元运算（常见于密码学/编解码）
s u32 = (key[0] & 255) | ((key[1] & 255) << 8) | ((key[2] & 255) << 16) | ((key[3] & 255) << 24)
```

> **为什么允许？** 位元运算（mask、位移、XOR、OR）的语义就是构造一个位元模式。赋值给窄的无号型别时，截断高位是刻意的操作——开发者已透过 mask 或位移保证了结果的范围，或刻意丢弃高位。这是密码学（如 ChaCha20、Poly1305、Blake2）和编解码代码中的标准模式。

> **仅限无号目标型别。** 对有号整数目标（`i8`/`i16`/`i32`/`i64`），即使右侧是位元运算也会报错，因为符号位元的截断语义不明确：
>
> ```no
> d u64 = 42
> h i32 = d & 4294967295   ; ✗ 仍报错：有号目标不适用安全窄化
> ```

> **顶层必须是位元运算。** 只有当表达式的顶层运算子是 `&`/`|`/`^`/`<<`/`>>` 时才放行。加法、减法、函式呼叫、直接变数引用等不在此列：
>
> ```no
> d u64 = 42
> h u32 = d              ; ✗ 顶层是 Identifier，不是位元运算
> h u32 = d + 1          ; ✗ 顶层是 +，不是位元运算
> ```

#### 直接引入 `.noml` 设定档

`.noml` 档案可以用 `#` 直接引入：解析顺序先找同名 `.no`，找不到再找 `.noml`。引入后
**结构体名预设就是档名**（去掉副档名，可由档案顶部的 `#{name = '...'}` 注解改写），
各成员成为该结构体的栏位；同时生成一个同名的全局值承载档案内容，因此用
`server.port` 读取设定。

```noml
; cfg/server.noml
{
  host: 'localhost'
  port: 8080
  tags: [] #{type = '[]str'}
  compiler: {
    version: 'v0.1.0'
  }
}
```

```no
# /cfg/server

print(server.port); 8080
print(server.compiler.version); v0.1.0
```

- 栏位型别优先取成员的 `#{type = '...'}` 注解（值是完整的 nolang 型别表达式，如
  `'[]str'`、`'[]i64'`、`'?i64'`）；未标注时由值推断：字串 → `str`、整数 → `i64`、
  小数 → `f64`、布林 → `bool`、物件 → 自动生成的巢状结构体（`server-compiler`）、
  阵列 → `[]元素型别`。
- 空容器（`[]`、`{}`）**必须**写 `#{type = '...'}`：noml 的值本身没有型别，空容器
  无法推断。物件成员标注 `#{type = 'x'}` 时直接使用 `x`（需自行定义），不再自动生成
  巢状结构体。
- 巢状物件的结构体名以档名为前缀（`server-compiler`）；定义顺序先巢状后宿主。
- **顶部（文件级）注解可改写结构体名**：`#{name = '...'}`（等价写法 `#{type = '...'}`，
  `name` 优先）写在顶层 `{` 上方的独立一行（或顶层值同一行尾随）。改写后值绑定名与
  巢状结构体前缀一并跟随，但**导入路径仍按档名解析**：

```noml
; cfg/db.noml
#{name = 'db-options'}
{
  host: 'localhost'
}
```

```no
# /cfg/db
# /cfg/db as db2

print(db-options.host); localhost
print(db2.host); localhost
```

- 两个不同档案生成同一型别名时（例如不同目录下的同名档案）会报错，用顶部
  `#{name = '...'}` 区分即可；同一档案被多次导入（例如再加 `as` 别名）只合并一份型别定义。
- 键名按 nolang 规则转成中连接符小写（`anonymous-fn-type`）：数字开头加 `f-`，与
  关键字同名的加 `x-`。
- 允许 `as` 别名改写值绑定名，结构体名不变：`# /cfg/server as cfg`。
- `.noml` 型别不参与模组前缀：即使档名与标准库模组同名（如 `server`），型别仍是裸名。
- `package.noml` / `workspace.noml` 同样可写 `#{...}` 注解（如 `#{type = '[]str'}`）：
  解析时忽略，只供外部工具重建强型别结构；语法与 nolang 的 `#{...}` 完全一致。

### FFI（`#{c}` 注解）

透过 `#{c}` 注解宣告外部 C 函式，实现 FFI（Foreign Function Interface）。

**语法**：`#{c}` 独立一行，标记下一行为 FFI 宣告。`#{c}` 是注解系统的 FFI 语言键，也支援 `#{cpp}`、`#{rust}` 等其他语言。旧语法 `#c` 仍向后相容。

**私有宣告**：名称以 `_` 开头表示私有（不导出），C ABI 符号自动去除前缀 `_` 并将连字号转为底线。

**不再需要分开档案**：FFI 宣告与普通代码可写在同一个 `.no` 档案中。

**指针型别语法**：FFI 中使用 C 风格的 `*T`、`**T`、`***T` 表示指针，必须有具体型别 `T`。普通代码不能使用此语法。

| 语法        | 含义          | LLVM IR | 用途                  |
| --------- | ----------- | ------- | ------------------- |
| `*byte`   | 指向 byte 的指针 | `i8*`   | 不透明指标（如 db handle）  |
| `**byte`  | 双重指针        | `i8**`  | 输出参数（如 `sqlite3**`） |
| `***byte` | 三重指针        | `i8***` | 极少见的三重间接            |

```no
; sqlite.no — FFI 绑定与安全包装在同一档案
; 编译器自动将连字号 (-) 转为底线 (_) 以匹配 C ABI 符号
; 以 _ 开头的名称为私有，C ABI 符号自动去除前缀 _

; 基本型别参数
#{c}
c-strlen = (s str) (n i64)

; 指针参数（*byte = 不透明指标），私有宣告
#{c}
_sqlite3-close = (db *byte) (rc i32)

; 双重指针（**byte = 输出参数，呼叫后值自动存回变数），私有宣告
#{c}
_sqlite3-open = (filename str, db **byte) (rc i32)

; 多个指针参数，私有宣告
#{c}
_sqlite3-exec = (db *byte, sql str, callback *byte, arg *byte, errmsg *byte) (rc i32)
```

```no
; 同一档案中的安全包装

open = (dsn str) (d db-sqlite) {
    handle i64 = 0
    rc i32 = _sqlite3-open(dsn, handle)
    rc != SQLITE-OK -> {
        return
    }
    d.handle = handle
}
```

**规则：**

1. `#{c}` 独立一行，标记下一行为 FFI 宣告（旧语法 `#c` 仍向后相容）
2. FFI 仅为宣告，无函式主体
3. 指针必须有具体型别（如 `*byte`），不允许裸 `ptr`
4. `**byte` 用于输出参数：呼叫后 C 函式写入的指针值会自动转为 `i64` 存回呼叫端变数
5. 所有指针在 Nolang 端以 `i64` 储存（`ptrtoint`）
6. `str` 型别参数自动转为 null-terminated `i8*`
7. 名称以 `_` 开头表示私有（不导出），C ABI 符号去除前缀 `_`
8. FFI 宣告与普通代码可写在同一个 `.no` 档案中

> 反向方向（让 C / C++ / Rust / Go / Java / Python / C# 反过来呼叫 Nolang）用 `#{cabi='symbol'}` 与 `no build --shared`，见 [从宿主语言调用 Nolang](./host-interop)。

### 注解系统（`#{...}`）

`#{...}` 是通用注解系统，以逗号分隔的键值对列表。支援以下值类型：

| 语法  | 类型  | 范例                                   |
| --- | --- | ------------------------------------ |
| 独立键 | 布尔  | `#{debug}`                           |
| 布尔值 | 布尔  | `#{inline=true}` / `#{inline=false}` |
| 数值  | 整数  | `#{max=100}`                         |
| 文字  | 字串  | `#{name='hello'}`                    |
| 识别字 | 识别字 | `#{mode=fast}`                       |
| 阵列  | 阵列  | `#{derive=[Serialize, Deserialize]}` |
| 范围  | 范围  | `#{range=[0..256)}`                  |

多个键值对以逗号分隔：

```no
#{derive=[Serialize, Deserialize], range=[0..256), max=100, debug}
```

#### 注解位置

`#{...}` 只允许两种写法：

- **上方**：独立成行，置于目标（陈述、结构体栏位、枚举成员、宣告、match 臂）上方；
- **后方**：写在目标同一行的尾随位置（`res = arr[i] #{index-out=zero}`、`a pt #{inline}`、  
  `green #{deprecated}`）。

写在目标**前方同一行**（前缀，如 `#{index-out=zero} res = arr[i]`）是**编译错误**，编译器与  
LSP 会回报同一条诊断。判定方式：注解群组的 `}` 之后、同一行上不得再有程式码（换行、  
`;` 行注释、或紧接的另一个注解群组不算程式码）。

```no
; ✓ 上方：独立成行
#{overflow=wrap}
x i8 = a + 100

; ✓ 后方：同一行尾随
x i8 = a + 100 #{overflow=wrap}
```

```no
#{fmt-skip}
; ✗ 前方：同一行前缀 → 报错
#{overflow = wrap} x i8 = a + 100
```

结构体栏位与枚举成员（C 风格枚举的值、标签列举的变体）的注解同样只允许上方或后方  
（`a pt #{inline}`、`a pt #{inline=true}`、`green #{deprecated}`、`ok(v i64) #{inline}`）。  
注意 `#{inline}` 的**值**同样受支援：`#{inline=false}` 是合法的（见下文  
〈结构体栏位上的 `#{inline}`〉）。

`if <cond> { ... }` 写法中，注解夹在条件与 `{` 之间（`if x > 0 #{overflow=wrap} {`）也是  
「前方」位置，同样报错。该处的扫描是宽松的，过去会把整组注解吞掉——既不生效也不报错，  
是最难察觉的一种失效。

范围语法支援 16 种括号组合（规律：`[` 包含左端点，`(` 不包含；`]` 包含右端点，`)` 不包含）：

**有界区间（4 种）**— 两端都有值：

- `[a..b]` — 两端闭区间（`x >= a && x <= b`）
- `[a..b)` — 左闭右开（`x >= a && x < b`）
- `(a..b]` — 左开右闭（`x > a && x <= b`）
- `(a..b)` — 两端开区间（`x > a && x < b`）

**无上限区间（4 种）**— 省略右端点：

- `[a..]`、`[a..)` — 左包含，无上限（`x >= a`）
- `(a..]`、`(a..)` — 左不包含，无上限（`x > a`）

**无下限区间（4 种）**— 省略左端点：

- `[..b]`、`(..b]` — 无下限，右包含（`x <= b`）
- `[..b)`、`(..b)` — 无下限，右不包含（`x < b`）

**完全无界区间（4 种）**— 两端都省略，基于类型最小值/最大值：

- `[..]` — 类型最小值 ≤ x ≤ 类型最大值（两端都包含）
- `[..)` — 类型最小值 ≤ x < 类型最大值
- `(..]` — 类型最小值 < x ≤ 类型最大值
- `(..)` — 类型最小值 < x < 类型最大值

#### 注解的作用域

注解的**位置**决定宿主，宿主的**种类**决定它管多大范围。一共四层，由外向内生效、
就近覆盖，函式体是继承的硬边界：

| 层级 | 宿主 | 生效范围 |
| --- | --- | --- |
| **L0 模组级** | 档案头 | 本档全部宣告与语句（档案头注解 + 一个空行） |
| **L1 宣告级** | 常量/全局变数、结构体、介面、标签列举、函式、方法 | 该宣告的整个定义（函式含函式体与全部巢状区块） |
| **L2 区块级** | 协程组、if 组、`cond -> body`、match、`for`/计数/区间循环 | 该块体内全部语句（含巢状块，止于内层 L1 边界） |
| **L3 单行级** | 单条陈述（`let`、赋值、`?=`、`return`、呼叫、`cond ->` 臂） | 该陈述自身及其运算式 |

```no
; L1：整个函式
#{overflow=wrap}
sum = (xs []i64) (total i64) {
    ; L3：只管下一条陈述
    #{overflow=wrap}
    total = xs.len() - 1
    ; L2：整个循环体
    #{overflow=wrap}
    i <- [0..xs.len()): {
        total = total + xs[i]
    }
}
```

完整的判定规则、键 × 层级矩阵、与现行实作的差距，见
[〈注解与注释的作用域〉](annotation-scope.md)。

FFI 注解 `#{c}` 是注解系统的特殊形式，当注解包含 FFI 语言键（`c`、`cpp`、`rust` 等）且后续为函式宣告时，编译器将其识别为 FFI 绑定：

```no
; #{c} 带额外注解
#{c, debug}
_sqlite3-open = (filename str, db **byte) (rc i32)
```

#### 注解附加到宣告

非 FFI 注解会自动附加到紧随其后的宣告（变数宣告、结构体定义），可用于为数值型别（如 `num`、`i64` 等）标记范围限制等元数据：

```no
; 变数宣告带 range 注解
#{range=[0..256)}
x num = 42

; 结构体定义带注解
#{derive=[Serialize, Deserialize]}
point {
    x i64
    y i64
}

; 结构体栏位带 range 注解（可用于 num 等数值型别）
person {
    age num #{range=[0..150]}
    score i64 #{range=[0..256)}
    name str
}
```

`range` 注解特别适用于 `num` 型别（`num = int | float`），用于标记数值的有效范围。范围值可以是整数或识别字：

```no
; 使用常量识别字作为范围边界
#{range=['i8.MIN'..'i8.MAX']}
val i8 = 100
```

#### 文件嵌入（`#{embed=...}`）

`#{embed=...}` 注解在编译期将外部文件内容嵌入为 `[]byte` 只读常量，类似 Go 的 `//go:embed`。嵌入的数据直接编译进可执行文件，实现单二进制分发，无需运行时读取文件。

**语法**：

```no
#{embed='path/to/file'}
ICON []byte

; 或使用裸路径（无引号）
#{embed='assets/icon.ico'}
ICON []byte
```

`embed` 注解附加到紧随其后的 `[]byte` 变数宣告上。变数宣告**不能**带有显式初始值——值由嵌入的文件内容提供。

**路径解析**：

- 相对路径相对于包根目录（`package.noml` 所在目录）解析
- 支援绝对路径
- 路径中可包含 `/`、`.`、`-` 字符

**范例**：

```no
; 嵌入 Windows 图标
#{embed='assets/win-icon.ico'}
WIN-ICON []byte

; 嵌入 SSL 证书
#{embed='certs/server.pem'}
SERVER-CERT []byte

; 嵌入配置文件
#{embed='config/default.json'}
CONFIG []byte

; 使用嵌入数据
print('icon size: ', len(WIN-ICON))
print('first byte: ', WIN-ICON[0])
```

**注意事项**：

1. 嵌入数据为**只读**常量，指向只读内存区域。写入嵌入数据的行为是未定义的（与 Go `//go:embed` 语义一致）
2. 嵌入变数不参与堆释放——程序退出时不会 free 嵌入数据的指针
3. 仅支援 `[]byte` 类型宣告（`[N]byte` 固定阵列亦可）
4. 文件必须在编译期存在，否则报错
5. 不能与显式初始值共存（如 `ICON []byte = [1, 2, 3]` 会报错）

#### 文件夹嵌入（`#{embed='dir'}`）

`#{embed=...}` 也支援嵌入整个目录。当路径指向目录时，编译器递回读取目录下所有文件，嵌入为 `fs.embed` 类型的只读文件系统。运行时通过 `read()`、`exists()` 方法按路径访问嵌入的文件，无需任何 C 函数——查找逻辑完全由 Nolang 实现。

**语法**：

```no
; 嵌入整个前端目录
#{embed='../frontend/dist'}
DIST fs.embed

; 从嵌入的文件系统读取文件
data = DIST.read('index.html')

; 检查文件是否存在
ok = DIST.exists('css/style.css')
```

**`fs.embed` 类型**：

`fs.embed` 是 Nolang 标准库 `fs` 模组中定义的结构体，包含嵌入文件的元资料（路径、偏移、长度）。编译器在编译期读取目录并将所有文件内容拼接为常量全局变数，运行时由纯 Nolang 实现的 `read` 方法遍历查找。

| 方法       | 签名                                  | 说明                |
| -------- | ----------------------------------- | ----------------- |
| `read`   | `(path str) (data ?[]byte)`           | 读取嵌入的文件，返回内容（未找到时为 nil） |
| `exists` | `(path str) (yes bool)`             | 检查嵌入的文件是否存在       |

**范例**：

```no
; HTTP 静态文件伺服器：将前端文件嵌入单一二进制
#{embed='../frontend/dist'}
DIST fs.embed

serve = (conn server-conn) {
    conn.parse()
    path = conn.path
    path == '/' -> path = '/index.html'

    ; 去掉前导 / 得到相对路径
    rel = path.slice(1, path.len-bytes())

    ; 从嵌入的文件系统读取
    data []byte = DIST.read(rel)
    {
        ok -> it

        -> {
            conn.write-html(404, 'Not Found')
            conn.close()
            return
        }
    }
    conn.write-status(200)
    conn.write-header('Content-Type', get-content-type(path))
    conn.write-body(data)
    conn.close()
}
```

**注意事项**：

1. 目录中所有文件（含子目录）递回嵌入，路径以相对于嵌入目录的路径存储（如 `css/style.css`）
2. 路径分隔符统一为正斜杠 `/`（跨平台一致）
3. `fs.embed` 类型变数为只读，不参与堆释放
4. 适用於单二进制分发场景（如 HTTP 静态文件伺服器、CLI 工具嵌入资源）

#### 平台注解

平台注解是编译期过滤器，根据目标平台决定是否包含代码。使用**扁平化键**（如 `#{mac-arm64}`）同时指定 OS 与架构，无歧义，附加到紧随其后的宣告上。不匹配的代码完全不参与编译——不生成 LLVM IR，不进行类型检查。

**支援的平台键（6 种扁平组合）：**

| 键                | 匹配                         |
| ---------------- | -------------------------- |
| `#{linux-amd64}` | Linux x86_64               |
| `#{linux-arm64}` | Linux ARM64                |
| `#{win-amd64}`   | Windows x86_64             |
| `#{win-arm64}`   | Windows ARM64              |
| `#{mac-amd64}`   | macOS x86_64（Intel）        |
| `#{mac-arm64}`   | macOS ARM64（Apple Silicon） |

```no
#{mac-arm64}
print('running on macOS ARM64')

#{linux-amd64}
print('running on Linux x86_64')

#{win-amd64}
print('running on Windows x86_64')

; 平台特定的变数
#{mac-amd64, mac-arm64}
sep = '/'

#{win-amd64, win-arm64}
sep = '\\'

; 平台特定的函数
#{mac-arm64, mac-amd64}
greet = () {
    print('hello from mac')
}

#{linux-amd64, linux-arm64}
greet = () {
    print('hello from linux')
}

greet()
```

同一宣告上的多个键为 **OR** 关系——任一匹配即包含。因每个键已同时指定 OS 与架构，无需 AND 逻辑。

| 注解                          | 含义                                |
| --------------------------- | --------------------------------- |
| `#{mac-arm64}`              | 仅 macOS ARM64                     |
| `#{mac-amd64, mac-arm64}`   | macOS 任意架构                        |
| `#{linux-amd64, win-amd64}` | Linux x86_64 **或** Windows x86_64 |
| `#{mac-arm64, linux-arm64}` | macOS ARM64 **或** Linux ARM64     |

```no
; macOS 和 Linux（所有架构）都执行
#{mac-amd64, mac-arm64, linux-amd64, linux-arm64}
shared = () {
    print('unix-like')
}

; 仅 Windows x86_64
#{win-amd64}
reg-key = () {
    print('reading registry on win/x64')
}

; 仅 macOS ARM64（Apple Silicon）
#{mac-arm64}
neural = () {
    print('Apple Neural Engine available')
}
```

使用 `os.get-arch()` 可在执行期取得当前架构，使用平台注解则在编译期包含或排除代码。

## package.noml 编译器配置

`package.noml` 中的 `compiler` 区块控制编译器行为。`version` 值约定带前导 `v`（如 `"v0.1.0"`）；编译器内部解析时对前缀不敏感，`"v0.1.0"` 与 `"0.1.0"` 皆视为同一版本。

```noml
{
  compiler: {
    version: 'v0.1.0'
    emit: 'js'
  }
}
```

### `emit`

控制输出目标后端：

| 值           | 说明                                      |
| ----------- | --------------------------------------- |
| `""` （空，预设） | 使用 LLVM 后端生成原生可执行档                      |
| `"js"`      | 使用 JS 后端生成 JavaScript（型别擦除），无需 LLVM 工具链 |

设定为 `"js"` 后，`no build` 自动走 JS 后端，等效于命令列 `--js`。命令列旗标优先级高于配置文件。

```noml
; 自动生成 JavaScript
compiler: {
  emit: 'js'
}
```

### `anonymous-fn-type`

控制是否允许匿名函式型别语法（如 `cb ()()`）。预设 `false`（禁用），需使用具名函式型别别名。

### `link-libs`

指定连结的 C 函式库列表：

```noml
compiler: {
  link-libs: ['crypto', 'ssl']
}
```

## 编译期变数注入（-ld）

`no build`、`no run`、`no test` 支援通过 `-ld-KEY=VALUE` 旗标在编译期注入全域常量。注入的变数等同于在源码顶部声明 `KEY = VALUE`，可在程式中直接使用。

### 语法

```bash
no build -ld-KEY=VALUE [更多 -ld...] <file>
```

- `-ld` 前缀后紧跟变数名和值，用 `=` 分隔
- 多个 `-ld` 旗标可同时使用
- 布林简写：`-ld-DEBUG`（不含 `=VALUE`）等同于 `-ld-DEBUG=true`

### 值的型别推断

| 值的形式             | 推断型别            | 范例                  |
| ---------------- | --------------- | ------------------- |
| 整数               | `i64`           | `-ld-COUNT=42`      |
| 浮点数              | `f64`           | `-ld-PI=3.14`       |
| `true` / `false` | `bool`          | `-ld-DEBUG=true`    |
| 其他               | `str`（单引号字串字面量） | `-ld-VERSION=0.1.2` |

### 范例

```no
; 假设使用 -ld-VERSION=0.1.2 -ld-COUNT=42 -ld-DEBUG=true 编译
print('VERSION:', VERSION); 输出: VERSION: 0.1.2
print('COUNT:', COUNT); 输出: COUNT: 42
print('DEBUG:', DEBUG); 输出: DEBUG: 1 (bool 在原生后端印为 1)
```

```bash
; 注入多个变数
no build -ld-VERSION=0.1.2 -ld-COUNT=42 -ld-DEBUG=true main.no

; 布林简写
no run -ld-RELEASE main.no

; JS 后端也支援
no build --js -ld-VERSION=0.1.2 main.no
```

### 与源码声明的关系

`-ld` 注入的变数与源码声明的互动规则：

- **源码已有同名声明**：注入的值会**就地替换**源码中该变数的值。常用模式是在源码中声明占位变数（如 `VERSION = ''`），构建时用 `-ld-VERSION=0.1.2` 赋值。
- **源码中不存在**：注入的变数会被前置到 AST 最前面，作为新的全域常量宣告，参与所有后续编译 pass（型别推断、验证、模组合并、codegen）。
- **不注入时**：源码中的声明保持原样，不受影响。

```no
; 源码声明占位变数
VERSION = ''
COUNT = 0

print('VERSION:', VERSION)
print('COUNT:', COUNT)

; no build -ld-VERSION=0.1.2 main.no
; 输出: VERSION: 0.1.2  （注入值覆盖了源码的 ''）
;       COUNT: 0        （未注入，保持源码值）
```
