# Экспорт

Nolang использует ключевое слово `@` в файле `lib.no` в корне пакета для объявления экспортируемых элементов. Внешние пакеты при импорте через `#` могут обращаться только к этим экспортируемым символам.

> **Внимание**: `@` отвечает только за экспорт символов между пакетами Nolang и не создаёт символов C ABI. Чтобы C / C++ / Rust / Go / Java / Python / C# могли вызывать Nolang, используйте аннотацию `#{cabi='symbol'}` вместе с `no build --shared`, см. [Вызов Nolang из host-языков](./host-interop).

## Синтаксис

```no
@ path[.func]
[alias]
```

- `path` — путь модуля (относительно корня пакета или рабочего пространства, без расширения `.no`)
- `func` — необязательно. Экспортируемая функция/константа/перечисление; если опущено, экспортируется весь модуль
- `alias` — необязательный псевдоним при внешнем импорте; может содержать `/` (например `test/assert`)

## Правила

- Операторы экспорта **могут** находиться только в файле `lib.no` в корне пакета (единственное исключение — следующий раздел «Глобальные вызываемые псевдонимы»)
- По одному экспортируемому элементу на строку
- **Экспорт символа** `@ path.func [alias]`: экспортирует функцию, константу или перечисление из модуля
- **Экспорт модуля** `@ path [alias]`: экспортирует весь модуль. Псевдоним необязателен и по умолчанию равен последнему сегменту `path`, поэтому `@ /test/src/assert` эквивалентно `@ /test/src/assert assert`. Многосегментный псевдоним вида `@ /test/src/assert test/assert` позволяет импортировать модуль как `# test/assert`
- Экспорт модуля регистрирует только имя модуля, но не вызываемый псевдоним; он не может привязать тип к модулю (у типов нет уровня глобального имени)
- Структуры, перечисления и другие типы, на которые ссылается экспортируемая функция, **экспортируются автоматически**, ручное объявление не требуется
- Если экспортируемой функции не существует в модуле, LSP сообщит об ошибке

## Пример

```no
; lib.no — файл экспорта в корне пакета
@ /src/utils.greet a
@ /src/utils.hello b
@ /src/math.pi
```

```no
; src/utils.no
; определить экспортируемые функции
greet = (name str) {
    print('Hello, ' - name)
}

hello = () {
    print('Hi')
}
```

## Глобальные вызываемые псевдонимы

Та же запись, сделанная в **`std/global.no`** (а не в `lib.no` какого-то пакета), имеет иной смысл:
она не фильтрует экспорт, а объявляет **глобальное второе имя, которое можно вызывать**. Голое имя `<alias>` просто *является* `func` модуля `path` — эффект полностью совпадает с записью `<path>.<func>(...)`.

```no
; std/global.no — две записи, одинаковая семантика
@ std/err.new err; в форме экспорта
err = err.new; в форме присваивания
```

```no
e = err('disk full', code.io); эквивалентно e = err.new('disk full', code.io)
m = e.msg(); 'disk full'
```

Правила:

- Только `std/global.no` обладает этим смыслом; `@` в `lib.no` по-прежнему является фильтром экспорта
- Обе записи **эквивалентны**, компилятор нормализует их к одному объявлению; одновременная запись обоих вариантов не создаёт конфликта
- Форма присваивания действует **только в `global.no`**. В обычной программе `x = mod.fn` — это переменная, хранящая значение функции (которую можно использовать для косвенного вызова), а не глобальный псевдоним
- Правой частью формы присваивания должно быть голое обращение `<модуль>.<функция>`: не вызов, не литерал, не чтение поля и не связывание с типом. если целевое значение не является функцией, объявление просто не действует (объявления констант вроде `PI = math.PI` не затрагиваются)
- Псевдоним действует только в позициях **вызова по голому имени**. Квалифицированные вызовы не затрагиваются: `io.err(...)` по-прежнему является средством записи в stderr модуля `io` и не перехватывается псевдонимом `err`
- Вызов модулем собственной одноимённой функции также не затрагивается (исключение для собственного модуля)
- **Список параметров** псевдонима берётся из целевой функции; **тип результата** определяется в точке вызова целевой функцией
- Псевдоним не конфликтует с вариантом `err` встроенного option: в позициях, где ожидается тип `?T` (`x = err('m')` после `x ?i64`, ветка match `err ->`, функция, возвращающая `?T`), `err(...)` по-прежнему является конструктором варианта err для option (tag 2)

## Импорт экспортируемых символов

Внешние пакеты при импорте через `#` могут обращаться только к элементам, объявленным в `lib.no`:

```no
; импортировать псевдоним a (соответствует package-name.utils.greet)
# package-name.utils.greet a
; или использовать имя функции напрямую
# package-name.utils.greet
```

## Поддержка LSP

- **Переход к определению**: щелчок по имени экспортируемой функции или псевдониму в `lib.no` ведёт к определению в соответствующем файле модуля
- **Автодополнение**: при вводе `@` и пути автоматически предлагаются доступные пути к файлам и имена функций
- **Диагностика ошибок**: показывается ошибка, если экспортируемой функции не существует в модуле
