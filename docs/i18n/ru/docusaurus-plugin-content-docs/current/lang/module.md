# Префиксы при вызове между модулями

Nolang использует обязательное соглашение об именровании модулей: при вызове в файле `.no` функций или констант, определённых в **другом модуле** (другом файле `.no`), необходимо использовать префикс `ShortName.`. Это исключает конфликты имён между модулями.

Модули стандартной библиотеки загружаются компилятором автоматически, **их не нужно импортировать явно** (аннотация `# std/...` не требуется) — достаточно сразу использовать префикс `ShortName.`. `no fmt` автоматически удаляет все чистые std-импорты модулей без псевдонима (например, `# std/noml`, `# std/math`, `# std/fmt`); псевдоним (`# std/noml n`) или импорт функции (`# std/math.sqrt`) сохраняется (подробнее см. [Стиль кода · автоматическая упорядочка операторов импорта](./code-style#автоматическая-упорядочка-операторов-импорта-дедупликация--удаление-std-импортов-без-псевдонима--сортировка)).

> **Зависимости и разрешение путей**: ключ зависимости локального пакета может отображаться в короткое имя или полный URL через `workspace.noml`. Подробнее см. [Типы зависимостей и правила версий](../usage#依賴類型與版本號規則).

## Определение ShortName

ShortName — это последний сегмент пути модуля, используемый как префикс при вызове между модулями.

| Путь файла | FullPath | ShortName | Описание |
| --- | --- | --- | --- |
| `std/math.no` | `math` | `math` | файл верхнего уровня |
| `std/fs.no` | `fs` | `fs` | файл верхнего уровня |
| `std/net/net.no` | `net/net` | `net` | последний сегмент пути |
| `std/net/client.no` | `net/client` | `client` | последний сегмент пути |
| `std/crypto/sha256.no` | `crypto/sha256` | `sha256` | последний сегмент пути |
| `std/archive/gzip.no` | `archive/gzip` | `gzip` | последний сегмент пути |

ShortName — это последний сегмент FullPath после разделения косой чертой (например, `crypto/sha256` → `sha256`).

## Когда префикс нужен

При вызове модульных функций или констант, определённых в другом модуле, необходимо использовать префикс `ShortName.`.

```no
; модульная функция
sha256.sha256(data)
sha256.sha256-hex(data)
fs.open(path, opts)
gzip.gzip-decompress(data)
math.pow(x, y)

; модульная константа
net.NET-BUF-SIZE
math.PI
```

### Соглашение об именовании функций

**Не добавляйте префикс имени модуля к имени функции.** Функции внутри модуля должны иметь короткие и понятные имена, а префикс `ShortName.` при вызове из другого модуля сам добавит информацию о модуле.

```no
; ✅ правильно: короткое имя функции без префикса модуля
; tail.no
; входная функция называется просто именем модуля
tail = () {
    ...
}

; вспомогательная функция — короткое имя
atoi = (s str) (v i64) {
    ...
}
```

```no
#{fmt-skip}
; ❌ избегайте: избыточный префикс имени модуля в имени функции
; tail-run = () { }
; tail-atoi = (s str) (v i64) { }
```

То же соглашение сохраняется и при импорте между модулями:

```no
; ✅ коротко и понятно
# /src/tail.tail
# /src/mktemp.mktemp
```

```no
#{fmt-skip}
; ❌ избыточно
; # /src/tail.tail-run
; # /src/mktemp.mktemp-run
```

> **Избегайте ключевых слов**: `awy` (ключевое слово группы сопрограмм), `match` (ключевое слово сопоставления с образцом) и т. п. нельзя использовать как имена функций. `run` удалён и может быть обычным идентификатором. Входной функции рекомендуется давать имя самого модуля (например, `ping.no` → `ping`).

## Когда префикс не нужен

В следующих случаях префикс не требуется:

### 1. Глобальные функции (`with-cap` / `with-len` / `with-cap-len` / `print` / `eprint` / `format` / `exit`)

Эти 7 функций — встроенные глобальные функции языкового уровня, их можно использовать напрямую, без префикса модуля. Их объявления-комментарии собраны в `std/global.no`, чтобы разработчикам было удобно с ними ознакомиться.

**Конструкторы ёмкости/длины:**

- `with-cap(cap)` — создать строку или срез заданной ёмкости (len=0), тип выводится из левой части присваивания
- `with-len(len)` — создать строку или срез заданной длины
- `with-cap-len(cap, len)` — создать строку или срез заданной ёмкости и длины

**Вывод/форматирование:**

Nolang использует синтаксис **именованных строк формата** `{name[:spec]}`, которые ссылаются на переменные из области видимости напрямую, без позиционных аргументов. Поддерживается проверка на этапе компиляции. Вывод идёт непосредственно через системные вызовы `io.out`/`io.err` и не зависит от libc `printf`.

- `print(s)` / `print(s0, s1, ...)` — вывод в стандартный поток, аргументы разделены пробелами, **автоматический перевод строки**
- `eprint(s)` / `eprint(s0, s1, ...)` — вывод в стандартный поток ошибок, аргументы разделены пробелами, **автоматический перевод строки**
- `format(s)` — возвращает отформатированную строку (заменяет `sprintf`), без автоматического перевода строки

**Управление процессом:**

- `exit(code)` — завершить процесс с кодом состояния (было `os.exit`, теперь повышено до встроенной глобальной функции, префикс `os.` не нужен)

**При нескольких аргументах литералы по умолчанию являются шаблонами, а не строками формата в стиле C.** В `print('result={val}', 42, 'result={val}')` каждый строковый литерал **сам по себе** является шаблоном: его `{val}` берётся из **области видимости точки вызова** и не связан с другими аргументами того же вызова. Литерал **не** описывает и не поглощает последующие аргументы — это не подстановка, как в `printf('%d', 42)`. Нелитеральные аргументы (переменные, выражения) обрабатываются как обычные вариадические аргументы, разделяются пробелами, и в конце всей строки стоит только один перевод строки.

```no
val = 42
print('result={val}', 42, 'result={val}'); result=42 42 result=42
tmpl = '{val}'
print(tmpl); {val} — переменная — это обычный текст, подстановки нет
print('a={val}', val); a=42 42
```

`format(s)` и устаревший `sprintf(s)` по-прежнему принимают только **одну строку формата**, вариадической формы у них нет.

> `printf`, `eprintf` **удалены**: имена остались в таблице символов (вызовы по-прежнему разрешаются, редактор продолжает дополнять),
> но **любой вызов — жёсткая ошибка компиляции** (`[printf-depr]`), а сообщение напрямую направляет на миграцию. `sprintf` ещё работает, но **устарел**.
> Соответствия такие:
> - `printf(s)` → `print(s)` (с переводом строки) или `io.out(s)` (без перевода строки, стандартный вывод)
> - `eprintf(s)` → `eprint(s)` (с переводом строки) или `io.err(s)` (без перевода строки, stderr)
> - `sprintf(s)` → `format(s)` (возвращает отформатированную строку)
>
> `io.out`/`io.err` — низкоуровневые команды, вывод **без перевода строки**. Поскольку модульный вызов требует имени модуля, `io.err` явно несёт префикс модуля и не конфликтует с конструктором Option `err()`; даже при совпадении имён префикс модуля их различает.

```no
; конструкторы ёмкости/длины (без префикса)
s str = with-cap(256); ✅ предварительно выделить str на 256 байт
v []i64 = with-cap(100); ✅ предварительно выделить срез на 100 элементов
v []i64 = with-cap-len(200, 100); ✅ ёмкость 200, длина 100
v []i64 = with-len(100); ✅ срез длиной 100

; вывод/форматирование (без префикса)
print('hello {n}'); ✅ автоматический перевод строки
print(a, b, c); ✅ несколько аргументов, разделены пробелами, с переводом строки
print('x={n}', n); ✅ литерал — шаблон, переменная — значение
print('result={val}', 42, 'result={val}'); ✅ каждый литерал подставляется отдельно
print(); ✅ нет аргументов — только перевод строки
s = format('x={x}'); ✅ возвращает отформатированную строку (одна строка формата)
eprint('err: {n}'); ✅ вывод в stderr с переводом строки
eprint('err:', a, b); ✅ несколько аргументов, в stderr через пробел
print('編號 {id:06} 金額 {money:.2f}'); ✅ поддержка выравнивания, заполнения, ширины, точности

; низкоуровневые команды (требуют префикс модуля)
io.out('no-newline-here'); ✅ вывод без перевода строки (заменяет printf)
io.err('err-no-newline'); ✅ stderr без перевода строки (заменяет eprintf)

; все остальные межмодульные вызовы требуют префикса
fs.open(path, opts); ✅ с префиксом (даже для builtin)
```

#### Спецификаторы формата

В `{name[:spec]}` поле `spec` поддерживает следующие компоненты (порядок фиксирован, все необязательны):

```
[[fill]align][sign][#][0][width][.precision][type]
```

- `fill` — символ заполнения (по умолчанию пробел), используется только вместе с `align`
- `align` — `<` выравнивание по левому краю, `>` по правому, `^` по центру
- `sign` — `+` показывать знак плюс для положительных, `-` только для отрицательных (по умолчанию)
- `#` — префикс системы счисления (`0x`/`0o`/`0b`)
- `0` — дополнение числа нулями слева до заданной ширины
- `width` — минимальная ширина поля
- `.precision` — число знаков после запятой для чисел с плавающей точкой / длина обрезки строки
- `type` — `d`(целое), `x`/`X`(шестнадцатеричное), `o`(восьмеричное), `b`(двоичное), `c`(символ), `f`(с фиксированной точкой), `e`/`E`(научная нотация), `g`/`G`(общий), `s`(строка, по умолчанию), `t`(имя типа данных, определённое на этапе компиляции), `v`(значение литерала: строка в одиночных кавычках, vec вызывает to-str)

```no
x i64 = 42
u u64 = 255
pi f64 = 3.14159
s str = 'hello'
print('{x:06}'); 000042
print('{x:>10}'); выравнивание по правому краю, ширина 10
print('{u:#x}'); 0xff
print('{pi:.2f}'); 3.14
print('{pi:8.3e}'); 3.142e+00
print('{s:<10}'); hello     (по левому краю)
print('{s:.3}'); hel (обрезано до 3 символов)
print('{x:t}'); i64 (выведено имя типа переменной x)
print('{s:v}'); 'hello' (строка взята в одиночные кавычки)
```

`{{` и `}}` используются для вывода литеральных `{` и `}`, но **только если в той же строке есть хотя бы одно настоящее поле `{name}`**. Литерал, содержащий лишь экранирование и не содержащий полей, выводится как есть: `print('{{n}}')` выведет `{{n}}` (а не `{n}`), `print('{{')` выведет `{{`. Чтобы вывести отдельную фигурную скобку, просто используйте `print('{')` / `print('}')`.

### 2. Определения в том же файле

Функции, константы и методы, определённые в том же файле `.no`, используются напрямую, без префикса.

```no
; в sha256.no:
sha256(data); sha256 определён в этом файле

; константа определена в этом файле
HMAC-BLOCK-SIZE
```

### 3. Методы встроенных типов

Методы встроенных типов (`str`, `i64`, `vec`, `arr`, `byte`, `char`, `bool` и др.) не требуют префикса. Методы встроены в тип и разрешаются через тип получателя.

```no
'hello'.starts-with('he'); метод str
n.to-str(); метод int
v.push(42); метод vec
a.contains(3); метод arr
c.is-digit(); метод char
```

### 4. Методы экземпляра структуры

Для вызова методов уже созданного экземпляра структуры префикс модуля не нужен. Метод разрешается через тип экземпляра, компилятор автоматически находит соответствующее определение `struct.method`.

```no
f = fs.open(path, opts); fs.open — модульная функция, префикс нужен
f.read(buf, n); file.read — метод структуры, префикс не нужен
f.close(); file.close — метод структуры, префикс не нужен

p = path {
    p: '/tmp'
}
p.exists(); path.exists — метод структуры, префикс не нужен
```

## Вызов метода против вызова модульной функции

Требуется ли префикс при вызове метода, зависит от **владельца метода**:

- **методы встроенных типов** (`str.starts-with`, `i64.to-str` и др.) — префикс не нужен
- **методы экземпляра структуры** (`f.read`, `p.exists` и др.) — префикс не нужен
- **модульные функции** (`fs.open`, `sha256.sha256` и др.) — **префикс нужен**

В `fs.fil()` `fs` — это ShortName модуля, а `fil` — имя модульной функции. Префикс `fs.` нельзя опустить, потому что `fs` здесь не имя переменной, а путь модуля.

### Два смысла записи `Name.Function`

Записи `process.cmd(...)` и `p.start(...)` обе имеют вид `xxx.yyy()`, но их семантика полностью различна:

| Запись | `xxx` | `yyy` | Семантика |
| --- | --- | --- | --- |
| `process.cmd(...)` | ShortName модуля | модульная функция | `xxx` — путь модуля, `yyy` — отдельная функция, определённая в этом модуле |
| `p.start(...)` | переменная-экземпляр | метод структуры | `xxx` — переменная типа `process`, `yyy` — метод, определённый как `process.start = ...` |

**Разница при определении**:
- модульная функция при определении **не имеет префикса**: внутри модуля просто пишем `cmd = (program str, ...) { }`
- метод структуры при определении **обязательно имеет префикс `struct.`**: `process.start = (program str, ...) { }`

**Разница при вызове**:
- модульная функция вызывается извне как `ModuleName.function()`: `process.cmd(...)`
- метод структуры вызывается через экземпляр: `p = process.new()` → `p.start(...)`

> **Внимание**: даже внутри модуля вызов модульной функции того же модуля не имеет префикса (`cmd(...)`), а вызов метода структуры идёт через неявное `self` или синтаксис `.method()`.

## Ссылки на типы из других модулей

При ссылке на типы (структуры, интерфейсы, перечисления и т. д.), определённые в **другом модуле**, необходимо использовать префикс `ShortName.`. Это относится к следующим случаям:

### Структура реализует интерфейс

Когда структура реализует интерфейс, определённый в другом модуле, имя интерфейса должно нести префикс модуля:

```no
#{fmt-skip}
; ❌ ошибка: db, rows, stmt — интерфейсы, определённые в модуле sql, префикс нельзя опускать
db-mysql db {
    fd i64
}
```

```no
; ✅ правильно: использовать sql.db, sql.rows, sql.stmt
db-mysql sql.db {
    fd i64
}

rows-mysql sql.rows {
    fd i64
}

stmt-mysql sql.stmt {
    fd i64
}
```

### Параметры и типы возврата функций

Межмодульные типы в сигнатуре функции также требуют префикса:

```no
; ✅ правильно: тип возврата использует sql.result
db-mysql.exec = (sql str) (r sql.result) {
    ...
}
```

### Типы полей структуры

```no
; ✅ правильно: тип поля использует sql.connection
conn-mysql sql.db {
    handle sql.connection
}
```

### Случаи, когда префикс не нужен

- **типы, определённые в том же модуле**: структуры, интерфейсы и перечисления, определённые в том же файле `.no`, используются по имени типа напрямую
- **встроенные типы**: `str`, `i64`, `bool`, `byte` и другие встроенные типы не требуют префикса
- **встроенные интерфейсы**: `enter`, `leave` и другие встроенные в язык интерфейсы не требуют префикса

```no
; типы, определённые в том же файле, префикс не нужен
result {
    last-id i64
    affected i64
}

; enter/leave — встроенные интерфейсы, префикс не нужен
; result — структура, определённая в том же файле, префикс не нужен
db {
    enter
    leave
    close() (ok bool)
    exec(sql str) (r result)
}
```

## Полный пример

```no
; модули стандартной библиотеки загружаются автоматически, явный импорт не нужен

; ─── префикс НЕ нужен ───

; глобальные функции (объявлены в global.no)
s str = with-cap(256)
v []i64 = with-len(100)
print('hello {n}')
s = format('x={x}')

; функция из того же файла
sha256(data)

; методы встроенных типов
'hello'.starts-with('he')
n.to-str()
v.push(42)

; методы экземпляра структуры
f = fs.open(path, opts)
f.read(buf, n)
f.close()

; ─── префикс НУЖЕН ───

; модульные функции
sha256.sha256(data)
sha256.sha256-hex(data)
fs.open(path, opts)
gzip.gzip-decompress(data)
math.pow(x, y)

; модульные константы
net.NET-BUF-SIZE
math.PI

; ссылки на типы из других модулей (реализация интерфейса, тип параметра, тип возврата, тип поля)
db-mysql sql.db {
    fd i64
}

r sql.result = d.exec('CREATE TABLE ...')
```
