# Соглашение о разрешении путей: относительно корня рабочей области (Workspace-Root-Relative)

## Соглашение (принято)

Все **embed-пути** и **пути импорта** (директивы `use` / `#`, embed-ресурсы) разрешаются в **канонический абсолютный путь относительно корня рабочей области** — они **больше не разрешаются относительно «каталога текущего исходного файла»**.

- «Корень рабочей области» (workspace root) — каталог, содержащий `workspace.noml`, то есть `pkg.WorkspaceRoot()`.
  Обратите внимание: каталог, содержащий `package.noml`, является **корнем пакета** (`pkg.RootDir`); это разные уровни — корень рабочей области находится выше (содержит `workspace.noml`, может содержать несколько пакетов), а корень пакета — это каталог конкретного **пакета** (содержит `package.noml`), в котором находится несколько **модулей** (исходных файлов `.no`). Не путайте их.
- После разрешения выполняется канонизация (`filepath.Clean`, удаление `.`/`..`, унификация разделителей), в результате чего получается **глобально уникальный** канонический путь, который служит единственным идентификатором для загрузки модулей, ключей кэша и принадлежности AST/семантики.
- Этот канонический путь является **компонентой пути** ключей кэша `lexer.tokenCache` и `checker.parseProgramFileCache`. Фактически ключ кэша — составной `(канонический путь, хэш содержимого)` (`cache.Key`, см. `src/cache/lru.go`): тот же путь, но изменённое содержимое → другой хэш → автоматическая инвалидация; устаревшие токены/AST больше не возвращаются. Кэш имеет ограниченный размер LRU, поэтому долгоживущие процессы (LSP / fmt) не испытывают утечки памяти (пункт ③ из оригинального аудита архитектуры в два прохода).

## Почему

1. **Устраняем коллизии ключей кэша в корне**. Старым ключом кэша токенов/AST была «строка пути»; когда разные исходные файлы импортировали/встраивали с одинаковой относительной строкой (например, `utils/no` или embed-имя `data.json`), они попадали в одну запись кэша → взаимное заражение, неверные токены/AST. После перехода на канонические абсолютные пути относительно корня рабочей области **каждый логический файл имеет уникальный ключ; один и тот же файл всегда отображается в один и тот же ключ**, и коллизии исчезают конструктивно (пункт ④ из оригинального аудита архитектуры в два прохода).
2. **Существенное упрощение и повышение надёжности логики компилятора**. Разрешение путей сводится от «разбросанного по parser / transpiler / checker разрешения относительно текущего файла» к **единому шагу канонизации**; прямые ссылки, загрузка модулей, ключи кэша и пути в диагностике используют одну и ту же базу и больше не зависят от расположения импортирующего файла.
3. **Прокладываем путь к кэшированию между файлами и параллельной сборке**. Канонические абсолютные пути делают ключи кэша стабильными и глобально сравнимыми, что упрощает будущее повторное использование deep-clone (избегание дублирования `ParseProgram`) и оптимизации ленивого разрешения.

## Границы применимости

- **Абсолютные пути** (локальные модули, начинающиеся с `/`): уже разрешены относительно корня рабочей области, без изменений.
- **Модули `std/`**: поступают из встроенного `StdFS`, ключ имеет вид `std/<rel>.no`; без изменений, никогда не смешиваются с локальными путями.
- **Embed-ресурсы**: независимо от относительного имени, используемого для ссылки, внутренне нормализуются в канонический embed-ключ относительно корня рабочей области.

## Реализовано (Implemented, 2026-08-02)

Единые вспомогательные функции находятся в `src/package/paths.go` (пакет `pkg`, только стандартная библиотека, без циклических зависимостей):

- `FindWorkspaceRoot(start)`: поднимается от `start` вверх в поисках каталога, содержащего `workspace.noml`.
- `FindPackageRoot(start)`: поднимается от `start` вверх в поисках каталога, содержащего `package.noml` (резервный вариант при отсутствии рабочей области).
- `ResolveToWorkspaceRoot(wsRoot, rel)`: нормализует произвольный путь импорта/embed в абсолютный путь относительно корня рабочей области (удаляет ведущий `/`; абсолютные пути возвращаются как есть; при пустом `wsRoot` используется текущий каталог).
- `ResolveEmbedBase(sourcePath)`: база разрешения для относительных embed-путей — предпочтительно корень рабочей области, с откатом на корень пакета / каталог исходного файла.

Объединённые точки входа:

- `src/build/transpiler.go` `resolveUse`: ветка A (`/`-префикс) и ветка E (alias) объединены в `pkg.ResolveToWorkspaceRoot(t.workspaceRoot(), path)`, добавлен метод `t.workspaceRoot()` (предпочитает `pkg.WorkspaceRoot()`, иначе поднимается от `sourcePath` в поисках `workspace.noml`). Старая избыточная логика `if t.pkg != nil { baseDir = pkg.RootDir; if wsRoot... }` удалена; резервный вариант относительно cwd теперь использует `FindWorkspaceRoot`.
- `src/build/transpiler.go` `processEmbeds`: относительные embed-пути теперь используют `pkg.ResolveEmbedBase(sourcePath)` (предпочтительно корень рабочей области).
- `src/checker/checker.go` `ValidateEmbedAnnotations`: пути проверки embed также используют `pkg.ResolveEmbedBase`.

Ключи кэша (`tokenCache` / `parseProgramFileCache`) получают канонический абсолютный путь относительно корня рабочей области в качестве компоненты пути через `resolveFile(filePath)`; объединяясь с хэшем содержимого исходного файла в составной ключ (`cache.Key`), они обеспечивают конструктивное исчезновение коллизий, автоматическую инвалидацию при изменении файла по тому же пути и ограниченный LRU, предотвращающий утечки памяти.

Встроенные модули `std/` и `js/` по-прежнему используют `StdFS`/`JsFS` (ключ вида `std/<rel>.no` / `js/<rel>.no`) и не затрагиваются; `processEmbeds` применяется только к основной программе (пользовательскому исходному коду) — собственные embed-ресурсы модулей std по-прежнему разрешаются относительно их собственного расположения.

> Статус: **реализовано (2026-08-02)**. Новый код должен напрямую использовать `pkg.ResolveToWorkspaceRoot` / `pkg.ResolveEmbedBase`; **не** используйте «каталог текущего файла» (`filepath.Dir(t.sourcePath)` и т. п.) для относительного разрешения.

## Словарь терминов (унифицировано, 2026-08-02)

- **workspace (рабочая область)** — обычно соответствует одному репозиторию. Корневой каталог содержит `workspace.noml`; может содержать несколько пакетов. Корень рабочей области — единственная база для разрешения всех embed-путей и путей импорта.
- **package (пакет)** — крупная единица компиляции: одна библиотека или один исполняемый файл. Корневой каталог содержит `package.noml` (**корень пакета**). Объявляет зависимости, бэкенд генерации и т. д. Пакет содержит несколько модулей.
- **module (модуль)** — обычно один исходный файл (`.no`). Текущее соглашение: **один файл = один модуль**. Загрузить модуль = загрузить файл `.no`.

Иерархия: **рабочая область ⊃ пакет (один или несколько) ⊃ модуль (один или несколько)**. Не используйте «module» в значении «package» (единица компиляции) — это роль «package».
