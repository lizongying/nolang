## Обмен данными

### json — разбор и генерация JSON

`json` хранит дерево JSON в **пуле узлов, выделенном в куче** (`json-pool`), поддерживая вложенные массивы и объекты, скаляры string/number/bool/null, escape-последовательности и числа в экспоненциальной записи. Пул использует динамический `vec` и **не имеет фиксированного ограничения ёмкости** — общее число узлов и число дочерних элементов одного узла ограничены только доступной памятью. Высокоуровневый интерфейс инкапсулирует пул и индекс корневого узла в структуре `json`; её поле `pool` помечено `#{inline=false}` (поле-указатель), что позволяет безопасно возвращать и копировать `json` по значению.

```no
; Разбор: возвращает ?json (ok=успех, err=ошибка с указанием причины)
j = json.parse('{"name":"Alice","age":30,"items":[1,2,3],"active":true}')
j: {
    ok -> {
        name = it.get-str('name'); получение скаляра: get-str / get-num / get-bool / get-i64 (?значение)
        age = it.get-i64('age'); получение целого (?i64)
        items = it.get('items'); получить дочерний узел, возвращает ?json
        s = it.stringify(); сериализовать обратно в строку
    }

    err(e) -> print(e)
}

; Создание: начиная с пустого json, добавляем set / arr-push
j2 = json.new()
j2.set-str('key', 'value')
j2.set-i64('count', 3)
j2.arr-push-str('a')
print(j2.stringify())
```

**Высокоуровневый API (структура `json`)**

- `json.new()` — создать пустой (null) `json`
- `json.parse(s)` — разобрать, возвращает `?json`; при ошибке ветка `err` содержит конкретную причину (`empty input` / `parse error` / `trailing characters`)
- `j.stringify()` — сериализовать в строку
- Чтение: `j.get-str(key)` / `j.get-num(key)` / `j.get-bool(key)` / `j.get-i64(key)` (каждый возвращает `?value`); `j.get(key)` возвращает дочерний узел `?json`
- Прямой доступ к скаляру (если корень — скаляр): `j.str()` / `j.num()` / `j.bool()` / `j.i64()` / `j.str-val()`
- Запись: `j.set-str(key,val)` / `j.set-num` / `j.set-i64` / `j.set-bool` / `j.set-null` / `j.set-key(key, val json)`
- Массив: `j.arr-get(i)` / `j.arr-len()` / `j.arr-push(val json)` / `j.arr-push-str` / `j.arr-push-num` / `j.arr-push-bool`
- Перебор объектов: `j.obj-len()` / `j.obj-key(i)` / `j.obj-keys-str()` / `j.delete-key(key)`
- Проверка типа: `j.kind()` и `j.is-null()` / `j.is-obj()` / `j.is-arr()` / `j.is-str()` / `j.is-num()` / `j.is-bool()`

**Ёмкость пула (без фиксированного предела)**

В ранних версиях пулом служил массив фиксированного размера с жёсткими лимитами `JSON-MAX-NODES = 128` / `JSON-MAX-CHILDREN = 32`, при превышении которых молча возникала ошибка. Теперь пул полностью переведён на кучевой `vec`:

- Общее число узлов и число дочерних элементов на узел **не имеют ограничений**, кроме доступной памяти.
- `json.parse` возвращает `err` только при настоящей синтаксической ошибке; ветки «пул исчерпан» больше нет.
- `j.set*` / `j.arr-push*` возвращают `false` только при несоответствии целевого типа (например, set для узла не-объекта или push для узла не-массива). `j.overflowed()` сохранён для обратной совместимости и теперь всегда возвращает `false`.

> **Семантика копирования `json` (`#{inline=false}`)**: `pool` — поле-указатель, поэтому дочерний узел `json`, возвращаемый `j.get` / `j.arr-get`, **глубоко копирует** весь пул и является независимым снимком родительского пула — запись в снимок не распространяется обратно на родительский узел. Кроме того, поскольку `?json` (option) при `match` потребляет своё значение, **повторный `match`** одного и того же option приведёт к ветке `nil`; если нужно несколько раз выполнять операции с одним результатом разбора, сделайте это в рамках одного `match` или сначала сохраните `it` в локальную переменную `json`.

**Низкоуровневый API (`json-pool` / `json-value`)**

Операции напрямую по индексам узлов; пул используется как локальная переменная (одноуровневая структура безопасно возвращается и копируется по значению):

- `p = json.new-pool()`; либо `p = json-pool {}`, затем `p.init()` (инициализирует каждый vec `nodes`/`strs`/`ec`/`ek`/`en` через `with-len(0)`)
- `idx = p.alloc()` — выделить новый узел и вернуть индекс (кучевой vec автоматически расширяется)
- `p.add-child(node-idx, child-idx, key)` — добавить дочерний элемент через список рёбер (`ec`/`ek`/`en` — односвязные списки), без ограничения на узел
- `node-idx, next-pos, ok = p.parse(s, pos)` — разобрать одно значение начиная с `pos`, вернуть индекс узла
- `val-idx = p.get-key(obj-idx, key)` (`?i64`); `p.arr-get(arr-idx, i)` (`?i64`); `p.arr-len(arr-idx)`
- `p.get-kind(idx)` / `p.get-str(idx)` / `p.get-num(idx)` / `p.get-bool(idx)`
- `p.set-key(obj-idx, key, val-idx)`; `p.copy-tree(src, idx)` (рекурсивное глубокое копирование поддерева)
- `p.stringify(node-idx)` — сериализовать указанный узел

### toml — разбор и генерация TOML 1.0

`toml` хранит документ TOML в `toml`, поддерживая комментарии, ключи bare/quoted/dotted, обычные таблицы, array-of-tables, строки basic/literal/multiline, целые в различных системах счисления, числа с плавающей точкой, логические значения, даты и время, массивы и inline table. Значения, для которых нет отдельного типа Nolang, сохраняются в виде исходных литералов.

```no
cfg = toml.parse('title = "Nolang"\n[server]\nport = 8080\n[[server.backends]]\nname = "local"')

doc = toml.new()
doc.put('name', '"nolang"')
doc.put('server.port', '8080')
doc.put('enabled', 'true')
raw = toml.get(doc, 'server.port')
text = toml.stringify(doc)
```

Часто используемые функции:

- `toml.new()` — создать пустой документ
- `toml.parse(text)` — разобрать и вернуть `?toml`
- `doc.put(key, raw-value)` — проверить и добавить/обновить значение TOML
- `get(doc, key)` — получить исходное значение
- `get-str`, `get-i64`, `get-f64`, `get-bool` — получить скалярное значение
- `toml.stringify(doc)` — сериализовать документ

Ограничения документа: 4 ключа, 2 обычные таблицы, 2 array-of-tables; ключ — не более 32 bytes, значение — не более 128 bytes.

### yaml — разбор и генерация YAML 1.2

`yaml` хранит дерево документа YAML 1.2 (core schema) в пуле узлов (`pool`), поддерживая блочные отображения, блочные последовательности, потоковые коллекции (`[...]` / `{...}`), скаляры в одиночных/двойных кавычках и plain, блочные скаляры (`|` / `>` с chomping `-` / `+`), комментарии, маркеры документа (`---` / `...`) и несколько документов, якоря (`&`) и псевдонимы (`*`), ключ слияния `<<`, явные ключи (`? k`), вывод типов (null / bool / int / float / `.inf` / `.nan`), запросы по точечному пути, а также сериализацию в JSON / YAML.

```no
doc ?yaml = yaml.parse('name: Alice\nserver:\n  port: 8080\ntags:\n  - a\n  - b\n')
doc: {
    nil -> print('nil')

    err -> print(it.msg())

    -> {
        doc = it
        name = doc.find-str('name'); ?str
        port = doc.find-i64('server.port'); ?i64
        name: {
            ok -> print(it)

            -> print('')
        }
        port: {
            ok -> print(it.to-str())

            -> print('')
        }
        print(doc.to-json())
        print(doc.to-yaml())
    }
}
```

Часто используемые функции и методы:

- `yaml.parse(text)` / `yaml.parse-all(text)` — разобрать, вернуть `?yaml` (ветка `err` содержит позицию `line L, column C`)
- `yaml.valid-of(text)` / `yaml.error-of(text)` — только проверить, не создавая документ
- `yaml.strip-bom(text)` — удалить UTF-8 BOM
- `doc-count()` / `doc(i)` — доступ к нескольким документам
- `kind()`、`is-null()`、`is-bool()`、`is-int()`、`is-float()`、`is-nan()`、`is-str()`、`is-seq()`、`is-map()`、`len()`、`text()`、`tag()`、`anchor()`、`line-of()` — информация об узле
- `str()`、`i64()`、`f64()`、`bool()`、`scalar-text()` — получение значения, всегда возвращают `?value`
- `at(i)`、`value(i)`、`key(i)`、`key-node(i)`、`get(key)`、`find(path)` — дочерние узлы / ключи
- `get-str` / `get-i64` / `get-f64` / `get-bool`、`find-str` / `find-i64` / `find-f64` / `find-bool` — удобные методы получения
- `to-json()`、`to-json-all()`、`to-yaml()`、`stringify()`、`source-of()` — сериализация

Константы типов узлов: `YAML-KIND-NULL` / `BOOL` / `INT` / `FLOAT` / `STR` / `SEQ` / `MAP` (0–6); константы стиля скаляра `YAML-STYLE-PLAIN` / `SINGLE` / `DOUBLE` / `LITERAL` / `FOLDED` / `ALIAS` (0–5) и `YAML-STYLE-BLOCK` / `FLOW` (6–7).

> **Замечание первое**: дочерние представления возвращаются как `?yaml`, а вспомогательные функции получения значения — как `?value`; распаковывайте их через match (`child = d.at(i)`, где ветка `ok` связывает `it` с дочерним узлом, а ветка по умолчанию обрабатывает отсутствие значения; каждая ветка на отдельной строке). Дочерний узел разделяет пул узлов с родительским документом, поэтому рекомендуется завершать получение значений в том же match или сначала привязать значение к переменной и не удерживать устаревший дескриптор при последующих изменениях пула. Для получения значений всегда рекомендуется использовать удобные функции для работы с путями, такие как `find-str` / `find-i64`.
>
> **Замечание второе**: во вложенных match `it` восстанавливается **по уровням**. Ветка внутреннего match заново связывает `it` со своим субъектом (тело ветки должно видеть внутреннее значение), но как только эта ветка завершается, `it` возвращается к субъекту охватывающей ветки, поэтому следующая запись безопасна:
>
> ```no
> d ?yaml = yaml.parse(src)
> d: {
>     nil -> print('nil')
>
>     err -> print(it.msg())
>
>     -> {
>         print(it.find-str('a'))        ; внешний it = документ
>         v ?yaml = it.at(0)
>         v: {
>             nil -> print('none')
>             err -> print('err')
>             -> print(it.find-str('b')) ; внутренний it = дочерний узел
>         }
>         print(it.find-str('c'))        ; ✅ it снова равен документу
>     }
> }
> ```
>
> Единственное исключение — самый внешний match: после его завершения `it` сохраняет значение последней ветки (не восстанавливается), поэтому не полагайтесь на `it` вне match. Если нужно использовать значение через несколько уровней, всё же явно сохраните его в именованную локальную переменную (`doc = it`) или используйте связывание через деструктуризацию `ok(v) -> ...`.
>
> **Замечание третье**: `.nan` разбирается в настоящее NaN (`f64()` возвращает NaN, `x != x` истинно). В JSON нет NaN, поэтому `to-json()` выводит для него `null`, а `to-yaml()` выводит `.nan`.
