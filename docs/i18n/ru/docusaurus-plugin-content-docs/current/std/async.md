## Асинхронность (Async)

В Nolang есть только один синтаксис параллелизма верхнего уровня: группа сопрограмм `awy { ... }`, внутри которой задачи порождаются через `co`. Ключевое слово `run` удалено (теперь это обычный идентификатор); `awy <handle>` и группы сопрограмм в виде «голого» блока в позиции оператора тоже упразднены; **`co` вне группы — ошибка компиляции** (`E_CO_OUTSIDE_GROUP`).

`co` порождает только **процедуру** — вызываемая сторона не должна объявлять возвращаемое значение (неявно возвращаемое методом `self` не считается), поэтому результаты всегда передаются через канал: процедура отправляет значение в канал и выполняет `close()`, а вызывающая сторона опустошает канал вне группы.

### Группы сопрограмм

```no
; процедура: только пишет в канал, не объявляет возвращаемое значение
produce = (ch chan[i64], v i64) {
    ch <- v
    ch.close()
}

ch1 chan[i64] = with-cap(1)
ch2 chan[i64] = with-cap(1)

; параллелизм: две задачи запускаются вместе, группа ожидает в конце
awy {
    co produce(ch1, 1)
    co produce(ch2, 2)
}

r1 = 0
<- ch1: { ok -> r1 = it }
r2 = 0
<- ch2: { ok -> r2 = it }

; порядок: следующий spawn использует результат предыдущего как аргумент, «чтение канала» служит барьером
awy {
    co produce(ch1, r1)
}
```

`ch1` / `ch2` несут результаты, а не непрозрачные дескрипторы задач. Подробнее см. «Асинхронное программирование» в `lang/syntax.md`.

### «Бесцветный» async: `co`

`co` — «бесцветный» (colorless) синтаксис: вы пишете «неокрашенное» имя `produce`, а компилятор автоматически создаёт мономорфизированный вариант `produce-async` и выполняет его как «окрашенную» безстековую сопрограмму. Не пишите суффикс `-async` вручную в прикладном коде.

Две формы:

- `co f(args)` — spawn процедуры; `f` не должна объявлять результат (неявный `self` метода является исключением).
- `co { ... }` — spawn замыкания; свободные переменные блока захватываются по значению (снимок на момент spawn).

`co` не является значением и должно быть отдельным оператором: `r = co f()` и `print(co f())` дают ошибку `c0nostmt`.

Правила:

- **Мономорфизация**: `co produce(ch, 1)` автоматически создаёт `produce-async` (копия тела `produce` с новым именем). Если `produce` также вызывается синхронно, оба варианта сосуществуют.
- **Транзитивность**: если внутри процедуры тоже есть `awy { co child(n) }`, такая процедура также мономорфизируется в `-async`.
- **Низкоуровневое lowering** (не является синтаксисом языка): каждая `co` превращается в `OpRun`, а в конце группы вставляется `OpAwait`.

### Отмена

`cancelled()` можно использовать внутри сопрограммы для кооперативной самопроверки. `cancel(h)` — низкоуровневая операция с дескриптором; новый синтаксис не предоставляет дескрипторы задач, и прикладной код её не использует.

> **Внимание:** отмена кооперативная, а не вытесняющая. Долгие блокирующие вызовы (например, сетевые запросы) нельзя принудительно прервать; задача действительно остановится только на следующей кооперативной точке проверки (`cancelled()` или следующем планировании событийного цикла).

#### Отмена через канал вручную (рекомендуется)

В новом синтаксисе нет `ch.cancel()`, у канала тоже нет варианта `cancel`. Когда нужно, чтобы «внешний сигнал заставил worker завершиться», **заведите собственный канал и используйте `close()` как сигнал отмены** — это единственная семантика отмены у `chan[T]`. В трёхсостояниях цикла приёма `nil` означает «канал закрыт и опустошён» — это и есть ветка отмены; `err` означает лишь неинициализированный дескриптор и не должен использоваться для отмены.

```no
; канал управления: закрытие означает отмену
stop chan[i64] = with-cap(0)

worker = (stop chan[i64]) {
    <- stop: {
        ok  -> { }              ; получено сообщение (в этом примере не используется)
        nil -> print('cancel')  ; сюда попадаем после stop.close()
        err -> { }              ; неинициализированный дескриптор
    }
}

stop.close()
awy {
    co worker(stop)
}
; вывод: cancel
```

Чтобы инициировать отмену во время выполнения из другой задачи, поместите действие закрытия тоже внутрь группы (нельзя закрывать канал после `awy` — группа в конце ждёт всех, и если worker уже «паркуется» на пустом канале, возникнет взаимоблокировка). Помните, что `<- ch: { ... }` — это **цикл приёма**: получив одно значение, он продолжает ждать следующее, поэтому уведомляющая сторона после отправки обязана выполнить `close()`, чтобы canceller вышел из цикла и дошёл до `stop.close()`:

```no
stop chan[i64] = with-cap(0)
awake chan[i64] = with-cap(1)

worker = (stop chan[i64]) {
    <- stop: { ok -> { }  nil -> print('cancel')  err -> { } }
}

canceller = (awake chan[i64], stop chan[i64]) {
    <- awake: { ok -> { }  nil -> { }  err -> { } }   ; ждём уведомления; после получения нужно дождаться close, чтобы выйти из цикла
    stop.close()                                       ; именно эта строка является сигналом отмены
}

notify = (awake chan[i64]) {
    awake <- 1
    awake.close()                                      ; чтобы цикл приёма canceller дошёл до nil
}

awy {
    co worker(stop)
    co canceller(awake, stop)
    co notify(awake)
}
; вывод: cancel
```

Если вам просто нужно проверять в **начале каждого шага самого worker**, не был ли запрошен останов, удобнее использовать `cancelled()`; но он позволяет только самопроверку — извне дескриптора для уведомления нет. Для сценария «сигнал от другой стороны» используйте приведённый выше подход с каналом.
