## Базовые типы

### types — определения типов

Соответствие типов Nolang типам LLVM:

| Nolang           | LLVM                                               |
| ---------------- | -------------------------------------------------- |
| `bool`           | `i1`                                               |
| `byte`           | `i8`                                               |
| `char`           | `i32`                                              |
| `i8/i16/i32/i64/i128` | `i8/i16/i32/i64/i128`                             |
| `u8/u16/u32/u64/u128` | `i8/i16/i32/i64/i128`                          |
| `f32`            | `float`                                            |
| `f64`            | `double`                                           |
| `str`            | `%str-long = { i32, i32, i8* }` (u32 len, u32 cap, data; 16 байт на 64-битной системе, выделение в куче) |
| `[]t`            | `%vec = { i32, i32, i64 }` (u32 len, u32 cap, ptrtoint data; 16 байт на 64-битной системе, выделение в куче) |
| `[n]t`           | `[n x t]` (обычная агрегатная величина, элементы встроены; **нет дескриптора len / cap**) |
| `txt`            | `{ [255 x i8], i8 }` (фиксированные 256 байт) |

> **И `str`, и `[]t` хранят len / cap внутренне как `u32`, но наружу предоставляют их как `i64`.** При чтении дескриптора выполняется `zext i32 -> i64`, при записи — `trunc i64 -> i32`; сигнатуры `s.len-bytes()`, `s.len()`, `s.cap()` и приватных `_len` / `_cap` / `_set-len` / `_set-cap`, а также `v.len()` остаются `i64`. Подробнее см. [Строки: внутреннее представление и публичный API](../lang/str.md) и [Модель памяти: представление типов](../lang/memory.md#型別佈局).
> Поле `data` у `%vec` намеренно остаётся `i64` (кодировка через `ptrtoint`), в отличие от `i8*` у `%str-long`, поэтому эти два дескриптора **больше не имеют одинакового представления** и их нельзя применять `getelementptr` как один и тот же дескриптор.
> У `txt` нет поля `cap`, длина хранится в одном `i8` (0-255), и он **не переходит на u32** вместе с `str`.

**Составные типы:**

- **Массив переменной длины `[]t`**: базовый `%vec = { u32 len, u32 cap, i64 data }` (16 байт; `cap == 0` означает заимствованное представление, которое не владеет буфером)
- **Массив фиксированной длины `[n]t`**: LLVM-массив фиксированного размера `[n x t]`, элементы встроены, дескриптор времени выполнения отсутствует; `.len` — константа времени компиляции `n`, `cap` отсутствует
- **Строка `str`**: выделенная в куче последовательность байт с дескриптором `{ u32 len, u32 cap, i8* data }` (16 байт на 64-битной системе); поддерживает `s[i]`, `s[i..j]`, `s + t`. Длина/ёмкость предоставляются наружу как `i64` (`s.len-bytes()` / `s.cap()`), а внутренне хранятся как `u32`
- **Фиксированная строка `txt`**: структура фиксированного размера 256 байт `{ [255]byte data, byte len }`, первые 255 байт хранят данные, последний 1 байт хранит **байтовую** длину (0-255), выделение в куче не требуется, необходимо указание типа (`t txt = 'abc'`); `t.len()` возвращает количество кодовых точек (согласовано со `str`, эквивалентно `t.count()`), `t.len-bytes()` возвращает количество байт; индексация `t[i]` **читает** в единицах **кодовых точек** (возвращает `char` соответствующей кодовой точки, при выходе за границы — `err`, `code.index-out`); **запись `t[i] = c` полностью запрещена с 2026-11-12** (ошибка компиляции `idxwrite`) — она заново кодирует `c` в UTF-8 и сдвигает хвостовые байты, из-за чего длина неявно меняется при записи (`i`, равное числу кодовых точек, означает добавление в конец, а всё, что выходит за 255 байт, молча отбрасывается); для изменения длины используйте `t.push(c char)` / `t.push-str(s)` / `t.push-txt(u)`, для изменения значения на месте — place-match `t[i]: { ok -> it = c }`; для чтения на уровне байт используйте `t.byte(i)` (возвращает `?byte`, при выходе за границы — nil); чтобы собрать строку по байтам, просто накопьте `[]byte` и один раз скопируйте через `txt.from-bytes(b)` (всё, что превышает 255 байт, отсекается, длина устанавливается по фактическому числу байт). Побайтовый писатель `txt._set-byte` с 2026-11-11 является **приватным для std** и недоступен из пользовательского кода. `s[i] = v` у `str` был **полностью запрещён** 2026-11-11 (ошибка компиляции `idxwrite`, база `with-cap` также больше не является исключением); со стороны `str` остались только `s.fill(val byte)`, place-match `s[i]: { ok -> it = v }` и используемые для роста `s.push(c)` / `s.push-str(s)`
- **Перечисление/Union**: `option` — тегированное перечисление (`ok t` / `nil` / `err str`)
- **Структура**: должна определяться в несколько строк, поля не разделяются запятыми
- **Map (ассоциативный массив)**: базовый linked-hash-map
- **Итератор**: `for iter.next() {}` (метод интерфейса `next() (ok bool)`)

### option — тип Option

`option<t>` — тегированное перечисление (tag=0=val, 1=nil, 2=err):

```no
#{fmt-skip}
x ?t                ; объявить option<t>
x = 42              ; установить значение
x = nil             ; установить nil
x = err('msg')      ; установить ошибку

; match
x: {
    val -> f(it)
    nil ->
    err -> g(it.msg())
}  
```

**Руководство по стилю:** когда функция может завершиться ошибкой или вернуть пустое значение, используйте `?t` (option) вместо `(val, ok bool)`. `?t` имеет три состояния: `ok` (есть значение), `nil` (пустое/нормальное отсутствие), `err` (ошибка). Нормальное значение связывается неявно. Например, `pop()` возвращает `?i64` (`nil` = пусто), `read-line()` возвращает `?str` (`nil` = EOF, `err` = ошибка), `lookup()` возвращает `?str` (`nil` = не найдено). Подробнее см. документацию по синтаксису.
