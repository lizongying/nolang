# Отчёт о производительности

_Benchmarks Game — Nolang vs C vs Rust_

## Обзор

- Реализации **C / Rust / Nolang** были скомпилированы и запущены локально. Данные получены с помощью `/usr/bin/time -l` и Python `time.perf_counter()` (медиана из 3 запусков для каждого).
- Столбцы **Nolang** с числовым значением означают успешное выполнение; пометка «Заблокирован» означает ошибку на этапе выполнения (например, segfault / abort). Подробности приведены в списке заблокированных в конце.
- Метрики: **Wall** — время по часам (через `time.perf_counter()`, разрешение µs); **CPU** — время user+sys (из `/usr/bin/time -l`, квантование 10 мс); **Mem** — пиковая резидентная память (max RSS). **Единицы времени — мс (миллисекунды, 2 знака после запятой), единицы памяти — МБ.**
- Раскладка таблицы: столбцы — три языка (C / Rust / Nolang), строки — три метрики (Wall / CPU / Mem).

**Итого**: 13 тестов, C/Rust выполнены 13, Nolang выполнены 12, заблокирован 1 (thread-ring, результат корректный, но помечен тестовым фреймворком из-за различия в модели параллелизма, см. пояснение в конце).

### thread-ring

| Метрика | C | Rust | Nolang |
|---|---|---|---|
| Wall | 1676.86 ms | 1729.19 ms | Заблокирован |
| CPU | 12430.00 ms | 13370.00 ms | Заблокирован |
| Mem | 10.7 MB | 10.0 MB | Заблокирован |

- Пояснение по Nolang (заблокирован): результат thread-ring **корректный**, но был помечен как заблокированный тестовым фреймворком из-за различия в модели параллелизма (Nolang использует имитацию сопрограмм в одном потоке, C/Rust используют многопоточность pthread). В сценарии thread-ring сопрограммы Nolang разгромно превосходят потоки ОС pthread: архитектура имитации сопрограмм в одном потоке против реализации на C pthread примерно в 70 раз быстрее. Этот разрыв обусловлен проектированием базовой модели выполнения, а не простой оптимизацией кода.
