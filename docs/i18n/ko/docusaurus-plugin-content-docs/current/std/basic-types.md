## 기본 타입

### types — 타입 정의

Nolang 타입과 LLVM의 대응 관계:

| Nolang           | LLVM                                               |
| ---------------- | -------------------------------------------------- |
| `bool`           | `i1`                                               |
| `byte`           | `i8`                                               |
| `char`           | `i32`                                              |
| `i8/i16/i32/i64/i128` | `i8/i16/i32/i64/i128`                             |
| `u8/u16/u32/u64/u128` | `i8/i16/i32/i64/i128`                          |
| `f32`            | `float`                                            |
| `f64`            | `double`                                           |
| `str`            | `%str-long = { i32, i32, i8* }`（u32 len, u32 cap, data；64비트에서 16바이트, 힙 할당） |
| `[]t`            | `%vec = { i32, i32, i64 }`（u32 len, u32 cap, ptrtoint data；64비트에서 16바이트, 힙 할당） |
| `[n]t`           | `[n x t]`（평면 집계, 요소 인라인; **len / cap 디스크립터 없음**） |
| `txt`            | `{ [255 x i8], i8 }`（고정 256바이트） |

> **`str`과 `[]t`의 len / cap은 내부적으로 모두 `u32`이고, 외부에는 항상 `i64`입니다.** 디스크립터를 읽을 때는 `zext i32 -> i64`、
> 쓸 때는 `trunc i64 -> i32`입니다. `s.len-bytes()`, `s.len()`, `s.cap()` 및 비공개 `_len` / `_cap` / `_set-len` /
> `_set-cap`의 시그니처는 모두 `i64`로 유지되고, `v.len()`도 마찬가지입니다. 자세한 내용은 [문자열: 내부 레이아웃과 외부 API](../lang/str.md)
> 및 [메모리 모델: 타입 레이아웃](../lang/memory.md#型別佈局)을 참고하세요.
> `%vec`의 `data` 필드는 의도적으로 `i64`(`ptrtoint` 인코딩)를 유지하며 `%str-long`의 `i8*`와 다르므로, 두 것은
> **더 이상 레이아웃이 같지 않으며**, 서로 `getelementptr`로 같은 디스크립터처럼 취급할 수 없습니다.
> `txt`에는 `cap` 필드가 없고 길이는 `i8` 하나(0-255)이며, **`str`을 따라 u32로 바뀌지 않습니다**.

**복합 타입:**

- **가변 길이 배열 `[]t`**: 내부는 `%vec = { u32 len, u32 cap, i64 data }`(16바이트; `cap == 0`은 빌린 뷰를 뜻하며 버퍼를 소유하지 않음)
- **고정 길이 배열 `[n]t`**: LLVM 고정 크기 배열 `[n x t]`이며, 요소가 인라인이고 런타임 디스크립터가 없습니다. `.len`은 컴파일 타임 상수 `n`이고 `cap`이 없습니다
- **문자열 `str`**: 힙에 할당된 바이트 시퀀스이며, 디스크립터는 `{ u32 len, u32 cap, i8* data }`(64비트에서 16바이트)입니다. `s[i]`, `s[i..j]`, `s + t`를 지원합니다. 길이／용량은 외부에 `i64`로 표시되고(`s.len-bytes()` / `s.cap()`), 내부에는 `u32`로 저장됩니다
- **고정 문자열 `txt`**: 고정 256바이트 구조 `{ [255]byte data, byte len }`이며, 앞 255바이트에 데이터를 저장하고 마지막 1바이트에 **바이트** 길이(0-255)를 저장합니다. 힙 할당이 필요 없고 타입 표기가 필수입니다(`t txt = 'abc'`). `t.len()`은 code point 개수를 반환하고(`str`과 맞춤, `t.count()`와 동일), `t.len-bytes()`는 바이트 개수를 반환합니다. 인덱스 `t[i]`의 **읽기**는 **코드 포인트** 단위로 이루어지며(해당 코드 포인트의 `char`를 읽고, 범위를 벗어나면 `err`, `code.index-out` 반환), **쓰기 `t[i] = c`는 2026-11-12부터 전역 금지**(컴파일 오류 `idxwrite`)되었습니다. 쓰기는 `c`를 다시 UTF-8로 인코딩하고 뒤의 바이트를 밀어내어 길이가 암묵적으로 바뀌기 때문입니다(`i`가 코드 포인트 수와 같으면 추가, 255를 넘는 부분은 조용히 버려짐). 길이를 늘리려면 `t.push(c char)` / `t.push-str(s)` / `t.push-txt(u)`를 쓰고, 제자리에서 값을 바꾸려면 place-match `t[i]: { ok -> it = c }`를 쓰세요. 바이트 단위 읽기는 `t.byte(i)`(`?byte` 반환, 범위 초과 시 nil 반환)을 사용하세요. 바이트 단위로 조립하려면 `[]byte`를 모은 뒤 `txt.from-bytes(b)`로 한 번에 복사하세요(255바이트 초과 시 잘리고 길이는 실제 바이트 수로 설정됨). 바이트 단위 기록기 `txt._set-byte`는 2026-11-11부터 **std 전용**이며 사용자 코드에서 호출할 수 없습니다. `str`의 `s[i] = v`도 2026-11-11에 **전역 금지**(컴파일 오류 `idxwrite`, `with-cap` 베이스도 더 이상 예외 아님)되었고, `str`에는 `s.fill(val byte)`, place-match `s[i]: { ok -> it = v }`, 증가용 `s.push(c)` / `s.push-str(s)`만 남았습니다.
- **열거형/Union**: `option` tagged enum(`ok t` / `nil` / `err str`)
- **구조체**: 여러 줄로 정의해야 하며 필드에 쉼표를 붙이지 않습니다
- **배열**: 내부는 linked-hash-map
- **이터레이터**: `for iter.next() {}`(인터페이스 메서드 `next() (ok bool)`)

### option — 옵션 타입

`option<t>` 태그 열거형(tag=0=val, 1=nil, 2=err):

```no
#{fmt-skip}
x ?t                ; 宣告 option<t>
x = 42              ; 設為有值
x = nil             ; 設為空
x = err('msg')      ; 設為錯誤

; match
x: {
    val -> f(it)
    nil ->
    err -> g(it.msg())
}  
```

**스타일 가이드:** 함수가 실패하거나 빈 값을 반환할 수 있다면 `(val, ok bool)` 대신 `?t` option을 사용하세요. `?t`는 세 가지 상태가 있습니다. `ok`(값 있음), `nil`(빈 값/정상적인 부재), `err`(오류). 정상값은 암시적으로 바인딩됩니다. 예를 들어 `pop()`은 `?i64`를 반환하고(`nil` = 비어 있음), `read-line()`은 `?str`을 반환하며(`nil` = EOF, `err` = 오류), `lookup()`은 `?str`을 반환합니다(`nil` = 찾지 못함). 자세한 내용은 문법 문서를 참고하세요.
