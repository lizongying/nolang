# 내보내기

Nolang은 `@` 키워드를 사용하여 패키지 루트 디렉터리의 `lib.no` 파일에서 내보내기 항목을 선언합니다. 외부 패키지가 `#` 로 가져올 때는 이렇게 내보내진 심볼만 접근할 수 있습니다.

> **주의**: `@` 는 Nolang 패키지 간의 심볼 내보내기만 담당하며 C ABI 심볼을 생성하지 않습니다. C / C++ / Rust / Go / Java / Python / C# 에서 Nolang을 호출하려면 `#{cabi='symbol'}` 애노테이션을 `no build --shared` 와 함께 사용하세요. [호스트 언어에서 Nolang 호출하기](./host-interop)를 참조하세요.

## 문법

```no
@ path.func
[alias]
```

- `path` — 모듈 경로(패키지 루트 디렉터리 기준이며 `/` 로 시작하고 `.no` 확장자를 붙이지 않음)
- `func` — 내보낼 함수/상수/열거형 이름
- `alias` — 선택적 별칭, 외부에서 가져올 때 사용하는 이름

## 규칙

- 내보내기 문장은 **오직** 패키지 루트 디렉터리의 `lib.no` 파일에만 작성할 수 있습니다(유일한 예외는 아래 절 "전역 호출 별칭" 참조).
- 한 줄에 하나의 내보내기 항목.
- 내보내기 항목은 함수, 상수, 열거형 등 최종 심볼만 가능합니다.
- **심볼 이름을 반드시 지정해야 합니다**: `@ std/txt` (경로만 있고 `func` 도 `alias` 도 없음) 는 오류입니다 (`lgxbfk9a`). 이런 표기는 아무것도 선언하지 않으며, 모든 소비자가 "심볼 이름이 있다"는 것을 전제로 하기 때문에 더 이상 조용히 무시되지 않습니다. 또한 어떤 타입을 특정 모듈에 묶는 용도로도 쓸 수 없습니다. 타입에는 전역 이름이라는 계층이 없고, `@` 의 별칭은 호출 가능한 심볼에만 의미가 있기 때문입니다.
- 내보낸 함수가 참조하는 구조체, 열거형 등의 타입은 **자동으로 내보내지며** 수동으로 선언할 필요가 없습니다.
- 내보낸 함수가 모듈에 존재하지 않으면 LSP 가 오류를 표시합니다.

## 예제

```no
; lib.no - 包根目錄導出文件
@ /src/utils.greet a
@ /src/utils.hello b
@ /src/math.pi
```

```no
; src/utils.no
; 定義被導出的函數
greet = (name str) {
    print('Hello, ' - name)
}

hello = () {
    print('Hi')
}
```

## 전역 호출 별칭

같은 줄 문법을 **`std/global.no`** (특정 패키지의 `lib.no` 대신) 에 작성하면 의미가 달라집니다. 내보내기 항목을 걸러내는 대신, 전역에서 호출할 수 있는 **두 번째 이름**을 선언합니다. 즉 이름만 쓴 `<alias>` 가 곧 `path` 모듈의 `func` 이며, `<path>.<func>(...)` 를 모두 써서 호출하는 것과 효과가 완전히 동일합니다.

```no
; std/global.no —— 兩種寫法，語義相同
@ std/err.new err; 導出式
err = err.new; 賦值式
```

```no
e = err('disk full', code.io); 等同 e = err.new('disk full', code.io)
m = e.msg(); 'disk full'
```

규칙:

- 오직 `std/global.no` 만 이 의미를 가집니다. `lib.no` 의 `@` 는 여전히 내보내기 필터링입니다.
- 두 표기는 **동등**하며, 컴파일러가 이를 동일한 선언으로 정규화합니다. 둘 다 함께 써도 충돌하지 않습니다.
- 할당식은 **`global.no` 에서만** 유효합니다. 일반 프로그램에서 `x = mod.fn` 은 함수 값을 담는 변수(간접 호출에 사용 가능)이며 전역 별칭으로 취급되지 않습니다.
- 할당식의 우변은 bare한 `<모듈>.<함수>` 참조여야 합니다. 호출, 리터럴, 필드 읽기, 타입이 붙은 바인딩이 아니어야 합니다. 대상이 함수가 아니면 선언이 자동으로 무효화됩니다 (`PI = math.PI` 같은 상수 선언은 영향을 받지 않습니다).
- 별칭은 **bare 이름 호출** 위치에서만 적용됩니다. 한정 호출은 영향을 받지 않습니다. `io.err(...)` 는 여전히 `io` 모듈의 stderr 기록기이며 `err` 별칭에 가로채이지 않습니다.
- 모듈 내부에서 자기 자신과 이름이 같은 함수를 호출하는 것도 영향을 받지 않습니다(자기 모듈 면제).
- 별칭의 **매개변수 목록**은 대상 함수에서 가져오며, **반환 타입**은 호출 지점에서 대상 함수가 결정합니다.
- 별칭은 내장 option 의 `err` 변형과 충돌하지 않습니다. 기대 타입이 `?T` 인 위치 (`x ?i64` 다음의 `x = err('m')`, `err ->` 매치 분기, `?T` 를 반환하는 함수) 에서 `err(...)` 는 여전히 option 의 err 변형 생성자(tag 2)입니다.

## 내보낸 심볼 가져오기

외부 패키지가 `#` 로 가져올 때는 `lib.no` 에 선언된 내보내기 항목만 접근할 수 있습니다.

```no
; 导入別名 a（對應 package-name.utils.greet）
# package-name.utils.greet a
; 或者直接使用函數名
# package-name.utils.greet
```

## LSP 지원

- **정의로 이동**: `lib.no` 에서 내보낸 함수 이름이나 별칭을 클릭하면 해당 모듈 파일의 정의 위치로 이동합니다.
- **자동 완성**: `@` 와 경로를 입력하면 사용 가능한 파일 경로와 함수 이름이 자동으로 표시됩니다.
- **오류 표시**: 내보낸 함수가 모듈에 존재하지 않으면 오류 진단이 표시됩니다.
