## 非同期（Async）

Nolang には表層の並行構文が 1 種類しかありません：`awy { ... }` コルーチングループで、グループ内で `co` を使ってタスクを生成します。
`run` キーワードは削除されました（現在は通常の識別子です）。`awy <handle>` と文位置の裸ブロックのコルーチングループも廃止されました。
**グループ外の `co` はコンパイルエラーです**（`E_CO_OUTSIDE_GROUP`）。

`co` は**プロシージャ**のみを起動します。呼び出される側は戻り値を宣言してはいけません（メソッドが暗黙に返す `self` は該当しません）。
そのため結果は必ずチャネルを経由します。プロシージャが値をチャネルに送って `close()` し、呼び出し側がグループ外で値を取り出します。

### コルーチングループ

```no
; 過程：只寫通道，沒有宣告回傳值
produce = (ch chan[i64], v i64) {
    ch <- v
    ch.close()
}

ch1 chan[i64] = with-cap(1)
ch2 chan[i64] = with-cap(1)

; 並發：兩個任務一起跑，組尾統一等待
awy {
    co produce(ch1, 1)
    co produce(ch2, 2)
}

r1 = 0
<- ch1: { ok -> r1 = it }
r2 = 0
<- ch2: { ok -> r2 = it }

; 順序：後一個 spawn 用前一個的結果當實參，靠「讀通道」當屏障
awy {
    co produce(ch1, r1)
}
```

`ch1` / `ch2` から得られるのは結果値であり、task ハンドルではありません。詳細は `lang/syntax.md` の「非同期プログラミング」を参照してください。

### カラーレス async：`co`

`co` はカラーレス（colorless）な構文です。色付けされていない関数名 `produce` を書くと、コンパイラが自動的に単相化して
`produce-async` バリアントを生成し、内部では色付きのスタックレスコルーチンとして実行します。アプリケーションコードで `-async` サフィックスを手書きしないでください。

2 つの形態：

- `co f(args)` — プロシージャの spawn。`f` は戻り値を宣言してはいけません（メソッドの暗黙の `self` は例外）。
- `co { ... }` — クロージャの spawn。ブロック内の自由変数は値でキャプチャされます（spawn 時点のスナップショット）。

`co` は値ではなく、独立した文でなければなりません。`r = co f()` や `print(co f())` はどちらも `c0nostmt` を報告します。

規則：

- **単相化**：`co produce(ch, 1)` は自動的に `produce-async` を生成します（`produce` の本体をコピーして名前を変更）。`produce` が同期呼び出しもされる場合、両者は共存します。
- **伝播性**：あるプロシージャの内部にも `awy { co child(n) }` がある場合、そのプロシージャ自体も `-async` に単相化されます。
- **低層の lowering**（ユーザー構文ではありません）：各 `co` は `OpRun` になり、グループ末尾に `OpAwait` が挿入されます。

### キャンセル

`cancelled()` はコルーチン関数内で協調的な自己チェックに使用できます。`cancel(h)` は低層のハンドル操作です。
新しい構文では task ハンドルを公開しないため、アプリケーションコードでは使用しません。

> **注意：** キャンセルはプリエンプティブではなく協調的です。長時間ブロックする呼び出し（ネットワーク要求など）は強制的に中断できません。
> タスクは次の協調チェックポイント（`cancelled()` の呼び出し、またはイベントループの次のスケジューリング）で実際に停止します。

#### チャネル自身でキャンセルを行う（推奨）

新しい構文には `ch.cancel()` がなく、チャネルにも `cancel` バリアントはありません。「外部からシグナルを送って worker を終了させたい」場合、
**自分でチャネルを 1 つ用意し、`close()` をキャンセルシグナルとして使います**。これが `chan[T]` 唯一のキャンセルセマンティクスです。
受信ループの 3 つの状態のうち、`nil` は「閉じられていて空である」ことを示し、まさにキャンセル分岐です。`err` は未初期化のハンドルを示すだけなので、
キャンセルを受け取るのに使わないでください。

```no
; 控制通道：關閉即取消
stop chan[i64] = with-cap(0)

worker = (stop chan[i64]) {
    <- stop: {
        ok  -> { }              ; 收到訊息（本例不用）
        nil -> print('cancel')  ; stop.close() 後落到這裡
        err -> { }              ; 未初始化的句柄
    }
}

stop.close()
awy {
    co worker(stop)
}
; 輸出 cancel
```

実行中に別のタスクからキャンセルをトリガーするには、close 処理もグループ内に入れます（`awy` の後に close してはいけません。
グループ末尾で一律に待機するため、worker が空のチャネルで park しているとデッドロックします）。`<- ch: { ... }` は**受信ループ**であることに注意してください。
1 つの値を受け取ると次の値を待ち続けるため、通知側は送信後に `close()` する必要があり、canceller がループを抜けて
`stop.close()` まで実行されます。

```no
stop chan[i64] = with-cap(0)
awake chan[i64] = with-cap(1)

worker = (stop chan[i64]) {
    <- stop: { ok -> { }  nil -> print('cancel')  err -> { } }
}

canceller = (awake chan[i64], stop chan[i64]) {
    <- awake: { ok -> { }  nil -> { }  err -> { } }   ; 等通知，收到後還要等 close 才會離開迴圈
    stop.close()                                       ; 這一句才是取消信號
}

notify = (awake chan[i64]) {
    awake <- 1
    awake.close()                                      ; 讓 canceller 的接收迴圈走到 nil
}

awy {
    co worker(stop)
    co canceller(awake, stop)
    co notify(awake)
}
; 輸出 cancel
```

worker が**自らの各ステップの冒頭**で停止が要求されたかどうかをチェックしたいだけなら、`cancelled()` の方が直接的です。
ただし、これは自己チェックのみで、外部から通知できるハンドルはありません。「他人がシグナルを送る」シナリオでは、上記のチャネルの慣例に従ってください。
