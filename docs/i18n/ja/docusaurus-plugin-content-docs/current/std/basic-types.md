## 基本型

### types — 型の定義

Nolang の型と LLVM の対応関係：

| Nolang           | LLVM                                               |
| ---------------- | -------------------------------------------------- |
| `bool`           | `i1`                                               |
| `byte`           | `i8`                                               |
| `char`           | `i32`                                              |
| `i8/i16/i32/i64/i128` | `i8/i16/i32/i64/i128`                             |
| `u8/u16/u32/u64/u128` | `i8/i16/i32/i64/i128`                          |
| `f32`            | `float`                                            |
| `f64`            | `double`                                           |
| `str`            | `%str-long = { i32, i32, i8* }`（u32 len, u32 cap, data。64 ビット環境では 16 バイト、ヒープ割り当て） |
| `[]t`            | `%vec = { i32, i32, i64 }`（u32 len, u32 cap, ptrtoint data。64 ビット環境では 16 バイト、ヒープ割り当て） |
| `[n]t`           | `[n x t]`（素の集約、要素はインライン。**len / cap ディスクリプタなし**） |
| `txt`            | `{ [255 x i8], i8 }`（固定 256 バイト） |

> **`str` と `[]t` の len / cap は内部ではどちらも `u32`、外部には常に `i64` として見えます。** ディスクリプタの読み取り時は `zext i32 -> i64`、
> 書き込み時は `trunc i64 -> i32` です。`s.len-bytes()`、`s.len()`、`s.cap()` とプライベートな `_len` / `_cap` / `_set-len` /
> `_set-cap` のシグネチャはすべて `i64` のままで、`v.len()` も同様です。詳細は [文字列：内部レイアウトと対外 API](../lang/str.md)
> と [メモリモデル：型のレイアウト](../lang/memory.md#型別佈局) を参照してください。
> `%vec` の `data` フィールドは意図的に `i64`（`ptrtoint` エンコード）のままとされ、`%str-long` の `i8*` とは異なるため、両者は
> **レイアウトが同一ではなくなりました**。同じディスクリプタとして互いに `getelementptr` してはいけません。
> `txt` には `cap` フィールドがなく、長さは 1 バイトの `i8`（0〜255）です。**`str` に合わせて u32 には変更しません**。

**複合型：**

- **可変長配列 `[]t`**：内部は `%vec = { u32 len, u32 cap, i64 data }`（16 バイト。`cap == 0` は借用ビューを示し、バッファを所有しません）
- **固定長配列 `[n]t`**：LLVM の固定サイズ配列 `[n x t]` で、要素はインライン、実行時のディスクリプタはありません。`.len` はコンパイル時定数 `n` で、`cap` はありません
- **文字列 `str`**：ヒープ割り当てのバイト列で、ディスクリプタは `{ u32 len, u32 cap, i8* data }`（64 ビット環境では 16 バイト）。`s[i]`、`s[i..j]`、`s + t` をサポートします。長さ／容量は外部には `i64` として現れ（`s.len-bytes()` / `s.cap()`）、内部は `u32` で格納されます
- **固定文字列 `txt`**：固定 256 バイトの構造 `{ [255]byte data, byte len }` で、先頭 255 バイトにデータを格納し、最後の 1 バイトに**バイト**単位の長さ（0〜255）を格納します。ヒープ割り当ては不要ですが、型注釈が必須です（`t txt = 'abc'`）。`t.len()` はコードポイント数を返します（`str` に合わせたもので、`t.count()` と等価）。`t.len-bytes()` はバイト数を返します。インデックス `t[i]` の**読み取り**は**コードポイント**単位です（そのコードポイントの `char` を読み返し、範囲外なら `err`、`code.index-out` を返します）。**`t[i] = c` への書き込みは 2026-11-12 より全域で無効化されています**（コンパイルエラー `idxwrite`）。これは `c` を再度 UTF-8 エンコードして後続のバイトをずらし、長さが書き込みに伴って暗黙に変化するためです（`i` がコードポイント数に等しい場合は追加、255 を超える部分は黙って破棄）。可変長にするには `t.push(c char)` / `t.push-str(s)` / `t.push-txt(u)` を、その場で値を変更するには place-match `t[i]: { ok -> it = c }` を使ってください。バイト単位の読み取りには `t.byte(i)` を使います（`?byte` を返し、範囲外なら nil を返します）。バイト単位で組み立てたい場合は `[]byte` をそのまま作り、`txt.from-bytes(b)` で一度にコピーします（255 バイトを超える部分は切り詰められ、長さは実際のバイト数に設定されます）。バイト単位のライター `txt._set-byte` は 2026-11-11 より **std の非公開** API であり、ユーザーコードからは呼び出せません。`str` の `s[i] = v` も 2026-11-11 に**全域で無効化**されています（コンパイルエラー `idxwrite`。`with-cap` ベースも例外ではなくなりました）。`str` 側に残るのは `s.fill(val byte)`、place-match `s[i]: { ok -> it = v }`、そして伸長用の `s.push(c)` / `s.push-str(s)` だけです。
- **列挙型/Union**：`option` のタグ付き列挙型（`ok t` / `nil` / `err str`）
- **構造体**：複数行での定義が必須で、フィールドにカンマは付けません
- **配列**：内部は linked-hash-map
- **イテレータ**：`for iter.next() {}`（インターフェースメソッド `next() (ok bool)`）

### option — オプション型

`option<t>` のタグ付き列挙型（tag=0=val、1=nil、2=err）：

```no
#{fmt-skip}
x ?t                ; 宣告 option<t>
x = 42              ; 設為有值
x = nil             ; 設為空
x = err('msg')      ; 設為錯誤

; match
x: {
    val -> f(it)
    nil ->
    err -> g(it.msg())
}  
```

**スタイルガイド：** 関数が失敗する可能性がある場合や空の値を返す場合は、`(val, ok bool)` ではなく `?t` option を使ってください。`?t` には 3 つの状態があります：`ok`（値あり）、`nil`（空値／正常な欠落）、`err`（エラー）。正常な値は暗黙にバインドされます。たとえば `pop()` は `?i64` を返し（`nil` = 空）、`read-line()` は `?str` を返し（`nil` = EOF、`err` = エラー）、`lookup()` は `?str` を返します（`nil` = 見つからない）。詳細は構文ドキュメントを参照してください。
