# クロスモジュール呼び出しのプレフィックス

Nolang は強制的なモジュール名前空間の規則を採用しています。1 つの `.no` ファイル内で**他のモジュール**（別の `.no` ファイル）で定義された関数や定数を呼び出す際は、`ShortName.` プレフィックスを付ける必要があります。これによりモジュール間の名前の衝突を回避します。

標準ライブラリのモジュールはコンパイラによって自動的に読み込まれ、**明示的なインポートは不要**です（`# std/...` アノテーションも不要）。`ShortName.` プレフィックスを直接使って呼び出せます。`no fmt` は別名なしの純 std モジュールインポート（例 `# std/noml`、`# std/math`、`# std/fmt`）をすべて自動的に削除します。別名（`# std/noml n`）や関数インポート（`# std/math.sqrt`）は保持されます（詳細は[コードスタイル · インポート文の自動整理](./code-style#インポート文の自動整理重複排除--別名なし-std-インポートの削除--ソート)を参照）。

> **依存関係とパス解決**：ローカルパッケージの依存キーは `workspace.noml` を通じて短縮名や完全な URL 形式にマッピングできます。詳細は [依存関係の種類とバージョン番号の規則](../usage#依賴類型與版本號規則) を参照してください。

## ShortName の定義

ShortName はモジュールパスの最後のセグメントで、クロスモジュール呼び出し時のプレフィックスとして使われます。

| ファイルパス | FullPath | ShortName | 説明 |
| --- | --- | --- | --- |
| `std/math.no` | `math` | `math` | トップレベルのファイル |
| `std/fs.no` | `fs` | `fs` | トップレベルのファイル |
| `std/net/net.no` | `net/net` | `net` | パスの最後のセグメント |
| `std/net/client.no` | `net/client` | `client` | パスの最後のセグメント |
| `std/crypto/sha256.no` | `crypto/sha256` | `sha256` | パスの最後のセグメント |
| `std/archive/gzip.no` | `archive/gzip` | `gzip` | パスの最後のセグメント |

ShortName とは、FullPath をスラッシュで区切った最後のセグメントのことです（例：`crypto/sha256` → `sha256`）。

## プレフィックスが必要な場合

他のモジュールで定義されたモジュールレベルの関数や定数を呼び出す際は、`ShortName.` プレフィックスが必要です。

```no
; 模組級函數
sha256.sha256(data)
sha256.sha256-hex(data)
fs.open(path, opts)
gzip.gzip-decompress(data)
math.pow(x, y)

; 模組常量
net.NET-BUF-SIZE
math.PI
```

### 関数の命名規則

**関数名にモジュール名のプレフィックスを付けないでください。** モジュール内の関数は短く直感的な名前で十分です。クロスモジュール呼び出し時の `ShortName.` プレフィックスが自動的にモジュール情報を示してくれます。

```no
; ✅ 正確：函數名簡潔，不加模組名前綴
; tail.no
; 入口函數直接用模組名
tail = () {
    ...
}

; 輔助函數用簡短名稱
atoi = (s str) (v i64) {
    ...
}
```

```no
#{fmt-skip}
; ❌ 避免：函數名冗餘帶上模組名前綴
; tail-run = () { }
; tail-atoi = (s str) (v i64) { }
```

クロスモジュールのインポート時も同様です：

```no
; ✅ 簡潔直觀
# /src/tail.tail
# /src/mktemp.mktemp
```

```no
#{fmt-skip}
; ❌ 冗餘
; # /src/tail.tail-run
; # /src/mktemp.mktemp-run
```

> **キーワードを避けることに注意**：`awy`（コルーチングループのキーワード）、`match`（条件マッチのキーワード）などは関数名に使えません。`run` は削除されたため、通常の識別子として使えます。エントリ関数にはモジュール名そのものを直接使うことを推奨します（例：`ping.no` → `ping`）。

## プレフィックスが不要な場合

以下の場合はプレフィックスが不要です：

### 1. グローバル関数（`with-cap` / `with-len` / `with-cap-len` / `print` / `eprint` / `format` / `exit`）

これら 7 つの関数は言語レベルのグローバル組み込み関数で、モジュールのプレフィックスなしで直接使えます。それらのコメントによる宣言はすべて `std/global.no` にまとめられており、開発者が確認しやすくなっています。

**容量／長さの構築：**

- `with-cap(cap)` — 指定した容量の文字列またはスライスを生成します（len=0）。型は代入の左辺から推論されます
- `with-len(len)` — 指定した長さの文字列またはスライスを生成します
- `with-cap-len(cap, len)` — 指定した容量と長さの文字列またはスライスを生成します

**出力／フォーマット：**

Nolang は**名前付きフォーマット文字列**の構文 `{name[:spec]}` を使い、スコープ内の変数を直接参照します。位置引数は不要です。コンパイル時の検証にも対応しています。出力は `io.out`/`io.err` のシステムコールで直接書き込まれ、libc の `printf` には依存しません。

- `print(s)` / `print(s0, s1, ...)` — 標準出力へ出力します。複数の引数は空白で区切られ、**自動的に改行**されます
- `eprint(s)` / `eprint(s0, s1, ...)` — 標準エラーへ出力します。複数の引数は空白で区切られ、**自動的に改行**されます
- `format(s)` — フォーマット済みの文字列を返します（`sprintf` の代替）。自動改行はしません

**プロセス制御：**

- `exit(code)` — 終了ステータスコードでプロセスを終了します（旧 `os.exit` からグローバル組み込みに昇格し、`os.` プレフィックスは不要になりました）

**複数の引数を渡す場合、リテラルはデフォルトでテンプレートとして扱われ、C スタイルのフォーマット文字列ではありません。** `print('result={val}', 42, 'result={val}')` では、各文字列リテラルが**それぞれ** 1 つのテンプレートです。その `{val}` は**呼び出し元のスコープ**から値を取得し、同じ呼び出し内の他の引数とは関係ありません。リテラルは後続の引数を記述したり消費したりし**ません**——`printf('%d', 42)` のような置換ではありません。リテラルでない引数（変数、式）は通常の可変長引数として扱われ、空白で区切られ、行末に改行が 1 つだけ付きます。

```no
val = 42
print('result={val}', 42, 'result={val}'); result=42 42 result=42
tmpl = '{val}'
print(tmpl); {val} —— 變數是純文字，不做替換
print('a={val}', val); a=42 42
```

`format(s)` と廃止済みの `sprintf(s)` は引き続き**単一のフォーマット文字列**のみを受け取り、複数引数の形式はありません。

> `printf`、`eprintf` は**削除されました**：名前は依然としてシンボルテーブルに残っており（呼び出しは解決でき、エディタの補完も機能します）、
> しかし**どんな呼び出しもハードなコンパイルエラー**です（`[printf-depr]`）。メッセージは移行先を直接案内します。`sprintf` はまだ使えますが、**廃止予定**です。
> 代替関係は次のとおりです：
> - `printf(s)` → `print(s)`（自動改行）または `io.out(s)`（改行なし、標準出力）
> - `eprintf(s)` → `eprint(s)`（自動改行）または `io.err(s)`（改行なし、標準エラー）
> - `sprintf(s)` → `format(s)`（フォーマット済み文字列を返す）
>
> `io.out`/`io.err` は低レベルコマンドで、出力は**改行されません**。モジュール呼び出しにはモジュール名を付ける必要があるため、`io.err` はモジュールプレフィックスを明示しており、Option の構築関数 `err()` と衝突しません。同名でもモジュールプレフィックスで区別できます。

```no
; 容量/長度構造（無前綴）
s str = with-cap(256); ✅ 預分配 256 位元組的 str
v []i64 = with-cap(100); ✅ 預分配 100 個元素的切片
v []i64 = with-cap-len(200, 100); ✅ 容量 200、長度 100
v []i64 = with-len(100); ✅ 長度 100 的切片

; 輸出/格式化（無前綴）
print('hello {n}'); ✅ 自動換行
print(a, b, c); ✅ 多參數，空格分隔，自動換行
print('x={n}', n); ✅ 字面量是模板，變數是值
print('result={val}', 42, 'result={val}'); ✅ 每個字面量各自替換
print(); ✅ 空參數，只輸出換行
s = format('x={x}'); ✅ 返回格式化字串（單一格式字串）
eprint('err: {n}'); ✅ 輸出到 stderr 並換行
eprint('err:', a, b); ✅ 多參數，stderr 空格分隔
print('編號 {id:06} 金額 {money:.2f}'); ✅ 支援對齊、填充、寬度、精度

; 底層命令（需要模組前綴）
io.out('no-newline-here'); ✅ 輸出不換行（替代 printf）
io.err('err-no-newline'); ✅ stderr 不換行（替代 eprintf）

; 其他所有跨模組調用都需要前綴
fs.open(path, opts); ✅ 帶前綴（builtin 也需要）
```

#### フォーマット指定子

`{name[:spec]}` の `spec` は以下のフィールドに対応します（順序は固定で、いずれも省略可能です）：

```
[[fill]align][sign][#][0][width][.precision][type]
```

- `fill` — 埋め文字（デフォルトは空白）。`align` と一緒に使う必要があります
- `align` — `<` 左寄せ、`>` 右寄せ、`^` 中央寄せ
- `sign` — `+` 正数のときにプラス記号を表示、`-` 負数のみ表示（デフォルト）
- `#` — 基数プレフィックス（`0x`/`0o`/`0b`）
- `0` — 数値の前にゼロを補って指定した幅にします
- `width` — 最小フィールド幅
- `.precision` — 浮動小数点数の小数桁数／文字列の切り詰め長
- `type` — `d`（整数）、`x`/`X`（16 進数）、`o`（8 進数）、`b`（2 進数）、`c`（文字）、`f`（固定小数点）、`e`/`E`（科学表記法）、`g`/`G`（一般）、`s`（文字列、デフォルト）、`t`（データ型名、コンパイル時に確定）、`v`（リテラル値、文字列は単一引用符で囲み、vec は to-str を呼び出す）

```no
x i64 = 42
u u64 = 255
pi f64 = 3.14159
s str = 'hello'
print('{x:06}'); 000042
print('{x:>10}'); 右對齊寬度 10
print('{u:#x}'); 0xff
print('{pi:.2f}'); 3.14
print('{pi:8.3e}'); 3.142e+00
print('{s:<10}'); hello     （左對齊）
print('{s:.3}'); hel（截斷為 3 字元）
print('{x:t}'); i64（印出變數 x 的型別名）
print('{s:v}'); 'hello'（字串用單引號包裹）
```

`{{` と `}}` はリテラルの `{` と `}` を出力するために使われますが、**同じ文字列内に少なくとも 1 つの実際の `{name}` フィールドがある場合にのみ有効**です。エスケープだけを含みフィールドを含まないリテラルはそのまま出力されます。`print('{{n}}')` は `{{n}}` を出力し（`{n}` ではなく）、`print('{{')` は `{{` を出力します。単独の中括弧を出力するには、`print('{')` / `print('}')` を直接使ってください。

### 2. 同一ファイル内で定義

同じ `.no` ファイル内で定義された関数、定数、メソッドは、プレフィックスなしで直接使えます。

```no
; 在 sha256.no 中：
sha256(data); sha256 定義在本檔案

; 常量定義在本檔案
HMAC-BLOCK-SIZE
```

### 3. 組み込み型のメソッド

組み込み型（`str`、`i64`、`vec`、`arr`、`byte`、`char`、`bool` など）のメソッド呼び出しにはプレフィックスが不要です。メソッドは型に組み込まれており、レシーバの型から直接解決されます。

```no
'hello'.starts-with('he'); str 方法
n.to-str(); int 方法
v.push(42); vec 方法
a.contains(3); arr 方法
c.is-digit(); char 方法
```

### 4. 構造体インスタンスのメソッド

生成済みの構造体インスタンスに対してメソッドを呼び出す場合、モジュールのプレフィックスは不要です。メソッドはインスタンスの型から解決され、コンパイラが対応する `struct.method` の定義を自動的に見つけます。

```no
f = fs.open(path, opts); fs.open 是模組級函數，需前綴
f.read(buf, n); file.read 是結構體方法，不需前綴
f.close(); file.close 是結構體方法，不需前綴

p = path {
    p: '/tmp'
}
p.exists(); path.exists 是結構體方法，不需前綴
```

## メソッド呼び出しとモジュール関数呼び出し

メソッド呼び出しにプレフィックスが必要かどうかは、**メソッドの所有者**によって決まります：

- **組み込み型のメソッド**（`str.starts-with`、`i64.to-str` など）—— プレフィックス不要
- **構造体インスタンスのメソッド**（`f.read`、`p.exists` など）—— プレフィックス不要
- **モジュールレベルの関数**（`fs.open`、`sha256.sha256` など）—— **プレフィックスが必要**

`fs.fil()` の `fs` はモジュールの ShortName、`fil` はモジュールレベルの関数名です。`fs.` プレフィックスは省略できません。ここでの `fs` は変数名ではなくモジュールパスだからです。

### `Name.Function` の 2 つの意味

`process.cmd(...)` と `p.start(...)` はどちらも `xxx.yyy()` の形で書かれていますが、意味はまったく異なります：

| 書き方 | `xxx` | `yyy` | 意味 |
| --- | --- | --- | --- |
| `process.cmd(...)` | モジュールの ShortName | モジュールレベルの関数 | `xxx` はモジュールパス、`yyy` はそのモジュールで定義された独立した関数 |
| `p.start(...)` | インスタンス変数 | 構造体のメソッド | `xxx` は `process` 型の変数、`yyy` は `process.start = ...` として定義されたメソッド |

**定義時の違い**：
- モジュールレベルの関数は定義時に**プレフィックスを付けません**：モジュール内部に `cmd = (program str, ...) { }` と直接書きます
- 構造体のメソッドは定義時に **`struct.` プレフィックスが必要：`process.start = (program str, ...) { }`

**呼び出し時の違い**：
- モジュールレベルの関数は外部から `ModuleName.function()` で呼び出します：`process.cmd(...)`
- 構造体のメソッドはインスタンス経由で呼び出します：`p = process.new()` → `p.start(...)`

> **注意**：モジュール内部であっても、同じモジュールのモジュールレベル関数を呼び出す際はプレフィックスを付けません（`cmd(...)`）。一方、構造体のメソッドを呼び出す際は `self` による暗黙参照か `.method()` 構文を使います。

## クロスモジュールの型参照

**他のモジュール**で定義された型（構造体、インターフェース、列挙型など）を参照する際は、`ShortName.` プレフィックスが必要です。これは次の場合に当てはまります：

### 構造体によるインターフェースの実装

構造体が他のモジュールで定義されたインターフェースを実装する場合、インターフェース名にモジュールのプレフィックスを付ける必要があります：

```no
#{fmt-skip}
; ❌ 錯誤：db、rows、stmt 是 sql 模組定義的介面，不能省略前綴
db-mysql db {
    fd i64
}
```

```no
; ✅ 正確：使用 sql.db、sql.rows、sql.stmt
db-mysql sql.db {
    fd i64
}

rows-mysql sql.rows {
    fd i64
}

stmt-mysql sql.stmt {
    fd i64
}
```

### 関数の引数と戻り値の型

関数のシグネチャに含まれるクロスモジュールの型にもプレフィックスが必要です：

```no
; ✅ 正確：返回型別使用 sql.result
db-mysql.exec = (sql str) (r sql.result) {
    ...
}
```

### 構造体のフィールドの型

```no
; ✅ 正確：欄位型別使用 sql.connection
conn-mysql sql.db {
    handle sql.connection
}
```

### プレフィックスが不要な場合

- **同じモジュールで定義された型**：同じ `.no` ファイル内で定義された構造体、インターフェース、列挙型は、型名をそのまま使います
- **組み込み型**：`str`、`i64`、`bool`、`byte` などの組み込み型にはプレフィックスが不要です
- **組み込みインターフェース**：`enter`、`leave` などの言語組み込みインターフェースにはプレフィックスが不要です

```no
; 同檔案定義的型別，不需前綴
result {
    last-id i64
    affected i64
}

; enter/leave 是內置介面，不需前綴
; result 是同檔案定義的結構體，不需前綴
db {
    enter
    leave
    close() (ok bool)
    exec(sql str) (r result)
}
```

## 完全な例

```no
; 標準庫模組自動載入，無需顯式導入

; ─── 不需前綴 ───

; 全局函數（宣告在 global.no）
s str = with-cap(256)
v []i64 = with-len(100)
print('hello {n}')
s = format('x={x}')

; 同檔案函數
sha256(data)

; 內置類型方法
'hello'.starts-with('he')
n.to-str()
v.push(42)

; 結構體實例方法
f = fs.open(path, opts)
f.read(buf, n)
f.close()

; ─── 需要前綴 ───

; 模組級函數
sha256.sha256(data)
sha256.sha256-hex(data)
fs.open(path, opts)
gzip.gzip-decompress(data)
math.pow(x, y)

; 模組常量
net.NET-BUF-SIZE
math.PI

; 跨模組型別引用（介面實作、參數型別、返回型別、欄位型別）
db-mysql sql.db {
    fd i64
}

r sql.result = d.exec('CREATE TABLE ...')
```
