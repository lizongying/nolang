# 導出

Nolang 使用 `@` 關鍵字在包的根目錄 `lib.no` 文件中聲明導出項，外部包通過 `#` 導入時只能訪問這些已導出的符號。

## 語法

```no
@ path.func [alias]
```

- `path` — 模塊路徑（相對於包根目錄，以 `/` 開頭，不帶 `.no` 副檔名）
- `func` — 要導出的函數/常量/枚舉名
- `alias` — 可選別名，外部導入時使用的名稱

## 規則

- 導出語句**只能**寫在包根目錄的 `lib.no` 文件中（唯一例外見下節「全域可呼叫別名」）
- 一行一個導出項
- 導出項只能是函數、常量、枚舉等最終符號
- 被導出函數引用的結構體、枚舉等類型會**自動導出**，無需手動聲明
- 如果導出的函數在模塊中不存在，LSP 會提示錯誤

## 範例

```no
; lib.no - 包根目錄導出文件
@ /src/utils.greet a
@ /src/utils.hello b
@ /src/math.pi
```

```no
; src/utils.no
; 定義被導出的函數
greet = (name str) {
    print('Hello, ' - name)
}

hello = () {
    print('Hi')
}
```

## 全域可呼叫別名

同一行語法寫在 **`std/global.no`**（而不是某個包的 `lib.no`）裡時，含義不同：
它不篩選導出項，而是宣告一個**全域可呼叫的第二名稱**——裸名 `<alias>` 直接就是
`path` 模塊的 `func`，效果與寫全 `<path>.<func>(...)` 完全相同。

```no
; std/global.no —— 兩種寫法，語義相同
@ std/err.new err      ; 導出式
err = err.new          ; 賦值式
```

```no
e = err('disk full')        ; 等同 e = err.new('disk full')
m = e.msg()                 ; 'disk full'
```

規則：

- 只有 `std/global.no` 具有這個含義；`lib.no` 裡的 `@` 仍然是導出過濾
- 兩種寫法**等價**，編譯器把它們正規化成同一個宣告；同時寫兩個也不會衝突
- 賦值式**只在 `global.no` 有效**。普通程式裡的 `x = mod.fn` 是一個持有函數值的
  變數（可用作間接呼叫），不會被當成全域別名
- 賦值式的右邊必須是裸的 `<模組>.<函數>` 引用：不是呼叫、不是字面量、不是
  欄位讀取、也不是帶型別的綁定。目標不是函數時宣告自動失效（`PI = math.PI`
  這類常量宣告不受影響）
- 別名只在**裸名呼叫**位置生效。限定呼叫不受影響：`io.err(...)` 仍是 `io`
  模塊的 stderr 寫入器，不會被 `err` 別名劫持
- 模塊內呼叫自己同名的函數也不受影響（自模塊豁免）
- 別名的**參數表**取自目標函數；**回傳型別**在呼叫點由目標函數決定
- 別名與內建 option 的 `err` 變體不衝突：在期望型別是 `?T` 的位置
  （`x ?i64` 之後的 `x = err('m')`、`err ->` 匹配臂、回傳 `?T` 的函數），
  `err(...)` 仍然是選項的 err 變體構造器（tag 2）

## 導入已導出的符號

外部包通過 `#` 導入時，只能訪問 `lib.no` 中聲明的導出項：

```no
; 导入別名 a（對應 package-name.utils.greet）
# package-name.utils.greet a

; 或者直接使用函數名
# package-name.utils.greet
```

## LSP 支持

- **跳轉定義**：在 `lib.no` 中點擊導出的函數名或別名，跳轉到對應模塊文件中的定義位置
- **自動補全**：輸入 `@` 和路徑時自動提示可選的文件路徑和函數名
- **錯誤提示**：導出的函數在模塊中不存在時顯示錯誤診斷
