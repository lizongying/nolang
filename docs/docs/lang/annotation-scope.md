# 註解與註釋的作用域

`#{...}` 註解本身不帶「我能管多大範圍」的資訊——範圍由**它附着在哪個節點上**決定。
這頁把這件事固定下來：一個位置、一套判定、四個層級，讓作者、`no fmt`、`no vet`、
codegen 與 LSP 對同一行註解給出同一個答案。

> 為什麼必須固定：同一條 `#{overflow=wrap}`，若 `no vet` 認為它管整個函式、codegen
> 認為它只管下一行，就會出現「vet 全綠、運行期照樣回 `err`」的靜默語義漂移。
> 作用域不是註解的屬性，而是**讀者的共識**；共識不寫下來就會各自漂。

---

## 1. 一個原則：作用域由宿主決定

註解只有兩種合法位置（位置規則本身見 [`syntax.md`](syntax.md)〈註解位置〉）：

```no
; ① 上方：獨佔一行，置於目標之上
#{overflow=wrap}
x i8 = a + b

; ② 尾隨：寫在目標同一行的後方
x i8 = a + b #{overflow=wrap}
```

**寫在目標前方同一行是編譯錯誤**，不存在「前綴作用到後方」這條路：

```no
#{overflow = wrap} x i8 = a + b   ; ✗ 前綴 → 報錯
```

判定分三步，每一步都只有一個答案：

| 步驟 | 問題 | 答案來源 |
| --- | --- | --- |
| 1 | 宿主是誰？ | 位置：上方的第一條非註解/非註解行陳述，或同一行的前一條陳述 |
| 2 | 宿主屬於哪一層？ | 下表（節點種類決定層級） |
| 3 | 覆蓋到哪裡？ | 宿主子樹，減去內層硬邊界（§3） |

---

## 2. 四個層級

| 層級 | 宿主 | 生效範圍 | 寫法示例 |
| --- | --- | --- | --- |
| **L0 模組級** | 檔案頭 | 本檔案全部宣告與語句 | 檔案最頂端，且與後續內容之間空一行 |
| **L1 宣告級** | 常量/全局變數、結構體、介面、標籤列舉、函式、方法 | 該宣告的整個定義（函式含函式體與全部巢狀區塊） | 緊貼宣告上方，或宣告行尾隨 |
| **L2 區塊級** | 協程組、if 組、`cond -> body`、match、`for`/計數/區間循環、裸塊 | 該塊體內全部語句（含巢狀塊，止於內層 L1 邊界） | 緊貼塊頭那條語句上方 |
| **L3 單行級** | 單條陳述（`let`、賦值、`?=`、`return`、呼叫、`cond ->` 臂） | 該陳述自身及其運算式 | 緊貼陳述上方，或同行尾隨 |

### L0 模組級

位置是**檔案最開頭**（前面沒有任何語句或 import），且註解群組與第一條語句之間
**至少一個空行**——空行在這裡是「作用域終止符」，表示這組註解不屬於下一條陳述，
而屬於整個檔案。

```no
#{win-amd64}

; ↑ 空行 → 模組級：本檔只在 Windows x86_64 編譯
; 以下所有宣告與語句都在管轄內
helper = () {
    print('windows only')
}

label = 'win'
```

沒有空行就是一般的 L1（附着首個宣告），這條邊界讓既有程式碼不需遷移：

```no
#{buildin}
bool.to-str = () (out str) {
}
```

模組級只對「整檔有意義」的鍵有用（平台鍵、`overflow`）；宣告鍵（`buildin`、`generic`、
`embed`…）出現在 L0 是錯誤，不是「擴大範圍」。

跨檔案的配置不屬於註解，寫在 `package.noml`。

### L1 宣告級

```no
; 整個函式（含所有巢狀塊）都在管轄內
#{overflow=wrap}
sum = (xs []i64) (total i64) {
    total = 0
    i <- [0..xs.len()): {
        total = total + xs[i]
    }
}

; 整個結構體
#{derive=[Serialize]}
point {
    x i64
    y i64
}

; 方法與函式同級
#{track-caller}
log.write = (msg str) {
}
```

L1 內部還有**成員粒度**：結構體欄位、標籤列舉變體、C 風格列舉成員上的註解
（`a pt #{inline}`、`ok(v i64) #{inline}`）管的是該成員，不是整個型別。成員註解
不能寫成獨立一行置於成員上方以外的位置。

### L2 區塊級

宿主是「塊頭陳述」時，作用域是整個塊體：

```no
#{overflow=wrap}
i <- [0..n): {
    a i8 = 100
    b i8 = 100
    c = a + b          ; ← 被 L2 覆蓋
    j <- [0..m): {
        d = c * 2      ; ← 巢狀塊同樣被覆蓋
    }
}

#{win-amd64}
{
    x == 1 -> do-win-thing()
    -> do-other()
}
```

四種塊頭都適用：協程組（語句位置的裸塊）、if 組（`{ cond -> … }`）、單條件語句
（`cond -> body`）、match、`for` / 計數 / 區間循環。

`cond -> body` 的 body 若只是單條陳述，L2 與 L3 的結果相同；寫成塊才有區別。

### L3 單行級

```no
a i8 = 100
b i8 = 100
#{overflow=wrap}
c = a + b              ; ← 只管這一行
```

區塊內一個獨立成行的註解只認「緊跟其後的那一條陳述」。中間夾着無關的註解行
（例如 `#{overflow=wrap}` 之後再來一個 `#{...}`）不會中斷，仍找到第一條真正的陳述；
但若下一條註解本身也帶同名鍵，則以前者不轄制任何陳述（後者勝）。

## 3. 繼承、覆蓋與硬邊界

**由外向內繼承，就近覆蓋。** L0 → L1 → L2 → L3 逐層生效；同一節點上若出現同名鍵，
後者覆蓋前者（`#{overflow=wrap} #{overflow=clamp0}` 等同 `#{overflow=clamp0}`）。

**函式體是硬邊界。** 函式/方法/匿名函式體不繼承外層的 L2/L3 註解：

```no
#{overflow=wrap}
outer = () {
    inner = () (r i8) {
        a i8 = 100
        b i8 = 100
        r = a + b        ; ← 不繼承外層 wrap，仍是 ?i8 / err
    }
}
```

理由：外層註解若穿透進來，會靜默掩蓋巢狀函式裡真正沒處理的溢出——那正是這條
規則要防的事故。L1 註解則相反：它就寫在這個函式頭上，自然覆蓋整個函式體。

**硬邊界清單**（繼承到此為止）：函式體、方法體、匿名函式/lambda 體、`#{c}` 外部宣告。
**非邊界**（照常繼承）：`{}` 裸塊、if 組、match 臂、循環體。

## 4. 鍵 × 層級矩陣

`✓` 生效 ／ `✗` 非法（應報編譯錯誤）／ `—` 對該層無意義（同樣應報錯，而不是靜默丟棄）

| 鍵 | L0 模組 | L1 宣告 | L2 區塊 | L3 單行 |
| --- | --- | --- | --- | --- |
| `overflow` | ✓ | ✓ | ✓ | ✓ |
| 平台鍵（`mac-arm64` 等） | ✓ | ✓ | ✓ | ✓ |
| `buildin` | ✗ | ✓ 函式 / 標籤列舉 | ✗ | ✗ |
| `inline` | ✗ | ✓ 結構體 / 欄位 / 變體 / 函式 | ✗ | ✓ 成員尾隨 |
| `generic` | ✗ | ✓ 函式 / 結構體 | ✗ | ✗ |
| `track-caller` | ✗ | ✓ 函式 | ✗ | ✗ |
| `embed` | ✗ | ✓ 頂層 `let` | ✗ | ✗ |
| `bind` | ✗ | ✓ import 行 | ✗ | ✗ |
| `c` / `cpp` / `rust` | ✗ | ✓ 緊隨的函式宣告 | ✗ | ✗ |
| `fmt-skip` | ✗ | ✗ | ✓ markdown 圍欄塊 | ✗ |
| 元資料（`derive` / `range` / `max` / `debug`…） | ✗ | ✓ 宣告 / 成員 | ✗ | ✗ |
| `index-out` | — | — | — | — 已於 D11 移除，出現即報錯 |

「非法」與「無意義」都必須**報錯**，不能靜默失效：一條寫在 for 迴圈上方的
`#{buildin}` 若被悄悄忽略，作者會以為內建聲明生效了。

## 5. 註釋（`;` / `//` / `;;`）的作用域

註釋不參與編譯語意，歸屬只影響 `no fmt` 的排版與 API 文件的掛載。標記語法見
[`code-style.md`](code-style.md)〈註釋標記〉。

| 註釋 | 歸屬 |
| --- | --- |
| 行內（`x = 1 ; 說明`） | 該行 |
| 行上方連續註釋行 | 緊跟的下一條陳述/宣告（L1 或 L3，同註解的宿主判定） |
| 與目標之間有空行 | 不歸屬任何節點，作為區塊/檔案的分隔說明 |
| `;; … ;;` 塊註釋 | 只到自己的結束定界符，不跨作用域 |
| 註解與其目標之間的註解 | 隨目標走，輸出順序固定為「文件註釋 → 註解 → 陳述」 |

`;` 與 `//` 語義相同；`no fmt` 保留原始標記不改寫。文件註釋的翻譯錨點
（`[get](#args.get)`）必須是註釋群組的**最後一行**，屬於同一宿主，不能跨節點。

## 6. 三個消費者必須一致

同一條註解，四個讀者必須得到同一個作用域：

| 讀者 | 需要知道的 |
| --- | --- |
| parser / codegen | 這個節點及其子樹用哪個模式 |
| checker / `no vet` | 「已標註」的判定範圍 |
| `no fmt` | 註解印回原位，不得跨宿主搬移 |
| LSP | hover/quickfix 插入的位置等於它實際生效的位置 |

由此推出三條不變量：

1. **標註判定一致**：codegen 認為「已標註」的範圍，必然也是 `no vet` 認為已處理的範圍，反之亦然。
2. **fmt 不搬移**：`no fmt` 只能在同一宿主內調整位置（上方 ↔ 尾隨），跨宿主搬移等於改語義。
3. **失效必報**：註解落在沒有對應語意的層級（見 §4 的 `✗` / `—`）時報錯，不靜默忽略。

## 7. 現況與差距（2026-11-10 實測）

用 `bin/no`（當日建置）逐項驗證，形狀統一為「兩個 `i8 = 100` 相加，看結果是
`err` 還是 `-56`（wrap）」；平台鍵用 `#{win-amd64}` 在 macOS 上驗證是否被排除。

| 層級 | `overflow` | 平台鍵 | 宣言 |
| --- | --- | --- | --- |
| L0 模組 | 未實作（檔案頭註解會被附着到首條陳述） | 未實作 | 未實作 |
| L1 宣告 | ⚠️ `no vet` 認（整函跳過）、**codegen 不認**（仍 `err`） | ✓ 整棵子樹排除 | ✓ |
| L2 區塊 | ✗ codegen 不認、`no vet` 也不認 | ✗ 塊內仍參與編譯 | — |
| L3 單行 | ✓ | ✓ | — |

實測證據：

```text
a-none.no    (無註解)                     → err
b-line.no    (陳述上方 #{overflow=wrap})   → result:true  (-56，生效)
c-fn.no      (函式上方 #{overflow=wrap})   → err           (vet: No issues found)
d-block.no   (for 上方 #{overflow=wrap})   → err ×2        (vet: 2 hints)

p1-block.no  (#{win-amd64} + 2 * {…})      → 塊體仍執行    (未過濾)
p2-stmt.no   (#{win-amd64} + 單條 print)   → 該行被排除    (生效)
p4-fn.no     (#{win-amd64} + 函式宣告)     → 函式被排除    (生效)
p6-ifgroup.no(#{win-amd64} + if 組)        → 臂仍執行      (未過濾)
```

最危險的一條是 L1 + `overflow`：`no vet` 說「整函已標註」、codegen 卻按預設
`option` 模式生成，於是**檢查全綠、執行期照樣回 `err`**。這正是 §6 第 1 條
不變量要擋的漂移。

存量影響：`src/**/*.no` 中以註解作為檔案第一條有效行的有 21 個檔，其中 17 個是
`#{js}`、其餘是紧跟宣告的 `#{buildin}` 等——全部**沒有**空行，按 §2 的 L0 判據
仍然是 L1，`no fmt` 與編譯行為不變。`str.no` 有 2 處「註解 + 空行 + cond 臂」，
位於函式體內，不觸發 L0 判據。

## 8. 落地順序

1. **先統一 L1 的 `overflow`**：讓 codegen 讀函式級模式，或讓 `no vet` 不再整函跳過——
   二選一即可，但不能維持現狀。傾向讓 codegen 認（`src/std` 已有大量函式級 `#{overflow=wrap}`）。
2. **補 L2**：把塊頭註解下推到塊內陳述（parser 已有廢棄的 `propagateBlockScopedOverflow`
   可作參考，但它同時做了雙向回填，需改成單向繼承 + 內層覆蓋）。
3. **補 L0**：檔案頭註解 + 空行 → 生成模組級註解節點（目前零存量使用，風險最低）。
4. **收緊非法的鍵 × 層級組合**：從「宣告鍵寫在 L2/L3」開始報錯。
5. 每一步都要保證 `no fmt` 冪等，且 `no vet` 與 codegen 對同一份輸入結論一致。
